# 陪伴体验验收与观察

- 文档状态：REFERENCE
- 日期：2026-09-13
- 关联：[功能评审](feature-review-2026-09-13.md)、[当前实施状态](status/overview.md)
- 当前结果：以下人工场景均未执行；自动测试通过不自动填写人工通过。

## 使用方法

部署待审实现后，用两个独立测试伙伴 A/B 和少量虚构、不敏感偏好进行一轮验收；这里没有自动创建角色、写入记忆、启用主动聊天或开始十四日观察。记录所用服务端提交、固件版本、模型、音色、设备时区及噪声条件。先完成一轮固定场景，再进入日常使用，避免把反复开发测试当作自发使用。

每项只记“通过 / 失败 / 未评估”和一句错误类型，不额外收集正文。涉及未配置的日历、外部通知、第二设备或音色，标记未评估。角色的记忆由确认后才生效，不把模型提出的建议当作已经记住。

## 对话场景（20 项）

| ID | 操作 | 通过条件 |
| --- | --- | --- |
| C01 | 普通问候后聊一个新话题 | 不主动搬出无关项目或偏好 |
| C02 | 连续说“刚才那件事”“后来呢” | 承接最近真实回答，不编造新事件 |
| C03 | 无近期前文时说“继续讲” | 简短澄清对象 |
| C04 | 有前文时说“继续讲” | 推进内容，不重复整段开头 |
| C05 | 聊天气后说“那明天呢” | 继承天气对象并重新查动态事实 |
| C06 | 聊日程后说“不是日程，是明天的天气” | 以天气为准，使用相应授权工具 |
| C07 | 聊天气后说“换个话题” | 不再接天气，简短询问新对象 |
| C08 | 说“换个话题，聊聊音乐” | 直接回应音乐 |
| C09 | 换到音乐后说“明天呢” | 不错误继承旧天气对象 |
| C10 | 说“我们聊聊怎么结束聊天” | 不把讨论当成结束指令 |
| C11 | 连续模式中说“结束聊天” | 退出连续追问；是否听到告别按当前固件路径记录 |
| C12 | 结束后再次唤醒，说“继续讲” | 不复活已结束话题或告别轮次 |
| C13 | 结束后再次唤醒，明确聊新对象 | 正常进入新话题 |
| C14 | 有待确认操作时换题，再说“好的” | 不能执行旧操作 |
| C15 | 有待确认操作时结束，再次唤醒说“好的” | 不能执行旧操作 |
| C16 | 回复播放时触摸停止 | 后续旧音频不继续播放，下一轮可用 |
| C17 | 近期主动资讯播放后说“说说看” | 明确区分标题事实与一般知识，不编造全文 |
| C18 | 主动资讯播放后换题，再说“继续讲” | 不复活旧主动资讯 |
| C19 | 分别与 A/B 聊同一主题 | 能辨识性格差异，且不串对话对象 |
| C20 | 断开外部模型服务后尝试明确控制 | 已完成转写且语音服务可用时，结束/暂停等固定控制不依赖聊天模型；记录其他失败边界 |

## 记忆场景（20 项）

| ID | 操作 | 通过条件 |
| --- | --- | --- |
| M01 | A 确认“喜欢手冲咖啡”，直接问 A | 找到并准确使用该记忆 |
| M02 | 用 coffee 询问 A 的咖啡偏好 | 有限同义检索能召回 |
| M03 | A 确认午餐偏好，以“午饭”询问 | 能召回同义条目 |
| M04 | 用未在词表中的复杂转述询问 | 如实记录命中/漏召回，不因其他样例通过而算通过 |
| M05 | 只给 A 确认偏好，询问 B | B 不知道 A 的记忆 |
| M06 | 从 B 切回 A 再询问 | A 的记忆仍在 |
| M07 | 同角色、另一设备询问设备专属记忆 | 不跨设备使用专属条目 |
| M08 | 同角色、另一设备询问角色全局记忆 | 可按全局范围使用；不扩散到 B |
| M09 | 提出偏好变化但尚未确认 | 新建议不作为已生效长期记忆 |
| M10 | 确认同主题替代偏好 | 后续不再以旧偏好为现状 |
| M11 | 拒绝候选建议 | 拒绝内容不进入对话记忆 |
| M12 | 禁用已确认条目再询问 | 不再引用该条目 |
| M13 | 删除条目再询问 | 不再以长期记忆声称记住；单独记录近期对话仍可见的情况 |
| M14 | 预置无关高重要度条目，询问低重要度相关事实 | 无关条目不挤占相关结果 |
| M15 | 明确聊无关音乐主题 | 不硬套咖啡等旧偏好 |
| M16 | 问“你记得我什么”且条目超过八条 | 表述为部分回顾，不冒充完整列表 |
| M17 | 本轮没有检索到相关条目 | 不声称从未记住用户或数据库为空 |
| M18 | 多个长记忆触发提示词预算 | 使用记录仅含实际提供给模型的完整条目 |
| M19 | 检索服务故障 | 不拿无关高重要度条目填充；不凭空编造记忆 |
| M20 | 问“你为什么记得这个” | 来源说明与实际条目一致，不编造出处 |

“召回正确”和“引用合适”分别勾选。词面召回存在已知边界，M04 不能预填通过；实际引用自然度更不能只靠检索 SQL 测试证明。

## 主动反馈与提醒隔离

| ID | 操作 | 通过条件 |
| --- | --- | --- |
| P01 | A 播放兴趣话题后说“别再提这个” | 只静默 A 在该设备的已播放主题 |
| P02 | 有更新的未播放话题排队时重复 P01 | 不把排队话题当作拒绝对象 |
| P03 | 最近播出的是无主题问候，或已明确换题 | 不回退到更早兴趣话题进行修改 |
| P04 | 在控制台选择 B 查看/恢复同名话题 | 不修改 A；查看不切换设备当前角色 |
| P05 | A 说“今天别主动聊” | 只暂停 A 在该设备上，到设备当地次日起点自动解除 |
| P06 | A 暂停 30 分钟后切换 B | B 的暂停状态独立；按已说明范围假设验收 |
| P07 | 提前恢复 A | 仍遵守原主动开关、配额、时段和已静默话题 |
| P08 | 暂停前后存在排队的普通主动问候 | 尚未发送的问候取消，恢复后不补播 |
| P09 | 暂停期间触发普通提醒、工作休息、工作简报和外部通知 | 不被主动聊天暂停吞掉；各自原有免打扰/业务规则仍生效 |
| P10 | 说引用或否定形式的暂停短句 | 不自动改变暂停状态 |

已下发的音频使用既有取消机制；这里不承诺数据库偏好更新能撤回已经到达设备的消息。

## 十四日观察记录

发布追加专项（不计入原 50 项基线，均待用户真机测试）：

| 操作 | 通过条件 |
| --- | --- |
| 普通周期提醒播完说“稍后十分钟”，再确认两次 | 重述具体内容，仅新增一次再提醒，原周期不变 |
| 普通提醒播完说“完成了” | 不自动完成待办，要求明确标题 |
| 外部通知播完要求完成，再确认 | 说清通知内容及“回报完成”的含义，不宣称外部任务已执行 |
| 旧休息提案未确认，下一次休息提示出现后确认旧提案 | 拒绝过时提案，不修改下一次休息提示 |
| A 说“先不聊”后继续另一个话题 | 简短收尾，不追问旧话题，不自动全天暂停 A |
| A 说“今天安静点” | 与“今天别主动聊”范围一致，B 和普通提醒不受影响 |
| 打开高级扩展和旧能力/通知链接 | 入口可展开，旧链接可访问，未自动启用任何扩展 |

每天一行记录：日期、自发聊天是否发生、明天是否愿意继续、发生的对话/记忆错误类型、实际听到的主动开场数、愿聊/现在忙/不感兴趣各几次、哪一项辅助功能确实节省了操作。无事件记零，没配置记未评估，不编造分母。

只在固定场景和实际案例足够后评价下一轮方向。报告中的 ≥18/20 是建议门槛，不是现有成绩；任何跨角色记忆串用或未确认操作执行均单独修复，不用总体通过率掩盖。十四日使用结束也不自动等同于长期留存成功。
