# WORK-004 本地个人待办闭环

- 文档状态：DEPLOYED
- 日期：2026-08-30
- 实现基准：`f0bce2d`
- 工作流：服务端、前端、部署

## 目标

在不引入第三方任务平台、日历写入或模型自由副作用的前提下，为单用户桌面机器人增加可长期自用的个人待办闭环：管理员可在页面管理待办，机器人可读取当前角色的未完成待办，并通过既有确认式语音动作安全新增或完成待办。

## 数据与隔离

- 每条待办固定绑定一个设备和一个陪伴角色，创建后不能改绑。
- 保存标题、可选备注、优先级、状态、可选截止时间和时区；备注仅供管理页面使用，不发送给 Agent。
- Agent Tool 最多返回当前设备与角色的二十条未完成待办，只包含 ID、标题、优先级和截止时间。
- 管理 API 受既有管理员会话与 CSRF 边界保护；模型不能提供或覆盖设备、角色、会话或任务范围。

## 截止提醒

- 未来截止时间建立一条同角色、单次、用户来源的可靠提醒，正文固定为“待办到期：标题”。
- 修改未来截止时间或标题时更新仍处于等待状态的关联提醒，不创建重复提醒。
- 完成、删除或移除未来截止时间会取消尚未完成投递的关联提醒并解除关联。
- 重新打开待办时，仅当截止时间仍在未来才重新建立提醒；已过期待办可以保存，但不会补播历史提醒。
- 提醒继续遵守现有免打扰、设备忙碌、离线重试、TTS 和播放 ACK，不增加新的设备协议。

## 页面与语音

- “提醒管理”下新增“个人待办”，支持关键词、状态、优先级和角色筛选，以及新增、编辑、完成、重新打开、单条和批量删除。
- 新增/编辑表单使用 Fantastic-admin 的 `FaForm`、`FaFormItem` 和内建字段组件；列表与详情路由按框架约定建立 keep-alive 关系。
- 角色选择校验接受 PostgreSQL 合法的项目保留默认角色 ID，同时继续拒绝空值和非 UUID 文本；同一修复覆盖普通提醒与通知集成表单。
- 机器人回答待办、任务清单或要做的事时必须调用 `current_personal_tasks`；Tool 不可用时明确拒绝猜测，不能用提醒、日历或历史对话替代。
- 简单新增、带时间新增和按标题完成均先生成两分钟内有效的结构化提案；只有用户确认后才执行，重复确认保持幂等。
- 标题完成只在当前设备和角色的未完成待办中匹配；无匹配或多条相似结果时不写入。

## 固定边界

- 首版不接入 Todoist、提醒事项、日历写入、多人协作、附件、子任务或模型自动拆解。
- 不保存 Agent 的自由文本解释，不把备注发送给模型，不做过期提醒重放。
- 本任务不修改固件、串口、设备协议或身体动作；CoreS3 无需 OTA。

## 人工验收

1. 在“提醒管理 → 个人待办”新增一条无截止时间待办，确认列表可筛选、编辑、完成和重新打开。
2. 新增一条未来截止时间待办，确认页面显示“已关联机器人提醒”；完成后确认关联提醒不再播报。
3. 对机器人说“我的待办有哪些”，确认能读到当前角色未完成待办且不会朗读备注。
4. 对机器人说“添加待办：整理材料”，确认机器人先询问确认；确认后只创建一次。
5. 对机器人说“完成待办：整理材料”，确认机器人先询问确认；确认后任务变为完成。
