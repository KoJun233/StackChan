# WORK-003 观察结果一次性通知

- 文档状态：COMPLETED
- 日期：2026-08-30
- 实现基准：`f0bce2d`
- 工作流：服务端、部署

## 目标

十四天观察必须完整结束后才产生最终 `PASS` 或 `FAIL`。WORK-003 在不改变 WORK-002 门槛、聚合口径和当前窗口的前提下，把这一最终结果通过现有可靠提醒队列向机器人入队一次，避免管理员必须在准确日期主动刷新管理页。

## 固定行为

- 每五分钟扫描尚未记录完成通知的观察窗口。
- 第十四天当地日期完整结束前保持静默；`COLLECTING` 和 `NOT_STARTED` 不创建提醒。
- 最终只播报“门槛通过”或“至少一项未通过”，详细指标仍只在管理页查看。
- 提醒绑定入队时的当前活动角色，正文固定且不调用 LLM，不包含日历、天气、对话或指标明细。
- 提醒复用既有免打扰、设备离线重试、忙碌门禁、TTS 和设备 ACK 链路；本任务不直接控制设备。

## 幂等与并发

V44 为 `workday_pilot_observations` 增加 `completion_notification_queued_at`，并为 `workday:pilot:complete:{startedOn}:{status}` 建立每设备唯一索引。

调度按设备锁定当前观察行，在同一事务内创建提醒并写入已入队时间。服务重启、重复调度和并发执行不会重复创建；若提醒已经存在但标记缺失，则只重建标记。管理员重新开始观察也获取同一行锁，并为新窗口清空旧标记，避免与最终入队交叉覆盖。
