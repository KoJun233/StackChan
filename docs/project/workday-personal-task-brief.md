# WORK-005：工作日首次简报纳入个人待办

- 文档状态：COMPLETED
- 日期：2026-08-31
- 实现基准：`861d26a`
- 工作流：服务端、部署

## 目标

在不增加新的主动播报次数、不改变十四天观察口径的前提下，让每天第一次工作简报同时回答“今天优先做什么”。功能复用 WORK-001 的确定性首次简报和 WORK-004 的本地个人待办，不建立新的调度、模型调用或设备协议。

## 固定选择规则

- 只读取当前设备的活动角色，其他角色和其他设备的待办不得进入简报。
- 候选只包含未完成且满足以下任一条件的待办：已经逾期、按设备时区在当前工作日到期，或优先级为 `HIGH`。
- 已逾期和今天到期的待办优先，按截止时间升序；之后才是高优先级的未来或无截止待办，并保持确定性排序。
- 每次最多播报两项。标题最多播报四十个 Unicode 码点，超出部分用省略号截断。
- 语音只使用标题及“已逾期、今天到期、高优先级”分类；备注、内部 ID、角色 ID 和精确数据库字段不进入正文。
- 没有候选时不增加“无待办”噪声。待办读取失败时跳过该段，天气、日历和原简报可靠投递继续运行。

## 与既有口径的关系

- 每个工作日仍最多一次首次简报，继续使用 `(device_id, work_date)` 原子占位和可靠提醒队列。
- 简报 `SUCCESS/PARTIAL` 仍只反映天气和日历可用性；待办是本地可选增强，不增加外部服务降级码。
- 不修改十四天窗口、工作日规则、误播报计数、简报次数统计或最终 `PASS/FAIL` 门槛。
- 不新增数据库迁移、管理页面、Agent Tool、固件命令或身体动作。

## 验证与验收

- 单元测试覆盖设备/角色范围、最多两项、工作日时区分类、备注隔离和简报正文。
- PostgreSQL 持久化测试执行真实 JPQL，验证候选过滤、确定性顺序和分页上限。
- 自动化回归后只替换 LAN server；运行库继续保持 V45，CoreS3 继续保持 `424cb49 / motion_disabled`。
- 人工验收：为当前角色准备逾期、今日到期和高优先级测试待办，下一次显式开始工作模式时确认最多播报两项且不包含备注。当天已有简报时不得为测试重置观察窗口或绕过去重。
