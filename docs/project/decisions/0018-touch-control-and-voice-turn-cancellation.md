# 0018：触摸控制采用本地事件队列与幂等语音回合取消

- 状态：ACCEPTED
- 日期：2026-07-26
- 工作流：服务端、固件

## 背景

CoreS3 已能通过 WakeNet 完成语音回合，并用同一 `turn_id` 关联设备与服务端阶段。当前触摸只退出屏保；语音任务会同步等待最长 45 秒的 HTTP 回合，播放也会阻塞到 WAV 结束。用户无法在处理中取消晚到回复、在播放中立即停止，也无法在唤醒词不便使用时主动开始说话。

## 决策

### 本地手势

- UI 任务每 50 ms 采样触摸，只产生有界本地事件，不直接调用网络、麦克风或扬声器。
- 从屏保唤醒的第一次触摸只恢复亮度和当前状态；用户释放后才能开始新的手势，避免唤醒屏幕时误触发录音。
- 在线待机状态持续按住 600 ms 后进入按住说话；设备先显示聆听状态，随后录制按住期间的 16 kHz 单声道音频，释放或达到 8 秒上限时结束。
- 聆听或处理中短触取消当前语音回合；播放中短触立即停止播放并恢复麦克风；短暂成功、没听清、取消或可恢复错误反馈中短触立即返回待机。
- 未建立已认证设备 WebSocket 时视为离线，即使 Wi-Fi 已获得 IP，离线待机的长按也不启动录音或上传，并继续显示离线反馈。待机短触只记为活动，不创建语音回合。

### 取消与晚到结果

- `voice_turn_stage` 增加设备阶段 `TOUCH_STARTED` 和终态 `CANCELLED`。`turn_id` 在本地唤醒或长按开始时生成，字段仍只允许规范 UUID、单调相对耗时和固定枚举。
- `CANCELLED` 同时是隐私安全诊断事件和取消控制信号。服务端只允许已认证设备取消属于同一设备的回合；重复取消、取消早于 HTTP 到达和取消晚于终态都必须幂等。
- 设备收到取消手势后立即标记本地回合终止、调用 ESP-IDF 的 HTTP 取消 API，并丢弃随后到达的旧响应；旧回复不得在下一次交互中突然播放。
- 服务端为正在执行或短暂尚未到达的回合维护有界、短期的取消令牌。ASR、LLM 和 TTS 阶段之间检查令牌；LLM 流使用取消信号提前终止。已创建的 assistant 消息以 `INTERRUPTED` 结束，不保存为成功回复。
- PostgreSQL V15 为语音回合增加 `CANCELLED` 状态和事件阶段；取消仍遵守七天诊断保留，不保存音频、转写、回复正文、供应商响应或认证载荷。

### 播放和提醒

- 扬声器停止请求由语音控制任务处理；UI 任务只入队触摸事件。停止后必须执行与正常播放相同的麦克风恢复步骤。
- 普通语音播放被停止时，回合进入 `CANCELLED`，不记录 `PLAYBACK_COMPLETED`。
- `command_ack` 继续保留 `accepted` 以兼容旧固件，并允许在 `accepted=false` 时增加严格的 `result`：`cancelled` 或 `failed`。旧固件省略 `result` 时保持原有失败语义。
- 用户停止提醒播放时设备发送 `accepted=false,result=cancelled`；服务端把提醒标记为 `CANCELLED`，不得误记为 `DELIVERED` 或自动把它当作播放故障重试。

## 发布与兼容

1. 服务端先接受旧事件、`TOUCH_STARTED`、`CANCELLED` 和可选 ACK `result`，并完成 V15 迁移。
2. 旧固件继续使用原有阶段和四字段 `command_ack`，行为不变。
3. 服务端部署并确认旧固件在线后，才允许构建和刷写新固件。
4. 新固件不得先连接仍会把新增严格事件判为 `invalid_event` 的旧服务端。

## 安全边界

- 触摸控制不初始化或启用舵机、摄像头、LED、NFC 或其他执行器，`motion_disabled` 保持不变。
- 取消事件不包含自由文本、手势坐标、音频、转写、回复、URL、Token、API Key 或完整异常载荷。
- LAN HTTP 仍只用于可信局域网开发，生产保持 HTTPS-only。

## 影响

- 语音控制新增一个小型输入事件队列和控制任务，HTTP 客户端需要暴露线程安全的当前请求取消入口。
- 设备时间线可以区分 WakeNet 与触摸发起，并把取消作为非失败终态展示。
- 提醒的用户主动停止与硬件/下载失败不再混为同一结果。
