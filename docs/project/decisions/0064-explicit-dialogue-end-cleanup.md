# 0064：复用固件结束短句完成服务端会话收尾

- 状态：ACCEPTED
- 日期：2026-09-13
- 工作流：服务端
- 关联：[功能评审 D01](../feature-review-2026-09-13.md)、[0058](0058-explicit-voice-dialogue-controls.md)

## 决策

固件已经识别“结束聊天”及允许的尾随标点，退出连续追问。服务端使用同一精确短句，不把引用、否定、讨论如何结束聊天或其他未获固件支持的同义句当作控制指令。

- 结束时持久更新话题边界，取消本会话旧待确认操作，固定回复“好的，先聊到这里。”；不调用聊天模型、加载记忆提示词或提取新记忆。
- 保留聊天记录、长期记忆与角色独立关系；结束轮次不成为下次续讲对象。近期历史中的旧结束短句也可提供边界，避免旧版本留下的结束记录被当成普通话题。
- 语音与主动上下文采用同一有效边界。新唤醒之后可以开始新话题；没有新对象的“继续讲”确定性澄清，不复活已结束内容。
- 将提示词和模型配置读取推迟至实际需要模型的分支，明确操作与无上下文续讲也不再承担这些无关读取。
- 保持单 WAV 与既有取消路径；不改动固件或刷写。固件非流式结束路径可能不播放收尾音频，流式也由既有结束标志控制后续追问，不宣称这次验证了实体告别音频。

## 验收

解析正负例对齐固件支持的 ASCII/中文标点；历史选择验证结束前内容排除、告别轮次不可续讲、后续新话题保留。流式和非流式服务测试验证固定回复、边界持久调用、旧确认取消、一个音频片段及不调用模型/记忆服务。回归真实 PostgreSQL 边界与完整可运行服务端套件。实体连续对话仍需另行验收。
