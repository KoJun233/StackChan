# 0033：角色容器与严格数据隔离

- 状态：ACTIVE
- 日期：2026-08-13

## 背景

现有陪伴数据绑定单例人设。用户需要在同一设备上切换多个角色，同时保证人设、会话、记忆、提醒、主动主题和外部通知不会跨角色进入模型上下文或被误操作。

## 决策

- 使用 `companion_roles` 作为角色容器，每台设备通过 `device_active_roles` 保存活动角色。
- 迁移创建固定 UUID 的默认 `StackChan` 角色，并把既有角色相关数据全部归入默认角色。
- 网页会话创建时永久绑定角色；设备语音会话以 `(device_id, role_id)` 唯一定位。
- `roleId` 由会话、设备认证或管理员请求上下文解析，Agent Tool 和模型参数不能覆盖。
- 角色背景放在基础系统安全规则之后，以受限数据段转义注入，不作为自由系统提示词。
- 默认角色不可归档。归档角色时，活动设备切回默认角色、未来提醒取消、通知集成停用；历史会话和记忆保留。
- 设备凭据、网络、OTA、音量、免打扰、LLM/语音供应商、Skill/MCP、首版音色与表情继续共享。

## 后果

- V29 为所有隔离数据补充非空 `role_id`，后续查询必须显式限定角色。
- 旧 `/api/v1/persona` 只映射默认角色，作为兼容接口保留。
- 切换活动角色遇到进行中的语音回合或已派发提醒时返回 409。
- 本任务不修改固件、音色或表情资源。
