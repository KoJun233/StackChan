# 0077：自然语音诊断采用实际设备事件与独立实体测量

- 状态：ACCEPTED
- 日期：2026-10-14
- 工作流：全局
- 相关提交：`989b3d9`（实现基准；最终候选完整 SHA 见外置收据）
- 关联：[R01](../../requirements/companion-v1/R01-natural-voice.md)、[交付记录](../baselines/companion-r01-natural-voice.md)、[测量手册](../../runbooks/natural-voice-quality.md)

## 背景

用户反馈回答需要五六秒、记忆似乎依赖同一 session。服务端阶段耗时不能证明设备首声；旧 PLAYBACK_STARTED 在 codec 打开前上报，不能作为新性能样本。采音达到上限与正常端点需要区别，删除会话后的晚到诊断也需要防止重新出现。

## 决策

保留 WAKE/PTT、8 秒输入、约 800ms 静音窗、默认关闭连续对话、三次追加和 120 秒新回合启动限制。达到采音上限时确定性澄清，先于模型、写工具和记忆提取。完整正文仍一次 TTS、单 WAV，硬上限含标点共 160 Unicode 码点；近期上下文仍限定四轮完整成功配对和三十分钟。当前纠正与换题关闭旧上下文，续讲无唯一对象则追问；轻量拒绝不提取记忆。

沿既有认证阶段事件增加可选来源、端点至本地状态接受的耗时和采音上限原因。PROCESSING 的观测点是硬件状态接口接受，不能声称 LCD 帧已完成。播放观测点是首次成功 codec 写入，写入失败或取消不报告开始。首次写入回调只保存固定通知和阶段，UI 任务检查当前回合与取消后再显示 SPEAKING，不在音频写入循环等待界面锁。

设备单调时间、服务端阶段时长和实体观察分别统计。管理员汇总只读、默认 24 小时、最多七天；短聊分组来自服务器实际路由，复杂工具、失败、取消和缺失保持单列。至少三十个适用成功样本才给 nearest-rank 百分位，保留所有慢样本。接口 `endpointToFirstSound` 的 DEVICE_MONOTONIC 分组实际指 codec 写入开始；控制台说明为设备开始播放，`physicalObservationRequired=true`，实体首声只能由独立匿名 CSV 验收。旧设备缺新增证据为 UNKNOWN，不用 TTS 完成或服务器收包时间补算。

仅新增 V61，将诊断可空关联至服务端已绑定会话，不回填旧行。单消息删除保守清除该会话全部关联诊断，整段删除同步清除；其他会话与无关联旧诊断保持原七日清理。关联删除前保存匿名 turnId 墓碑，删除后保留七日，重复删除不延长；墓碑不包含设备、会话、正文或录音。绑定和隐私删除先锁会话，再按排序锁 turnId；阶段写入取相同 PostgreSQL 事务咨询锁并检查墓碑，避免删除与晚到事件竞态。墓碑过期后不永久记住 turnId，这是有界保留策略，旧记录不能声称已完成关联删除。

## 原因

可选字段保留旧协议；实际路由与实际写入比模型声明可信。独立实体测量能够区分 VAD 尾静音、网络与声学播放；匿名墓碑只保留阻止当前晚到事件所需的最小标识。

## 影响

V1–V60 原 SQL/checksum 不变；V61 升级只在隔离副本验证。新增固定通知 56 字节、阶段队列增量 192 字节，总静态增量 248 字节。LAN 候选 3,141,296 字节，3 MiB 槽余量 4,432 字节，仅高于 4,384 字节门槛 48 字节，后续改动必须重新构建和检查。分区、模型、输入配置、运动/相机与供应商保持原合同。软件通过不授予安装或实体性能通过。
