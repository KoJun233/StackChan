# 0050：短语音闲聊采用低延迟直连与连续合成

- 状态：ACCEPTED
- 日期：2026-09-08
- 工作流：服务端、部署
- 相关提交：`ac6f386`

## 背景

边录边传、短首段和固件段间预取已经分别缩短上传、首段合成和段间收帧等待，但普通语音闲聊仍统一经过受控 ReactAgent，并在完整模型回答结束后才开始第一段 TTS。真实使用以游戏时偶尔吐槽、分享输赢和延续短话题为主；这类输入通常不需要 Tool，却承担了 Agent 组装和整段生成等待。角色提示也没有明确限制语音闲聊长度，容易产生不必要的建议、追问和长回答。

当前运行的 `qwen-tts-latest` 是非实时 Qwen-TTS 模型。官方接口没有为该模型提供通用倍速参数，因此本任务不能通过发送未经支持的参数声称提高句内语速。

## 决策

1. 设备语音中不超过八十个 Unicode 码点、且不包含明确查询、搜索、最新消息、Tool、Skill 或 MCP 意图的输入，使用关闭推理模式的直接流式 ChatClient。网页聊天、长输入和明确外部能力请求继续使用现有受控 ReactAgent。
2. 当前时间、能力、日历、天气、个人待办、下一条提醒和待确认记忆问题始终进入各自的必需 Tool 路径。语音中的当前时间问题直接执行已授权的本地时间 Tool，并由服务端确定性生成单句中文，不再承担 ReactAgent 的两次模型往返；网页和其他事实问题保持受控 Agent。Tool 未授权或结果无效时继续拒绝猜测。
3. 模型文本流继续实时接收，但不在第一句完成时同步调用 TTS。每个语音回合只发起一次 TTS 并下发一个 SCV2 音频段，句号、逗号、问号和感叹号都交给同一次合成生成自然语气停顿。语音正文要求在 160 个 Unicode 码点内优先给出适合听取的摘要；模型仍超限时在前 160 码点内最近的完整句界收束，无完整句界才安全截断并补句号。
4. 隐藏表情标记不得进入合成。完整回答仍用于会话持久化、表情解析和确认式长期记忆建议；播放正文不截断、不改写。
5. 随口吐槽、输赢分享和简短闲聊默认只回答一到两句，整个回答尽量不超过四十个汉字，先接住情绪或话题。用户没有请求建议时不主动说教，也不为了延续对话而每次反问；明确要求解释、分析、步骤或完整事实时允许展开。
6. 取消、客户端断开和供应商失败沿用同一回合边界。已经安全刷新的第一段不会伪装成完整成功，未完成回答按现有中断或失败状态保存。
7. 非实时 ASR 明确返回官方“无有效语音”或“无词”错误时映射为 `NO_SPEECH`，让连续对话无人回应时安静收尾；其他 400、配置和供应商错误继续保持失败状态，不扩大吞错范围。

## 原因

短闲聊的核心价值是及时且连贯地回应，不需要每轮装配 Tool 和执行 Agent 循环。明确事实与外部状态问题仍保留受控 Agent，可以在降低常见闲聊延迟的同时维持最小权限和拒绝猜测边界。实测中首句同步合成会阻塞后续模型文本消费，首段发出后余句才开始新的 TTS，形成明显的段间空档；整段文本只合成一份音频可以从结构上消除这个等待，并让 TTS 自己处理标点语气。

## 影响

- SCV1、SCV2 帧格式、设备固件、数据库和管理页面均不改变。
- 当前非实时 TTS 的句内语速和标点停顿保持供应商输出；回复会等待完整文本后开始一次合成。服务端仍保留 SCV2 多段协议解析以兼容旧路径，但当前语音业务只发送一段。后续如切换到官方支持倍速的实时模型，必须单独验证音色、费用、协议和实机听感。
- 明确查询与 Tool 失败回复可能仍需等待完整 Agent 调用；本任务优先优化无需外部事实的高频短闲聊。
- 兴趣驱动的真实消息主动聊天属于后续阶段，本决策不新增联网来源、调度或主动次数。

## 替代关系

不替代既有 ADR；本记录细化 [0023](0023-controlled-react-agent-skills-tools-mcp.md) 的语音路由，并停止在当前语音业务中使用 [0037](0037-ordered-streaming-voice-playback.md) 的多段发送能力。SCV2 多段协议继续兼容旧客户端和既有取消边界，新的语音回合固定发送一段。
