# 0017：交互阶段在设备本地映射为可区分的可见状态

- 状态：ACCEPTED
- 日期：2026-07-26
- 工作流：固件

## 背景

INT-001 已能用隐私安全的阶段事件诊断语音回合，但 CoreS3 仍把无语音、离线、供应商异常和播放失败显示为同一种红色错误脸。用户不查看串口或管理端时，无法判断机器人是没有听清、暂时离线还是需要稍后重试。

## 决策

- 固件使用稳定的本地可见状态枚举：待机、聆听、处理中、播放、成功、没听清、离线和可恢复错误。
- WebSocket 未连接时，离线状态覆盖待机；已经开始的聆听、处理、播放和短暂反馈保持可见，结束后回到离线。恢复连接后重新显示当前阶段，不丢失语音任务状态。
- `NO_SPEECH` 使用温和的短暂反馈；成功使用与没听清相同长度的完成反馈；供应商、响应和播放故障使用可恢复错误反馈。短暂反馈结束后回到待机或离线。
- 低亮度动态瞳孔屏保只允许从待机或离线状态进入。聆听、处理、播放和短暂反馈期间不得进入屏保。
- 睡眠继续由既有屏保层表达，不增加网络协议字段。默认几何脸直接消费同一枚举，未来状态资源包必须复用该枚举并在资源缺失时回退到几何脸。
- 状态变化只更新显示和背光，不初始化摄像头、LED、舵机或其他执行器，`motion_disabled` 保持不变。

## 原因

连接状态与语音阶段可能并发变化。由显示层统一解析“当前阶段 + 是否连接”，可以让空闲设备持续显示离线，同时避免瞬时断线吞掉已经开始的交互反馈。把状态枚举从具体绘图代码中分离，也为单元测试和未来可替换资源包提供稳定边界。

## 影响

- 设备启动到 WebSocket 建立前显示中性灰离线；Wi-Fi 或 WebSocket 断开后，待机保持离线，活动交互先显示当前阶段或反馈，结束后回到离线，重连后自动恢复。
- 成功、没听清和可恢复错误会短暂延后 WakeNet 模型重建，但延迟分别限制在 1.2、1.2 和 1.5 秒。
- 本决策不改变设备 WebSocket、HTTP 语音协议、诊断数据、服务端、管理端或部署模式。
- 真机刷写仍要求用户明确确认 CoreS3、串口、transport profile 和精确 Git commit。
