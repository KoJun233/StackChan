# 0021：提醒与有限主动交互采用确定性规则和设备级控制

- 状态：ACCEPTED
- 日期：2026-07-27
- 工作流：服务端、前端、固件、部署

## 背景

现有提醒只支持单次固定时间播报；设备离线时一直保留为待发送，且没有免打扰、音量、夜间模式或主动问候边界。INT-006 需要扩展重复提醒和有限主动陪伴，同时避免模型自由决定何时打扰用户，并保持提醒持久化、固定同源音频和播放 ACK 的既有安全链路。

## 决策

### 重复提醒与时间语义

- 提醒支持单次、每日和每周重复；重复间隔为正整数。
- PostgreSQL 同时保存下一次执行时刻、IANA 时区和创建时的本地墙钟锚点。延期和稍后提醒只改变下一次执行时刻，不改变重复锚点。
- 计算下一次重复时刻时使用 Java `ZonedDateTime` 的标准解析：DST 缺口中的本地时间向前移动到首个有效时刻，DST 重叠优先使用较早偏移。页面必须明确展示该语义。
- 已确认送达或用户停止的重复实例在同一事务中推进到下一次，服务重启后不得再次交付同一实例。管理员可以“稍后提醒”或“跳过下一次”，不需要删除整个重复规则。

### 免打扰、离线和仲裁

- 每台设备保存音量、夜间模式、IANA 时区和可跨午夜的免打扰时段。免打扰默认关闭；期间不合成或发送音频，到期提醒延期到当前免打扰结束。
- 设备离线错过提醒按用户选择执行：重新上线后立即播报、按固定分钟数稍后再试，或跳过本次。单次提醒跳过后进入 `SKIPPED`，重复提醒推进到下一次。
- 设备离线、存在活动语音回合或已有提醒处于 `DISPATCHED` 时，不发送新的提醒或主动问候；忙碌状态只做短暂延期，不抢占当前交互。
- 管理端“立即停止”发送严格的 `stop_audio` 命令。设备只停止当前扬声器播放并按原路径恢复麦克风，不触发运动或其他执行器。

### 有限主动问候

- 主动问候按设备配置，默认关闭。用户必须明确设置固定问候文本、允许时段、最小间隔和每日上限。
- 调度器只依据上述配置、在线状态、免打扰和忙碌仲裁创建 `PROACTIVE` 来源的普通提醒；不调用 LLM 决定内容或时机。
- 最近主动时间和当日本地日期计数持久化，并在事务锁内更新，保证服务重启或并发调度不会突破限制。
- 系统错误、安全状态或供应商异常不会转写成陪伴性主动消息。

### 设备配置

- 服务端在管理员保存配置和设备认证连接建立后发送严格的 `configure_interaction` 命令，仅包含音量百分比和夜间模式。
- 新固件将音量映射到扬声器范围；夜间模式降低正常显示亮度。旧固件可以不识别该服务器命令，现有语音和提醒协议保持可用。

## 发布与兼容

1. 先发布接受 V17、设置 API、重复提醒和新命令的服务端；旧固件继续使用原有提醒命令和 ACK。
2. 管理端在新字段缺失时使用保守默认值，主动问候保持关闭。
3. 新固件可以在独立目录完成编译验证，但服务端健康、Flyway V17 和旧固件心跳验证通过前不得刷写设备。
4. 只有在用户明确确认 CoreS3、串口、profile 和精确提交后才能刷写。

## 安全边界

- 主动配置、命令和状态不包含音频、对话正文、转写、模型回复、凭据或供应商响应。
- `stop_audio` 和 `configure_interaction` 不得启用舵机、摄像头、LED、NFC 或其他执行器；`motion_disabled` 保持不变。
- LAN HTTP 仍只用于可信局域网开发，生产保持 HTTPS-only。
