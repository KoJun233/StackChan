# 0020：长期记忆必须经过确认并按会话范围组装

- 状态：ACCEPTED
- 日期：2026-07-26
- 工作流：全局

## 背景

StackChan 已有持久文本会话和按设备绑定的语音会话，但长期上下文仍只来自最近消息。INT-005 需要让用户控制机器人名字、语气、回复长度、主动程度和边界，并能查看机器人记住了什么、为什么记住、停用或删除。长期记忆会跨会话进入模型上下文，因此模型推断、设备隔离、敏感信息和删除生效都必须有明确边界。

## 决策

- 人设使用单例结构化配置，包含名字、语气、回复长度、主动程度、话题边界和禁忌；不把这些字段混入供应商密钥或自由 LLM 配置。
- 长期记忆存入 PostgreSQL，并记录作用范围、类别、来源、来源说明、确认状态、启用状态和创建/确认/更新时间。
- 当前作用范围为 `GLOBAL` 和 `DEVICE`。浏览器文本聊天只加载全局记忆；设备语音加载全局记忆和当前设备专属记忆。未来用户账户范围必须通过新迁移显式加入，不得复用设备 ID。
- 管理员手工创建的记忆视为用户明确确认，直接进入 `CONFIRMED`；机器人建议只能创建 `PENDING` 且保持停用，必须经确认接口转为 `CONFIRMED` 后才能进入上下文。当前版本提供待确认建议的数据模型与接口，但不自动从对话推断并写入建议；未来触发器也必须经过同一待确认路径。
- 提示词按“基础系统规则 → 结构化人设 → 已确认且启用的用户档案 → 已确认且启用的事件记忆 → 渠道附加规则 → 当前会话”组装。安全与系统规则优先，当前用户明确表达优先于旧记忆，同主题较新记忆优先，同等新旧时设备专属记忆优先。
- 记忆内容作为有界数据段加入提示词，不作为新系统指令；未确认、已拒绝、已停用和已删除的记忆不得加载。
- 每一轮都从 PostgreSQL 重新查询有效记忆，不建立会让删除延迟生效的唯一缓存。删除或清空后，下一轮上下文必须立即缺失相应内容。
- 控制台明确提示不要保存密码、令牌或完整身份凭据；系统不默认执行敏感信息识别或自动持久化。

## 原因

确认状态让“机器人认为值得记住”和“用户允许长期使用”成为两个独立事实。设备范围复用现有语音会话绑定，不需要改变固件或 SCV1，同时避免一台设备的专属信息泄漏给其他设备。结构化人设和固定组装顺序比继续堆叠自由提示词更容易解释、测试和迭代。

## 影响

- Flyway V16 新增人设与长期记忆表；部署 server 时必须执行 V16，但不需要刷写固件。
- 文本聊天和设备语音共用同一提示词组装服务，因此确认、启停和删除边界一致。
- 管理端新增人设设置、长期记忆列表和详情路由，可以搜索、编辑、确认、拒绝、启停、删除和清空。
- 自动生成记忆建议仍是 INT-005 的后续增量；启用前必须验证供应商兼容性、额外延迟和待确认展示，不能直接把模型推断写成有效事实。
