# 0041：私用优先的确定性工作日陪伴闭环

- 状态：ACCEPTED
- 日期：2026-08-24
- 工作流：全局
- 相关提交：`fa093dc`（实现基准）

## 背景

StackChan 已具备语音对话、角色、确认记忆、提醒、主动关心、受控 Agent、设备连接、动态表情、备份和 OTA，但当前路线主要以模块完成和底层媒体能力衡量进展，尚未证明机器人能稳定进入日常使用。官方 K151 整机还具备反馈舵机、接近/环境光、三段触摸、RGB、NFC、红外和电池监测，其中多数未被当前固件使用；项目文档关于缺少接近传感器的结论与整机事实不符。

用户决定先进行数月单用户私用，不承担开源安装和多硬件兼容成本。近期产品主身份是长期桌面陪伴，事务能力和受控 Agent 为辅助，并要求用二至四周建立可验证的工作日闭环。

## 决策

- 下一主线为 `WORK-001` 工作日桌面陪伴 V1，具体范围和实施顺序由[开发设计](../workday-companion-v1.md)约束。
- 用户必须显式启动工作模式；传感器只负责维持、暂停和恢复，不能自行开始全天监听或随机打扰。
- 日程、天气、在场、专注和休息均使用确定性规则。LLM 不改写事实、不决定打断时机、不提供舵机参数。
- iCloud Calendar 首版通过已验证 Apple Account 邮箱配合可撤销的 App 专用密码只读接入，按允许列表同步，私密事件隐藏标题，详情缓存最长二十四小时；真实对照已确认手机号不适用于 Apple CalDAV。CalDAV 只允许 Apple 全球/中国大陆根入口及其 `p数字-caldav` 编号 HTTPS 分片，并仅在全球端点认证失败时尝试中国大陆入口。
- 天气位置由管理页配置，V1 使用无独立密钥的 Open-Meteo；不建设手机持续定位。
- 当前活动角色负责语气、音色和表现；设备级工作设置不按角色重复。
- 身体动作只允许固件内置模板，默认保持 `motion_disabled`；校准、软限位、音频空闲、触摸停止和本地故障回退是启用前置。
- 摄像头、NFC、红外、Home Assistant、日历写入、随机主动闲聊、iOS App、多硬件兼容、舞蹈、模型控制舵机和开源安装优化冻结到私用验证之后。
- MEDIA-004 实现视为完成；因用户暂无 EAF 素材，V2 实体激活验收明确延期，不执行 OTA，也不把延期写成通过。

## 原因

确定性工作闭环能复用现有可靠提醒、互动回执、角色、免打扰和设备状态，同时用可测的每日使用结果验证产品价值。先私用避免把时间投入尚未证明价值的安装支持。有限动作和最小化外部数据则在增加身体感的同时维持既有隐私、安全和音频优先级。

## 影响

- 服务端将新增工作模式、只读 CalDAV、天气缓存和聚合指标，但不能把事件正文、凭据、位置历史或原始传感器流写入日志和指标。
- 前端扩展现有交互设置页面，不新增重复一级导航。
- 固件需要恢复并扩展 K151 整机硬件能力，但任意角度协议和模型运动权限继续禁止。
- 新主线开始前先修正已合入 MEDIA-004 后仍陈旧的状态、里程碑和硬件事实。
- 十四天门槛通过后继续私用六至八周；后继能力必须依据使用数据另立决策。
