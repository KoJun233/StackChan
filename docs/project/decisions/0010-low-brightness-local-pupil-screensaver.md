# 0010：空闲屏保采用低亮度、小区域、低频移动瞳孔

- 状态：ACCEPTED
- 日期：2026-07-20
- 工作流：固件
- 相关提交：`b4876fb`

## 背景

ADR 0008 为消除快速整屏闪烁，将 300 秒空闲屏保改为完全关闭背光。用户随后明确希望屏保保留可见的动态表情，但不能恢复高频整屏重绘或增加屏幕损耗。

## 决策

CoreS3 连续空闲 300 秒后把背光从正常亮度降低到低亮度，并以 2.5 秒为周期移动两只瞳孔。每帧只擦除并重画两个直径 26 像素的瞳孔区域，不清屏、不重画脸部其他区域，也不更新状态灯、嘴部或背景。

瞳孔沿固定、有界的八帧路径循环，偏移量在水平和垂直方向均不超过 8 像素，始终留在眼白内部。触摸、WakeNet 唤醒、语音状态切换、回复播放或提醒播报立即恢复正常亮度并完整重画当前表情。

## 原因

低亮度和低刷新率降低持续发光与写屏频率；只更新小范围瞳孔避免原实现的快速整屏闪烁，同时通过位置变化减少同一像素长期保持高亮的风险。固定路径便于测试和复现，不需要随机数、网络或服务器时钟。

## 影响

- 屏保继续完全由本地固件决定，网络离线时也能工作。
- 不得把刷新率提高到肉眼连续动画级别，也不得在屏保中周期性整屏重画。
- 屏保不初始化摄像头、LED、舵机或其他执行器，`motion_disabled` 保持不变。
- 固件刷写仍要求用户明确确认 CoreS3、串口、transport profile 和精确 Git commit。
