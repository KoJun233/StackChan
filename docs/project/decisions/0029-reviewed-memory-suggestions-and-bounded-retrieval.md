# 0029：长期记忆建议经过敏感过滤、冲突确认与有界检索

- 状态：ACCEPTED
- 日期：2026-08-02
- 工作流：服务端、前端、部署
- 关联：[0020：长期记忆必须经过确认并按会话范围组装](0020-confirmed-scoped-long-term-memory.md)、[0023：对话使用受控 ReactAgent、受信任 Skill 与仅授权 MCP Tool](0023-controlled-react-agent-skills-tools-mcp.md)、[0028：语音副作用采用结构化提案、确定性确认与幂等执行](0028-confirmed-idempotent-voice-actions.md)

## 背景

INT-005 已经支持管理员手工维护长期记忆，INT-010 允许明确的“记住”语音只写入待确认建议。INT-011 需要从普通完成回合中最多提出一条高价值建议，并让后续对话只检索少量相关记忆。自动提取不能把模型推断静默升级为事实，也不能把凭据、精确地址、身份号码或敏感财务/医疗推断保存到建议箱。

## 决策

### 建议与敏感边界

- 网页或设备语音回合成功完成后，应用可以异步执行一次独立建议提取；失败、取消、重放和动作提案回合不提取。每个来源回合最多保存一条建议，供应商失败或结构化结果不合法时不产生副作用。
- 提取器只接收当前完成回合的用户表达和机器人回答，不读取任意历史、Tool 参数/结果、认证信息、音频或供应商完整响应。模型只能返回固定 JSON 字段，应用再次校验类型、范围、长度和枚举。
- 凭据、验证码、令牌、密钥、精确住址、身份号码、银行卡号以及财务或医疗推断由应用侧敏感规则拒绝。被拒绝内容不写入记忆表，也不写入日志或审计正文。
- 自动建议固定为 `ASSISTANT_SUGGESTED + PENDING + disabled`。网页对话建议为全局范围，设备语音建议绑定当前设备；模型不能覆盖范围、设备或来源回合。允许主动提及默认关闭。

### 主题冲突与确认

- 每条记忆增加规范化 `topicKey`、1..5 重要度、来源回合、最后使用时间、替代关系和“允许主动提及”开关。
- 新建议与同范围的已确认启用记忆具有相同 `topicKey` 时，建议记录它可能替代的旧记忆，但旧记忆继续进入上下文。只有管理员确认新建议后，旧项才被标记为已替代并停用；旧项及替代关系继续保留以供审计。
- 修改待确认建议时重新计算可能替代项；拒绝、停用或删除在下一轮检索中立即生效。手工新增仍视为用户明确确认，但不会静默覆盖同主题记录。

### 检索与使用记录

- V25 启用 PostgreSQL `pg_trgm`，同时保留普通范围索引。检索只考虑当前范围内 `CONFIRMED + enabled` 且未被替代的记忆，综合关键词/相似度、重要度、最近使用和更新时间排序。
- 每轮最多选择 8 条，渲染到提示词的记忆段总计不超过约 4,000 个字符。`pg_trgm` 查询不可用时回退普通索引与确定性排序；空结果不扩大范围，也不恢复旧的全量 40 条/12,000 字符行为。
- 提示词组装返回本轮实际选择的记忆 ID。只有回合成功完成后才幂等写入 `turnId + memoryId` 使用记录并更新最后使用时间；记录不复制记忆正文、用户表达、机器人回答或模型响应。
- 管理 API 可返回来源回合、主题、重要度、替代关系、可能重复项、主动提及开关和按回合查询的已用记忆 ID，供管理页面解释来源；日志仍不得记录正文。

## 发布与兼容

1. V25 只扩展服务端记忆表、启用 `pg_trgm` 并新增使用记录表；现有记忆会以标题作为初始 `topicKey`、重要度 3、主动提及关闭进行兼容迁移。
2. INT-011 修改 server 和管理端静态资源，不改变 SCV1、WebSocket 命令或固件；发布时仍先替换 server，再用现有 `dd81a7e` 验证旧固件普通对话和连续对话。
3. 未经用户明确授权不替换运行 server、不执行 V25 运行迁移、不连接 COM3 或刷写固件。生产继续保持 HTTPS-only。
