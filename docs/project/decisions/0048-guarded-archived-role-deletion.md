# 0048：归档角色冷静期后由管理员手动永久删除

- 状态：ACCEPTED
- 日期：2026-09-01
- 工作流：服务端、前端、部署
- 相关提交：本任务提交（见 Git HEAD）

## 背景

角色归档会把设备切回默认角色，并让该角色停止进入新会话上下文，但会保留对话、记忆、提醒、通知和待办，便于误操作后恢复。只提供归档会让长期不用的个人数据无法清理；无人值守自动删除又会在管理员不知情时造成不可逆损失。

## 决策

- 默认角色永远不能永久删除；可用角色必须先归档。
- 归档后设置七天冷静期，期间可恢复且删除接口固定拒绝。
- 冷静期结束后只允许管理员在角色管理页二次确认后手动永久删除，不设置后台自动清理任务。
- 永久删除会级联清理该角色的会话与消息、长期记忆、提醒、通知集成、设备语音会话、主动主题冷却、语音动作记录和个人待办。
- `device_active_roles` 继续使用限制型外键；归档必须先把所有设备切回默认角色，它同时作为永久删除前的数据库安全门。
- 页面明确展示最早可删除日期和删除范围；逻辑备份仍按既有独立轮转策略保留，直到对应备份自然过期。

## 原因

七天冷静期为误归档提供可恢复窗口，手动确认让不可逆操作保持可见。由服务端时钟和事务统一裁决资格，不能通过修改浏览器时间绕过；数据库级级联确保角色数据不会残留为无主记录。

## 影响

- Flyway V46 调整角色数据外键，并把通知关联提醒和提醒分组改为可安全跟随父记录删除的策略。
- 删除成功后管理页面无法恢复该角色；灾难恢复必须继续走隔离备份 runbook，管理页不提供恢复按钮。
- 若未来需要自动保留策略，必须以新的明确决策替代本文，不能把当前七天冷静期解释为自动删除期限。
