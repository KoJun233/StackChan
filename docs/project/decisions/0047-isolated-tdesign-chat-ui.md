# 0047：TDesign Chat 仅用于陪伴聊天展示层

- 状态：ACCEPTED
- 日期：2026-09-01
- 工作流：前端
- 相关提交：本任务提交（见 Git HEAD）

## 背景

Fantastic-admin 仍适合承载后台导航、表单、表格、弹窗和状态卡片，但现有 `Fa*` 组件没有封装 AI 对话列表、Markdown 回复、自动滚动、复制回复和生成中止等组合能力。继续手写聊天气泡会重复维护可访问性、滚动与流式状态细节；在整个后台引入第二套通用组件又会造成主题和交互规范分裂。

## 决策

- Fantastic-admin 继续作为管理端唯一页面壳和通用管理组件体系。
- `@tdesign-vue-next/chat` 固定使用 `0.6.0`，只允许在 `/companion/chat` 的懒加载页面中直接导入 `ChatList`、`ChatContent`、`ChatActionbar` 和 `ChatSender`。
- 不使用 TDesign Chat 自带的传输或 Agent 状态层；现有 Pinia conversation store 继续负责服务端会话、SSE、幂等重试、取消和持久化边界。
- 聊天页只开启 Markdown、复制、自动滚动、停止生成和失败重试；附件、好评/差评、推理过程和分享保持关闭。
- 通过聊天页局部 CSS 变量桥接 Fantastic-admin 的品牌色、背景、文字和边框；其他页面不得为统一外观改用 TDesign 通用组件。

## 原因

这一边界复用成熟的 AI 对话展示能力，同时保留既有业务状态机和安全边界。路由级懒加载可把较大的聊天依赖隔离在高频对话页面，普通后台首屏不会加载它；通用后台继续使用 `Fa*`，避免两套表单、弹窗和表格规范并存。

## 影响

- 聊天路由会产生明显大于普通业务页的独立资源 chunk，升级 TDesign Chat 前必须复查安全修复、包体和主题桥接。
- 新增聊天能力应先判断能否组合现有四个展示组件；不得直接切换到 `Chatbot` 并绕过现有会话 store。
- 普通管理页面的新增与重构继续遵守 ADR 0001；若要扩大 TDesign 使用范围，必须由新的用户确认决策明确替代本边界。

## 替代关系

不替代既有 ADR；本文补充 [0001](0001-fantastic-admin-frontend.md) 的聊天页面例外。
