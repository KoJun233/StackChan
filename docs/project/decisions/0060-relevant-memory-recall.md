# 0060：长期记忆先筛相关性，再做有界排序

- 状态：ACCEPTED
- 日期：2026-09-13
- 工作流：服务端
- 关联：[功能评审 D02](../feature-review-2026-09-13.md)、[0059](0059-rendered-memory-context-accounting.md)

## 问题

原检索仅按 trigram 相似度排序，即使全部候选不相关仍返回最多八条；失败时又用重要度排序返回无关条目。用户因此可能在新话题中听到牵强的旧记忆。记忆回顾和具体话题检索也未区分。

## 决策

- 当前角色、设备范围、已确认、启用、未被替代的过滤继续优先生效；相关性过滤在数据库 LIMIT 前执行，防止无关高优先级条目挤占结果。
- 当前问题进行 NFKC、小写和 500 码点上限处理；去掉常见问句与偏好套话，提取至多 64 个中文双字片段或英文完整词。只用这些受限字符构造参数化正则，不把用户文本作为正则执行。
- 有限扩展咖啡/coffee、生日/birthday、称呼/昵称/nickname、饮品/饮料、早中晚饭/餐、散步/遛弯、宠物/pet。此表是可审查的词面召回辅助，不是完整语义理解；未覆盖的转述、单字对象和模糊指代可能漏召回，相关片段也仍可能产生误召回。后续按真实失败样例校准，不能宣称准确性已经全面验收。
- 明确的“你记得我什么”等回顾问句及兼容空查询允许返回最多八条已有记忆；提示词已说明是部分条目。具体话题无匹配时返回空集合，不用高重要度无关条目填充。检索到的条目也只应在确实有助当前话题时自然使用。
- 筛选后的候选继续按现有 trigram、重要度和使用/更新时间排序。查询使用独立只读事务；数据库查询失败返回空记忆上下文，避免异常污染调用方事务，不在失败事务内再次执行降级 SQL。
- 无新增外部模型调用、向量数据库、数据共享或迁移。跨角色记忆仍保持独立，偏好替换继续走原确认流程。

## 验收

真实隔离 PostgreSQL 覆盖：二十条无关高重要度记忆不能挤掉相关低重要度条目；无关闲聊与问候返回空；特定回忆问题和完整回顾分开；常见中英文/全角同义表达；英文子串和正则符号负例；角色/设备隔离；禁用、拒绝和已替代记录排除；查询失败后调用方事务仍可读取数据库。单元测试覆盖空降级、问句负例和 Unicode 长度边界。实际聊天自然度与召回准确率仍需正式使用样例。
