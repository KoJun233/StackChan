# 0046：今日待办进度复用最小只读 Tool

- 状态：ACCEPTED
- 日期：2026-08-31
- 工作流：服务端、部署
- 相关提交：WORK-006 任务提交（见 Git HEAD）

## 背景

WORK-004 已允许机器人读取未完成待办并确认式新增或完成，WORK-005 已把最多两项优先待办加入首次简报，但用户仍无法可靠询问“今天完成了什么”。让模型从历史对话推断完成情况会产生幻觉；为日终进度另建主动播报又会改变正在进行的十四天观察口径并增加打扰。

## 决策

- 扩展既有 `current_personal_tasks` 只读 Tool，在保持原 `tasks`、`count` 字段兼容的同时追加当前设备时区下的今日完成项。
- 今日完成范围固定为当前认证设备、当前活动角色和本地自然日；设备、角色和时区由服务端绑定，模型不能提供。
- 今日完成项最多十项，按完成时间倒序选择；模型只接收标题，不接收备注、精确完成时间、完成项 ID 或其他归属字段。
- 用户询问今日完成情况或任务进度时，受控 Agent 必须成功调用该 Tool；失败或未授权时拒绝猜测。
- 该能力仅响应用户主动查询，不新增日终播报、调度器、提醒、数据库迁移、页面、固件或动作。

## 原因

复用现有 Tool 可保持授权和审计入口不变，也避免增加新的管理开关。服务端以设备时区计算边界并只返回最小字段，既能回答日常进度，又不向模型暴露待办备注或精确行为时间。被动查询不改变首次简报去重和十四天主动打扰指标。

## 影响

- V45 现有 `completed_at` 和索引足以支持有界查询，不需要 Flyway 迁移。
- `current_personal_tasks` 的旧消费者仍可读取原字段；新增字段只提供今日完成摘要。
- 若未来需要自动日终总结、完成率趋势或跨日统计，必须另立决策定义主动时机、保留策略和观察口径，不能从本只读查询隐式扩展。
