# 0043：十四天私用门槛使用显式、本地、匿名聚合

- 状态：ACCEPTED
- 日期：2026-08-30
- 工作流：服务端、前端、部署
- 相关提交：待 WORK-002 任务提交

## 背景

`WORK-001` 已由 `c62ccd0` 合入，但原有九十天指标只统计会话、简报、专注和休息，不能验证产品设计冻结的误播报、外部降级归因、动作安全失败和设备重启门槛。依赖人工回忆或日志会遗漏事件，也会诱使系统保存不必要的正文和传感器数据。

## 决策

- 管理员显式开始或重新开始固定十四天观察；开始时冻结设备时区和工作日规则，系统不自动推断观察起点。
- 当前观察每台设备只保留一个窗口；重新开始不删除九十天聚合。
- 误播报由管理员按天增加匿名计数并可撤销，不要求保存原因或正文。
- 外部服务只保存来源计数和固定失败码；动作只保存安全拒绝数、实体失败数；重启由持久设备序号回退识别。
- 安全拒绝与预期触摸/语音停止不作为动作安全失败。只有超时、反馈和硬件错误使动作门槛失败。
- 报告在十四天结束前只显示 `COLLECTING`，结束后按冻结门槛确定性计算 `PASS` 或 `FAIL`。
- 指标写入与心跳、简报核心链路隔离；可观测性失败不能影响机器人连接或日常播报。
- 不修改固件协议，不启用身体动作，不上传外部分析服务。

## 原因

显式窗口避免把开发验收与真实私用混在不确定的起点中；匿名每日聚合足以判断门槛，又不会形成日程、天气、语音或家庭环境的第二份数据副本。固定分类和确定性报告使六至八周后是否继续开放能力有可复核依据。

## 影响

- V43 扩展设备序号、每日聚合和当前观察窗口。
- 管理页增加开始、重新开始、误播报标记/撤销和十四天报告。
- 同一天开始前已有聚合仍按当天计入，管理员应在首次实际使用前开始。
- 十四天观察本身仍是运营阶段；本决策不建立 `WORK-001A/B/C` 或 `PILOT-001` 交付维度。
