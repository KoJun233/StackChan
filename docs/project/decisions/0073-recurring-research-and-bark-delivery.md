# 0073：持续委托的周期资料研究与 Bark 交付

- 状态：ACCEPTED
- 日期：2026-10-08
- 工作流：服务端、前端
- 相关提交：`ec53bfe`（实现基准）
- 关联：[设计与验收](../recurring-research-delivery.md)

2026-10-10：[ADR0074](0074-natural-language-delegation-tasks.md) 已替代本 ADR 的固定资料输入、固定研究执行和每天唯一运行槽限制。Bark、密钥、HTTPS 与迁移安全约束继续有效；下文保留 V58 决策背景。

## 背景

用户认为单纯聊天可被手机聊天产品替代，希望生活伙伴能接下持续工作。用户以每日 AI 日报为第一个例子，明确主题不得写死，并选择控制台管理、Bark 在 iPhone 接收、当地 08:30 和最多五条带来源内容。

## 决策

新增通用持续委托、当日运行与成果、独立投递状态。首个执行能力是对明确配置的公开 RSS/Atom 来源进行周期资料研究；题目和整理要求来自委托。日报模板不决定通用运行器的主题。允许每日/每周、暂停/恢复、当日幂等手动运行与历史阅读。

每次生成使用范围固定的来源材料和模型调用预算，引用只映射到实际候选项。没有内容或来源失败时明确记录，不以无来源模型回答冒充日报。后台工作不继承网页或设备语音请求中的额外权限。

首版 Bark 出站投递与控制台成果分开。密钥加密保存并仅写；不暴露 LAN HTTP，不依赖 Mac 常开中转。已生成内容不会因投递失败重新生成；未知发送结果不自动重发。手机已阅读不在推送 API 能证明的范围内。

## 原因

这条路径可以验证一次委托后跨天产生实际成果，并保留未来其他执行能力和渠道的入口。Apple 公开个人 iMessage 接口不适用于当前 Windows 服务端直接推送，Mac 中转增加常开设备依赖。Bark 提供适合个人 iPhone 通知的 HTTPS API。

## 影响与替代关系

用户的新实施请求解除 [0069](0069-companion-first-console-consolidation.md) 中对本轮周期资讯扩源与持续任务的冻结；其他已确认边界不因此扩大。既有外部通知仍是入站语音业务，不改成手机出站业务；提醒、记忆和待续许可保持其原意。

迁移使用 V58，保留尚未合入的旧任务 V57。安装需含 V57 的集成来源及兼容验证，不直接用当前独立分支降替运行服务。本任务未包含外推、生产模式切换、固件或实体操作授权。
