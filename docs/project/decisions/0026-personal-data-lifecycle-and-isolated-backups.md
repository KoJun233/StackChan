# 0026：个人数据物理删除、范围导出与隔离备份恢复

- 状态：ACCEPTED
- 日期：2026-07-29
- 任务：`DATA-001`

## 背景

StackChan 已将网页聊天和设备语音正文保存在 `conversations` 与 `conversation_messages`。用户需要在管理端查找、导出和删除这些个人数据，同时需要一套不依赖运行数据库数据卷的 PostgreSQL 逻辑备份与恢复验证机制。

## 决策

### 对话删除

- 对话和消息均采用物理删除，不增加软删除正文副本。
- 删除单条消息只删除指定消息；若其他消息通过 `in_reply_to_message_id` 引用它，引用被置空，另一条消息不会被连带删除。
- 删除整段对话由数据库级联删除消息和设备语音映射。
- `STREAMING` 消息及包含 `STREAMING` 消息的对话不能删除，避免与正在写入的生成任务竞争；管理员应先停止生成再删除。
- 删除后，下一次上下文组装、管理搜索和导出都直接读取当前表，因此正文立即失效。
- 语音阶段诊断和 Agent Tool 审计只保留已有的非正文元数据。它们不建立对话外键，也不会复制或恢复已删除正文。

### JSON 导出

- 导出与管理列表使用相同的设备、时间和关键词过滤条件，并允许导出单个对话。
- 导出顶层包含固定 `schemaVersion`、导出时间、过滤范围和对话数组；每段对话只包含对话元数据、可选设备标识/显示名和当前仍存在的消息。
- 导出不包含管理员账户、会话、设备凭据、模型或语音配置、API Key、JWT、MCP 认证、诊断日志或 Agent Tool 参数/结果。
- 第一版对一次导出的对话数量设置上限，避免通过管理接口无界占用内存；超出时要求缩小筛选范围。

### 备份布局与轮转

- 使用独立 `stackchan-postgres-backups` 卷保存 PostgreSQL custom-format 逻辑备份，不与 `stackchan-postgres-data` 数据卷共用。
- 备份先写入 `.partial`，完成 `pg_dump`、SHA-256 和元数据生成后再原子改名。部分文件和失败任务不会成为成功备份。
- `daily/` 保留最近 7 份成功备份；`weekly/` 按 ISO 周保存该周最新成功备份并保留最近 4 周。重复执行同一周只替换该周副本。
- 每份清单记录创建时间、文件大小、摘要、源 PostgreSQL 版本、成功的 Flyway schema 版本列表，以及人设、已确认记忆、提醒和表达资源包计数。
- `status.json` 只保存安全状态和恢复验证摘要，并以临时文件原子替换。

### 恢复隔离

- 每次成功备份后，在备份容器内创建一次性 PostgreSQL 数据目录和 Unix socket，恢复到空的临时数据库。
- 恢复脚本拒绝任何运行数据库目标参数；它不接受目标主机、目标 URL 或目标凭据，只能使用脚本创建的临时实例。
- 恢复完成后比较人设、已确认记忆、提醒和表达资源包计数，并在退出时停止临时实例和删除临时目录。
- 管理页面只读取备份状态，不提供恢复按钮，也不返回文件路径、备份内容、数据库凭据或密钥。

## 后果

- 单条删除语义清晰，不会因为消息配对关系意外删除另一条正文。
- 已删除正文无法从应用数据恢复，但仍可能存在于保留期内的历史备份；恢复备份属于管理员离线灾难恢复操作，不是撤销删除功能。
- 备份容器需要与数据库版本匹配的 `pg_dump`/`pg_restore`，并需要独立持久卷；服务端仅以只读方式挂载该卷。
