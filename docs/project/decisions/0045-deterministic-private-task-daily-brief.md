# 0045：首次简报使用确定性、隐私安全的个人待办摘要

- 状态：ACCEPTED
- 日期：2026-08-31
- 工作流：服务端、部署
- 相关提交：WORK-005 任务提交（见 Git HEAD）

## 背景

WORK-001 的首次简报已经提供天气和日历，WORK-004 也已保存本地个人待办，但两者彼此独立。用户每天开始工作时仍需要主动询问机器人才能知道当前待办，这削弱了工作日闭环的日常价值。直接把全部未完成任务交给模型排序会扩大隐私暴露、增加不确定性，并可能让简报变得过长。

## 决策

- 首次简报由服务端确定性选择当前设备、当前活动角色的最多两项未完成待办，不调用 LLM 排序或改写。
- 候选限定为逾期、今天到期或高优先级；到期事项优先并按时间升序，高优先级未来或无截止事项随后。
- 简报只读取标题、优先级和到期分类，永不读取或播报备注；长标题按 Unicode 码点安全截断。
- 待办段是本地可选增强。查询失败不得阻断天气、日历或可靠提醒投递，也不得改变由天气/日历定义的简报成功状态。
- 继续复用每天一次的首次简报占位、免打扰、忙碌抑制和设备 ACK；不增加第二条主动播报。
- 不修改观察门槛、数据库结构、管理页面、Agent Tool、固件或身体动作。

## 原因

固定筛选和两项上限能把任务价值加入现有日常入口，同时保持播报时长和行为可预测。由本地服务完成选择避免把备注或完整任务集合交给模型，也不会引入新的外部依赖。失败开放策略使个人待办暂时不可读时仍能完成原有天气/日历简报。

## 影响

- WORK-005 在 V45 数据结构上增加只读候选查询和简报拼接，不需要 Flyway 迁移。
- 角色切换会自然改变下一工作日简报的待办范围；当天已经入队或完成的简报不会因切换角色而重放。
- 若未来需要任务自动规划或完整日清单，必须作为独立决策定义模型权限、时长上限和用户确认边界，不能静默扩大本摘要。
