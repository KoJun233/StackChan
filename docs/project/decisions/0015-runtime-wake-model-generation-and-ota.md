# 0015：自定义 WakeNet 模型采用在线生成或本地上传与三槽安全 OTA

- 状态：SUPERSEDED（由 [0016](0016-built-in-esp-sr-wake-model-catalog.md) 替代）
- 日期：2026-07-23
- 工作流：服务端、前端、固件、部署

## 背景

管理员需要在网页输入新的唤醒短语后，由系统自动生成模型、发送给目标机器人并重启启用，而不是每次重新构建和刷写整套固件。也需要允许管理员在自己的电脑完成训练后上传模型包，避开尚未接通的在线生成器。WakeNet 仍然不能直接把运行时文本当作模型；短语必须先由兼容 ESP32-S3 和 ESP-SR 2.4.6 的生成器产出 ESP-SR 模型包。

Espressif 没有提供可直接内置到本项目的公开“任意文本即时生成 WakeNet 模型”API。仓库也不能捆绑未知供应商凭据或把一个占位文件伪装成模型，因此需要定义真实、可替换的生成器边界。

## 决策

- 管理员在语音设置页选择机器人并输入 1 至 32 个 Unicode 码点的短语。服务端规范化文本并创建持久任务，状态依次为 `QUEUED`、`GENERATING`、`READY`、`INSTALLING`，最终进入 `INSTALLED`、`ROLLED_BACK` 或 `FAILED`。
- 页面提供 `ONLINE_GENERATION` 和 `UPLOAD` 两种来源。上传模式接收一个不超过 1.125 MiB 的 ZIP；根目录必须且只能包含 `manifest.json` 和 `srmodels.bin`。验证成功后任务直接进入 `READY`，不调用在线生成器；任务来源持久保存用于审计。
- 服务端通过 `COMPANION_WAKE_MODEL_GENERATOR_EXECUTABLE` 调用受运维控制的生成器进程。进程从 stdin 接收固定 JSON，并只可在指定输出目录写入 `manifest.json` 和 `srmodels.bin`；未配置真实生成器时任务必须以 `generator_unavailable` 失败。
- 在线生成器输出和上传包都必须声明 ESP32-S3、ESP-SR 2.4.6 和 `esp-sr-model-pack-v1`。服务端重新计算 SHA-256，并验证模型包结构、连续文件区、1 MiB 上限、目标自定义模型和 `wn9l_histackchan_tts3` 出厂回退模型同时存在。符号链接、未知清单字段、ZIP 路径或额外条目和不兼容输出均被拒绝。
- 服务端只向任务所属设备提供固定同源制品端点。设备使用已有设备 Bearer Token 下载；WebSocket 命令不接受 URL、凭据或额外字段。
- 固件保留永久只读意义上的出厂 `model` 分区，并在 `model_a`、`model_b` 两个 1 MiB 分区间交替安装。下载完成后设备校验长度、SHA-256 和 ESP-SR 包结构，只有全部通过才把目标槽标记为 pending 并重启。
- 新槽启动后，语音任务必须真实创建目标 WakeNet、验证 16 kHz 单声道和采样块，并分配监听缓冲区，随后才能确认安装。目标模型缺失、只加载到包内 fallback、20 秒内未确认，或 pending 状态发生第二次启动时，设备恢复上一槽并再次重启。
- 安装或回退结果保存在加密 NVS 中。设备在每次 WebSocket 重连后补报一次相同结果；服务端按任务、设备、模型名和 SHA-256 幂等处理。
- 已运行旧分区表的设备必须先经过一次明确授权的完整固件刷写，取得 `model_a`、`model_b` 和本决策的固件逻辑。完成这次引导后，更换唤醒短语只传输模型包，不再重刷固件。
- `motion_disabled`、LAN HTTP 仅开发使用和生产 HTTPS-only 边界保持不变。

## 原因

持久任务使耗时生成、文件上传、设备离线和服务重启都可观察；生成器进程契约允许接入实际供应商或自建流水线，而不把供应商私有协议写死在核心服务中。本地上传让已有训练环境可以立即接入，同时不降低模型校验标准。固定同源下载、内容校验和三槽回退共同限制了损坏包、错误模型和启动失败的影响范围，永久出厂槽保证两份 OTA 模型都不可用时仍有已验证恢复点。

## 影响

- 网页提交不是“保存一段文本”，而是启动可能持续数分钟的模型生成与安装任务。
- 上传普通 `.tflite`、裸的单模型文件或只含自定义模型的 `srmodels.bin` 不会被接受；上传包必须符合本决策的双模型 ZIP 契约。
- 生产可用性依赖运维提供真实且兼容的生成器可执行文件；仓库默认配置不会生成虚假模型。
- 模型制品暂存在 PostgreSQL，任务进入终态后清除二进制；任务元数据和失败码继续保留用于审计。
- 首次启用需要一次分区表/固件升级和真机 smoke test，此后无需为每个短语刷写固件。
