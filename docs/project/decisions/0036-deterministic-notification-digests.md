# 0036：通知摘要采用集成级等待窗口、确定性原文拼接与共享 ACK

- 状态：ACCEPTED
- 日期：2026-08-13
- 工作流：服务端、前端、部署
- 关联：[0032：外部通知平台](0032-external-notification-platform.md)、[0035：互动通知回执](0035-interactive-notification-responses.md)

## 背景

外部 Agent 或 CI 可能在短时间内产生多条完成消息。逐条合成和播报会打断用户，也会放大 TTS 请求；直接用 LLM 总结又会改变原文，并使单条通知的 ACK、过期、重试和互动回执归属不清。

## 决策

1. 摘要是通知集成的可选配置，默认关闭；管理员可设置 5–300 秒等待窗口，旧客户端省略配置时保持当前值。
2. 只聚合同一集成、同设备、同角色的单向外部通知。带 `responseActions` 的互动通知始终立即逐条播报，不进入摘要。
3. 每批最多 10 条、合成文本最多 1,000 字。服务端使用固定编号模板按创建顺序拼接原文，不调用 LLM，不跨集成或角色改写内容。
4. 摘要内部只有首条通知进入真实 `DISPATCHED` 并持有音频和命令；成员通过内部投递组绑定。对 REST/MCP 和管理页面，组内成员统一显示 `DISPATCHED`。
5. 设备 ACK、取消、播放失败或五分钟超时恢复按整个投递组原子推进。每条通知继续保留自己的 ID、幂等键、尝试次数、过期时间和最终状态；外部调用方仍逐条查询。
6. 已开始播放的摘要成员禁止单条或集成删除，角色归档也不提前取消；过期扫描等待本次 ACK 后再决定最终结果。

## 影响

- Flyway V32 增加集成聚合窗口和提醒投递组字段。
- 不增加外部 REST/MCP Tool，不修改固件或设备命令。
- 摘要减少短时密集播报，但会为首条单向通知引入最多配置窗口的等待。

## 替代关系

本决策完成 ADR 0035 中拆出的 `EVT-003`，不改变互动通知的确认和回执语义。
