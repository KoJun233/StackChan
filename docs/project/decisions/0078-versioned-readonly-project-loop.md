# ADR0078：一次只读项目与版本化成果反馈

- 状态：ACCEPTED
- 日期：2026-10-15
- 基准：`a961816`（PR #49 已合入 R00/R01）
- 关联：[R02](../../requirements/companion-v1/R02-project-loop.md)、[交付记录](../baselines/companion-r02-project-loop.md)

## 决策

沿用 delegation、原 ReactAgent、运行与投递枚举；只给 ONCE 新意图开启 project_loop。带幂等键的周期任务仍使用旧调度和 occurrence，手动运行不能清除下一次安排。项目被明确改为周期时关闭 project_loop，原审阅保留但反馈入口不再修改；未来 ONCE 的调度和手动入口必须共用修订运行槽，暂停后恢复也不例外。明确现在的 ONCE 在保存任务的事务中创建运行槽，提交后才交给原两工作者；无队列，容量不足保留 FAILED 历史，由用户明确重试。

公开读取授权来自用户给定 URL 或明确的公开资料探索指令，独立保存 project_source_mode。模型的 requiresToolEvidence 和工具提议不能授予联网权限。给定 URL 规范化后逐次在工具 handler 前匹配；纯文本显式空工具集不继承旧 Agent 的默认查询能力。实际读取记录输入 URL、证据编号和读取时间。原 HTTPS 读取器拒绝所有 3xx，本轮继续拒绝，不增加重定向能力。

模型返回结构化内容，服务器把可核对的原文与推断分开，渲染五区到原 run.output。缺来源、重复方案、伪造引用或假完成转 BLOCKED，保留有限事实。原 output 不因反馈被覆盖。反馈锁定 task.revision 与 review.resource_version；偏好修订增加原 task 的 revision，并用独立修订运行槽关联原 run。运行成功、渠道 SENT 和用户 ACCEPTED 分开保存。

V62 新增审阅、反馈、修订意图、操作收据与可选项目列，V1–V61 不变。收据绑定 device/role/action/key、规范请求摘要和资源；PENDING 先持久化，业务结果与 COMMITTED 同事务。失败同键不重试；进程重启把未提交收据标 FAILED。收据只保留 UUID 与固定元数据，删除私人任务会级联清除正文和审阅，但旧键仍不能新建任务。

自然入口先确定性区分真正委托、能力咨询、示例、拒绝与结果查询；设备与伙伴来自认证上下文，去除唯一设备猜选。十分钟草稿过期不继承授权。查询只读原成果，多候选用序号消歧。裸停止沿用前台取消，取消长期任务必须有明确对象。取消落库后原更新、恢复、运行与修订入口均拒绝再次执行。

## 后续与边界

R03 可通过原 taskId/runId 引用本轮历史；不复制成果另建正文库。完整 goal 状态、阶段与预算仍由 R03–R05 实施，R02 不宣称已验证尚不存在的 R03 迁移。Bark 默认关闭式授权语义保持，UNKNOWN 不自动重发。当前偏好撤销手机交付时降为 CONSOLE，偏好接口不会新增手机授权。网页使用管理员会话与 CSRF，不因 URL 中的 UUID 获得设备命令权限。

实际成果、实体语音与 360/1280px 视觉验收独立报告；离线假页面不能证明真实项目完成。开发、候选构建和只读核验不代表安装、刷写、外推或真实外发授权。
