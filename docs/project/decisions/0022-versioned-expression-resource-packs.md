# 0022：表情采用内置机械眼与可校验的版本化资源包

- 状态：ACCEPTED
- 日期：2026-07-28
- 关联：[0017：本地可见交互状态](0017-local-user-visible-interaction-states.md)

## 背景

0017 已固定机器人可见状态的语义，但原来的几何图形只能用于调试，缺少可交付的视觉层，也不能让管理员安全替换宠物形象。资源替换同时涉及图片一致性、设备离线、下载认证、掉电恢复、损坏回退和删除后的副本清理，不能把任意图片 URL 直接交给设备。

[FluxGarage/RoboEyes](https://github.com/FluxGarage/RoboEyes) 提供了圆角机械眼、眨眼、视线和情绪变化等有价值的视觉参考，但其仓库使用 GPL-3.0。当前项目没有采用其源代码或派生文件；默认表情以 M5Unified/M5GFX 独立实现，只借鉴公开可观察的交互概念。

## 决策

1. 默认表情是固件内置、无需网络和外部资源的机械眼渲染器。它覆盖 `idle`、`listening`、`processing`、`speaking`、`success`、`no_speech`、`offline`、`error` 八个稳定状态，并提供有界的眨眼、视线、脉冲和嘴型动画。
2. 自定义宠物表情包 v1 必须恰好包含上述八张 `320×240` PNG。单张不超过 384 KiB，完整制品不超过 1.5 MiB；服务端必须真实解码图片并校验尺寸、格式和每张 SHA-256。
3. 制品使用固定魔数 `SCEPKG1\0`、小端版本/清单长度、JSON 清单和顺序 PNG 载荷。设备不接受命令中的外部 URL，只从自身已配置服务的同源、设备认证端点下载。
4. 设备使用 `expression_a` / `expression_b` 两个 1.5 MiB 槽。新包写入非活动槽，完成整体摘要、清单、状态集合、每图摘要和 PNG 头校验后才更新 NVS 活动指针；失败或重启损坏时继续使用上一包或内置表情。
5. 新包成功切换后擦除旧槽；停用时先恢复内置表情，再擦除两个资源槽。离线设备在下次重连时收到幂等清理命令，避免删除后的图片长期留在设备闪存。
6. 自定义 v1 图片是静态状态图。低亮度屏保继续使用内置机械眼的小区域、低频瞳孔移动，避免对未知宠物图片做破坏性局部重绘。
7. 服务端保存管理端预览图和设备制品，但不把图片、摘要载荷或认证内容写入运行日志。数据库删除使用级联移除八张预览和制品；启用中的资源包不得删除。

## 结果

- 即使服务端、资源包或设备下载失败，机器人仍有完整且可辨识的默认表情。
- 资源包生成器可以独立演进，只要输出稳定的八状态 PNG；当前管理端负责本地预检、上传、预览、生成、启用、停用和删除。
- v1 不执行云端图片生成，也不把用户图片发送给未配置的第三方。AI 绘图工具可按 runbook 在边界外生成八张输入图，再由可信服务端编译制品。
- 后续若需要动态宠物动画，必须新增格式版本和容量/刷新预算，不得静默改变 v1 语义。
