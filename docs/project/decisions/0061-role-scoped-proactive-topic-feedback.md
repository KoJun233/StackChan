# 0061：主动话题反馈与恢复使用同一角色范围

- 状态：ACCEPTED
- 日期：2026-09-13
- 工作流：服务端、前端
- 关联：[功能评审 D03](../feature-review-2026-09-13.md)

## 问题与决策

话题冷却数据已经按设备和角色隔离，但语音“别再提这个”调用默认角色重载，控制台列表和恢复也只能操作默认角色。非默认伙伴的反馈因此可能无效或改到另一个伙伴。

- 语音反馈从当前会话取得角色，按设备、角色静默最近话题；兼容旧构造器的默认角色路径，实际服务注入会话服务。
- 话题列表及恢复 API 接收 UUID `roleId` 查询参数；省略参数时保留旧客户端的默认角色行为。明确指定角色时禁止退回默认角色查找。
- 控制台初次读取设备当前伙伴作为查看范围，允许选择其他未归档伙伴；查看和恢复不会切换设备伙伴。列表和恢复都携带显式角色。
- 请求保存设备和角色快照，切换范围即清空旧列表；使用请求序号与范围比对排除过时响应。恢复后只刷新原范围仍被选中的列表；加载失败区别于没有记录。
- 数据库结构、冷却周期、主动配额与记忆隔离不变。此改动只修复作用范围，暂不代表主动接受/拒绝/暂停闭环全部完成；最近主题仍取原主题记录，后续需核对成功播放与反馈目标的一致性。

## 验收

语音用例断言采用非默认会话角色；HTTP 用例覆盖指定角色、兼容默认角色与非法 UUID；前端 API 测试断言列表和恢复采用同一角色。真实 PostgreSQL 以同一话题键验证静默/查看/恢复不影响其他角色或设备。运行服务端回归、控制台全量测试、类型检查、生产构建及改动文件 ESLint/Stylelint。实体语音和页面交互尚待验收，不自动部署。
