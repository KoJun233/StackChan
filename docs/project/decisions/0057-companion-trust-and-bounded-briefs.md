# 0057：陪伴资讯措辞、待办总量与工作简报的可信边界

- 状态：ACCEPTED
- 日期：2026-09-13
- 工作流：服务端
- 关联：[功能评审 D04/D05/D06](../feature-review-2026-09-13.md)、[0046](0046-private-read-only-daily-task-progress.md)、[0052](0052-source-backed-interest-briefs.md)

## 背景

用户已授权按评审开始改造机器人。本轮交付报告 P0-2：标题资讯不能邀请用户听尚未读取的全文；待办总量不能等于截断列表长度；自动工作简报必须对长标题有统一预算。

## 决策

1. 资讯结尾改为邀请讨论话题，仍只确定性引用来源标题。无全文的上下文约束、来源记录、配额和回退不变。
2. 待办 Tool 保留 `count` / `completedTodayCount` 的已返回条目数量语义，新增 `totalCount` / `completedTodayTotalCount`、`hasMore` / `completedTodayHasMore` 和 `localDate`。工具说明明确总数取 total 字段。详情仍限 20/10 条且不包含备注；完成项仍仅含标题。
3. 通过同一只读 REPEATABLE_READ 事务查询当前设备/角色的两个列表与总量，冻结查询时的本地日期；完成区间为当地零点到次日零点的半开区间，覆盖夏令时。保留原有列表方法供其他业务使用。无新表或迁移。
4. 工作简报最多 200 个 Unicode 码点。角色名最多 8、天气摘要最多 39、单个日历/任务标题最多 12 个码点（标题限额含省略号）；最多两项日历和两项待办，保留日期、分类和来源降级说明。过长天气按完整分句收束并提示可查询详情，没有可用分句则只告知天气已更新，避免截断事实数字。最终总长门控作为防线。存储标题、查询与操作确认不截断。码点预算不等于二十秒实际音频，真实音色时长另验。
5. 不改变角色隔离、可靠提醒单飞/去重、每日简报 SUCCESS/PARTIAL 口径、主动次数、语音单 WAV 或身体安全状态。

## 验收

- 原测试基线 25/25。新增测试覆盖 21/11 条、空列表、设备/角色隔离、半开日期边界与夏令时；真实 PostgreSQL 验证聚合查询。
- 超长角色名/天气/日历/任务及 Unicode 补充字符下总长不超过 200，保留各来源和私密屏蔽；失败来源不阻断其余内容。
- 资讯仍引用同一原始标题与来源，未知编号/生成失败继续回退；不增加模型或全文请求。
- 运行服务端回归、空库迁移与打包及文档检查；软件完成与运行部署、实体体验分别记录。

## 兼容与回退

Tool 只追加字段，旧 count 不改义；旧页面/API 不变。所有改动仅服务端，可通过上一应用版本回退，无数据库回退或固件刷写。本轮不自动执行生产部署、外部推送或实体操作。

## 验证结果

2026-09-13 原定向基线 25/25；新增条目截断、总量、空列表、夏令时、长 Unicode 简报和真实数据库作用域测试后，非 loopback 服务端回归 502/502 通过，隔离 PostgreSQL 成功应用 V1..V49，JAR 打包成功。完整 534 项首跑有 32 个错误：31 个来自仓库既有八类 Windows loopback 限制，一个为既有异步并发异常；异步类单独 11/11 和后续非 loopback 整体复跑通过。未更改测试断言来忽略业务失败，未声称受限的网络测试通过。运行部署、固件及真实音色/模型验证尚未执行。
