# 0014：自定义唤醒词采用离线生成并随固件打包的 WakeNet 模型

- 状态：SUPERSEDED
- 日期：2026-07-23
- 工作流：固件

## 背景

WakeNet 不能把设备端或管理页面输入的一段任意文本直接当作新唤醒词。每个自定义短语必须先由兼容当前 ESP-SR 版本和目标芯片的模型生成流程产出模型目录，再把该目录写入固件的 `model` 分区。把普通文本配置伪装成可用的动态唤醒词，会造成设备启动后仍监听旧短语或完全无法监听。

当前 `model` 分区为 1 MiB，内置 `wn9l_histackchan_tts3` 已经过 CoreS3 实体验证。外部模型属于本地构建输入，不应提交模型二进制，也不应在没有用户许可时把短语发送给外部生成服务。

## 决策

- 自定义唤醒词是固件构建时能力，不增加运行时文本输入接口或远程模型下载接口。
- 用户先确认准确短语；如需使用外部模型生成服务，还必须单独确认允许提交该短语。模型生成不携带设备身份、Wi-Fi、Token 或其他凭据。
- 生成的模型只放在被 Git 忽略的 `firmware/local-wake-models/`，通过 ESP-SR 的 `CONFIG_ESP_SR_EXTERNAL_MODEL_PATH` 打入 `model` 分区。
- `CONFIG_STACKCHAN_WAKE_WORD_MODEL` 只接受并精确选择已打包的小写 WakeNet 模型名。固件不做模糊匹配，也不把 MultiNet 或任意其他语音模型当作唤醒模型。
- `wn9l_histackchan_tts3` 始终随镜像保留为安全回退。首选模型缺失、接口不可用、创建失败，或不是 16 kHz 单声道时，固件显式回退并记录非秘密诊断；回退也失败时停止语音任务，不使用不确定模型。
- 打包前必须运行模型包校验：目录和文件名受限，不允许符号链接、空文件或覆盖默认模型；按 ESP-SR 实际格式计算镜像大小，并在 1 MiB 分区中至少保留 64 KiB 余量。
- 模型包校验、三种传输 profile 构建和真机 smoke test 均通过后，才可把自定义模型镜像用于设备。刷写仍需用户明确确认设备、串口、profile 和提交。

## 原因

离线生成和固件打包符合 WakeNet 的实际能力边界，也让模型版本、分区容量和回退行为在刷写前可验证。保留已验证模型可以避免外部模型损坏或版本不兼容时静默失去本地唤醒；不提交模型二进制和不自动上传短语则限制隐私与供应链风险。

## 影响

- 更换唤醒短语需要重新生成模型、构建并刷写包含 `model` 分区的完整固件，不能只保存后台配置。
- 管理后台暂不出现“自定义唤醒词”文本框；现有灵敏度和录音阈值配置保持不变。
- 自定义模型的授权、来源和兼容版本由操作者记录，但不得记录秘密或完整认证载荷。
- `motion_disabled`、LAN HTTP 开发边界和生产 HTTPS-only 边界均不改变。
