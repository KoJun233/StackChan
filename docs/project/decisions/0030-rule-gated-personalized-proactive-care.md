# 0030：个性化主动关心必须经过规则门控与主题冷却

- 状态：ACCEPTED
- 日期：2026-08-04
- 工作流：服务端、前端、固件、部署

## 背景

0021 已把主动问候的时机固定在设备级允许时段、免打扰、最小间隔、每日上限、在线状态和忙碌仲裁中，内容使用管理员配置的固定文本。INT-011 又增加了“允许主动提及”的确认记忆。INT-012 需要在不让模型决定打扰时机、不泄露未授权记忆、也不因模型失败丢失到期事件的前提下，为主动问候生成一句有限的个性化措辞。

## 决策

### 规则先于模型

- 0021 的全部确定性规则继续先执行；任何一项不满足时，不查询主动记忆、不调用模型、不增加每日计数，也不创建提醒。
- 只有设备已经满足规则并成功占用本次主动配额后，才可生成内容。模型不能改变设备、时机、音量、每日上限、提醒状态或交付命令。
- 个性化措辞单独开关且默认关闭。关闭、没有合格记忆、模型超时、供应商失败或输出违规时，使用管理员现有固定问候文本。

### 最小记忆输入与输出边界

- 模型最多读取一条当前设备可见、`CONFIRMED + enabled + allowProactiveMention`、未被替代且通过敏感过滤的记忆，只发送该记忆的标题和正文；不发送对话历史、音频、转写、完整模型回复、其他记忆、凭据或 Tool/MCP 数据。
- 输出必须是简体中文纯文本单句，长度 2..100，不含换行、Markdown、URL、医疗/情绪诊断、治疗建议或系统指令。违规结果稳定回退固定问候。
- 生成文本只作为既有提醒正文保存以供播放；主题状态和生成元数据不额外复制正文，只保存设备 ID、规范化 `topicKey`、生成状态与时间。安全日志只记录失败阶段，不保存生成文本、记忆正文或供应商响应。

### 七天冷却与用户静音

- 每次为某个记忆主题创建主动提醒后，该设备与 `topicKey` 进入七天冷却；冷却在模型调用前参与候选筛选。
- 用户在语音回合明确说“别再提这个”时，永久静音该设备最近一次主动主题，直到管理员在页面解除；不删除、不停用原记忆，也不影响普通对话检索。
- 管理页只展示主题键、最后主动时间、冷却截止时间和是否被用户静音，不复制记忆正文。

### 持久化与兼容

- V26 为交互设置增加默认关闭的个性化开关，为主动来源提醒增加可空主题键和 `FIXED / GENERATED / FALLBACK` 生成状态，并新增设备级主题冷却表。
- SCV1、WebSocket 命令、提醒音频 ACK、连续对话和固件均不改变。旧固件继续接收普通提醒播放命令。

## 发布与验证

1. 从空 PostgreSQL 验证 V1..V26，并覆盖规则短路、未授权记忆排除、七天冷却、永久静音、模型超时/违规回退和调度记录保留。
2. 先只发布 server/V26，再用现有 `dd81a7e` 验证固定问候、个性化问候、免打扰、忙碌/离线和触摸停止；不需要刷写固件。
3. 未经用户确认不得推送任务分支；未经新的精确授权不得连接 COM3、刷写或改写 NVS。
