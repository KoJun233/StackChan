# 0072：明确许可的对话待续话题

- 状态：ACCEPTED
- 日期：2026-10-05
- 工作流：服务端、前端
- 相关提交：`ec53bfe`（实现基准；最终工作树验证另记）
- 关联：[实施计划](../topic-continuity.md)、[使用与验收](../../runbooks/topic-continuity-20261005.md)

## 背景

用户认为现有功能齐全但陪伴感弱，选择成人桌面伙伴和跨天自然接续，明确要求先确认建议、日常/兴趣/项目场景、相关聊天中接续、设备每日一条新建议及可暂停/停止。

## 决策

待续许可附着在设备及伙伴范围的事件记忆上。旧数据迁移默认 NONE；异步完成回合提取只能创建 PENDING 候选，不发送主动消息。复用 CONFIRM_MEMORY 固定快照、两分钟 TTL 和伙伴同意周期，卡片和旧语音均展示待续与进展保存含义。

生成和提出确认各有设备当地日期的唯一预算，事务中锁设备并插入预算。拒绝后不再自动询问；预算不随删候选或进程重启消失。保留拒绝记录的查找不使用近期行数截断。

仅向当前用户发起的设备语音对话提供一个词面相关且已确认、启用的话题。当前表达优先，未知结果只能询问。短指代要求同会话、三十分钟内且没有跨明确换题边界。先不聊暂停至设备当地次日；停止需要显式恢复；十四天无用户进展休眠，用户提起可恢复。

进展复制来源用户消息原文，限制 240 字，排除提问、假设及敏感/情绪内容，不采用机器人回答作为事实。实际语音路径要求来源消息存在、归属当前会话及伙伴、回复完成；与个人数据删除共用会话锁。删除源对话的任一消息保守清除该对话复制的进展，原已确认事实和许可仍单独管理。

## 原因

复用已有确认记忆和设备卡片可以保持同意与角色边界一致；单条相关接续和明确反馈减少重复追问。采用保守词面选择，暂不加入全局向量记忆、定时关心或情绪推断。

## 影响

V57 增加元数据和无正文的日预算。设备 UI v1 字段和旧固件语音方式保持兼容，无固件改动。控制台原记忆页显示状态与进展。网页文字会话不获得设备工具权限，第一轮不加入文字端自动待续。

状态与软件测试不能证明长期陪伴感改善；需要十四天自然观察。生产部署和数据备份按现有工作流执行，本次未部署、未外推。

## 替代关系

无；补充 [0070](0070-hybrid-voice-and-confirmed-companion-care.md) 的明确记忆许可，不改变已有一次关心、主动消息或实体操作的许可。
