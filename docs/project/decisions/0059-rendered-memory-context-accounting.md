# 0059：仅追踪实际进入提示词的记忆

- 状态：ACCEPTED
- 日期：2026-09-13
- 工作流：服务端
- 关联：[功能评审 D02](../feature-review-2026-09-13.md)

## 问题

原提示词按 4,000 字符预算排除完整记忆行，却返回全部检索候选 ID，导致未提供给模型的记忆也被记录为使用。分类标签未完整计入预算，遇到首个超长候选时还会阻止后面的较短条目进入提示词。空上下文措辞也把本轮未提供记忆与数据库没有记忆混为一谈。

## 决策

- 渲染文本和实际包含的 ID 同步产出，使用记录仅接收实际渲染 ID。该记录表示提供给模型，不证明模型在回答中引用了该条目。
- 4,000 Java 字符预算包含分类开闭标签和转义后的整行文本；不截断记忆事实，跳过放不下的条目并尝试后续条目，不产生空分类。
- 明确提示本轮内容只是部分记忆。没有可引用条目时不声称数据库没有记录。
- 每个角色独立记忆、设备范围、确认/禁用/替代状态以及原检索排序保持当前职责。此改动不解决同义召回及无关候选问题，后续必须用真实 PostgreSQL 正负例单独验证检索策略。

## 验收

覆盖超长首条、后续可容纳条目、跨分类总预算、完整开闭标签、空候选与全部超限候选；断言记录 ID 与实际文本一一对应。回归完成轮次记忆协调和语音路径。
