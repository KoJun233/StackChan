# 0011：语音协议只由显式接入方式决定

- 状态：ACCEPTED
- 日期：2026-07-21
- 工作流：服务端、前端
- 相关提交：`e41a40f`

## 背景

语音模型名称会随供应商和版本变化，不能再根据 `fun-asr-*`、`qwen-*` 或其他命名规则推断应该使用 WebSocket 还是 HTTP。此前把非实时 ASR 模型送入实时 WebSocket 会超时，也无法让管理员独立选择 ASR 与 TTS 的接入方式。

## 决策

语音配置为 ASR 和 TTS 分别保存 `REALTIME` 或 `NON_REALTIME`，并保存自由填写的模型名。接入方式是唯一协议路由信号：

- `REALTIME` 只走 WebSocket。
- `NON_REALTIME` 只走 HTTP。
- 模型名按管理员输入原样传给当前提供方，不参与协议判断。
- 调用失败时不自动切换协议、不重试另一条实现，也不根据模型名做兼容回退。

百炼适配器实现实时/非实时 ASR 和实时/非实时 TTS 四条独立路径。OpenAI-compatible 适配器当前只实现非实时 HTTP；如果选择实时模式，调用直接失败，不降级为 HTTP。

## 原因

显式模式让配置行为可预测，也允许以后增加新供应商和新模型名，而无需修改模型名称白名单或推断规则。严格单路调用还能避免一次语音请求同时消耗两个协议端点或产生难以判断的回退结果。

## 影响

- 数据库增加 `asr_mode` 和 `tts_mode`。迁移按旧实现的真实行为把既有 ASR 标记为 `REALTIME`、既有 TTS 标记为 `NON_REALTIME`，不检查已有模型名。
- 管理页只提供模式下拉和自由模型名输入，不提供会改写模型名的推荐模型联动。
- 连接测试与设备语音回合都使用同一组已保存模式。
- 新供应商必须在自己的适配器中明确实现对应模式；未实现的模式必须失败，不能借用另一模式。

## 来源

- 用户明确要求模式与模型名解耦，并要求实时只走 WebSocket、非实时只走 HTTP、失败不兼容回退。
