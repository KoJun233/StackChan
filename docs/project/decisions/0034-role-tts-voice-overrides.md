# 0034：角色 TTS 音色覆盖与安全回退

- 状态：ACCEPTED
- 日期：2026-08-13
- 工作流：服务端、前端
- 相关提交：当前任务提交

## 背景

角色容器已经隔离人设与陪伴数据，但所有角色仍使用同一个全局 TTS 音色。用户需要让不同角色呈现不同声音，同时继续共享语音供应商、模型、访问模式与密钥，并保持现有固件播放协议不变。

## 决策

- 每个角色增加一个可选的 TTS 音色覆盖值；空值表示继承全局音色。
- 设备语音回复使用当前会话角色的音色，提醒与外部通知使用提醒记录绑定角色的音色。
- 角色音色调用失败时，仅使用同一套全局语音配置和全局音色重试一次；全局调用失败则保持现有安全错误语义。
- 全局语音连接测试继续只验证全局音色，避免角色配置影响基础供应商诊断。
- 不记录角色音色值、语音正文、音频或完整供应商响应。

## 原因

角色级覆盖提供了明确的体验差异，又不会复制供应商凭据或扩大角色隔离边界。服务端在生成音频前解析角色，因此无需修改设备命令和固件。一次全局回退可避免无效或暂不可用的角色音色阻断提醒与对话，同时避免无界重试。

## 影响

- Flyway V30 为 `companion_roles` 增加可空音色字段。
- 角色 API 与 Fantastic-admin 角色表单公开该非秘密配置，并在列表中标识继承关系。
- 角色归档、恢复、切换和旧客户端默认角色兼容行为不变。
- 后续如需角色表情，仍必须等待固件支持多资源包常驻，不复用本决策扩展固件协议。
