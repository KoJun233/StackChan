# 0038：分层动态球形表情与兼容资源包

- 状态：ACCEPTED
- 日期：2026-08-20
- 修订：2026-08-23，`MEDIA-002D` 完整迁移到官方 CoreS3 BSP + LVGL 9.4，并完成真机性能与音量调校
- 工作流：前端、服务端、固件
- 关联：[0022：版本化表情资源包](0022-versioned-expression-resource-packs.md)、[0033：角色容器](0033-companion-role-containers.md)、[表情渲染调研](../expression-rendering-landscape.md)

## 背景

现有固件把八个交互状态直接渲染为内置机械眼或八张全屏 PNG。内置动画每 100 ms 更新一次，没有从当前姿态到目标姿态的插值；自定义 PNG 启用后则完全停止周期动画，只在状态变化时硬切图片。继续增加全屏状态图只能扩大制品，不能解决低帧率、眨眼跳帧和缺少生命感的问题。

StackChan 使用 320×240、RGB565 的 ILI9342C 屏幕。面板可以按 60 Hz 级别扫描，但 60 张完整画面需要约 73.7 Mbit/s，不能把面板刷新率直接解释为全屏动画帧率。动态渲染若以 60 FPS 为目标，必须缩小更新区域、记录真实耗时并在音频繁忙时有界降帧。首轮 M5Unified/M5GFX 原型还暴露了显示、触摸、麦克风和扬声器共用板级抽象与后台任务时难以解释的资源竞争，因此本记录在 `MEDIA-002D` 修订显示与硬件边界。

产品确认采用类似 Emotion Ball 的抽象球形视觉方向，但不复制其受非商业许可证约束的源码、轮廓点、配置、配色或粒子参数。现有 PNG 资源包继续作为可选兼容模式。

## 决策

### 渲染器与兼容性

1. 保留 ADR 0022 的 v1 八状态 PNG 制品、同源认证下载、摘要校验、A/B 安装和内置机械眼回退；不重新编号或强制迁移旧资源包。
2. 固件原生动态球形渲染器作为默认表情模式。球体目标区域为 160×160，不绘制嘴巴，通过眼睛轮廓、球体形变、颜色和有界粒子表达情绪。
3. PNG 模式继续静态兼容。管理页必须明确提示它不具备原生球体的连续变形；首版只允许安全的切换提示，不把旧资源包伪装成动态主题。
4. 每个角色只配置一个主色，并仅用于轨道、粒子等点缀；默认球体保持奶油色，避免主题色淹没眼型辨识度。害羞/喜爱使用柔和粉色，错误/愤怒固定珊瑚红，离线固定灰色，更新固定蓝紫色，角色不能覆盖这些语义颜色。

### 状态分层与权限

渲染优先级固定为：

```text
错误 / 离线 / 更新
    > 物理短时反应
    > 倾听 / 思考 / 说话
    > 角色情绪
    > 待机微动画
```

- 十二种角色情绪为：中性、开心、喜爱、难过、生气、惊讶、困惑、害羞、疲倦、专注、紧张、满足。
- 九种系统或交互表现为：待机、倾听、思考、说话、完成、没听清、错误、离线、更新中。其中“没听清”是语音失败反馈，不改变 v1 静态资源包仍为八张图的兼容格式。
- 六种生命周期与物理行为为：开机出现、苏醒、待机呼吸、靠近好奇、摇晃眩晕、困倦睡眠。
- 模型每回合只能建议预定义的情绪和弱/中/强三级强度。服务端验证枚举，无效值回退中性；模型不能提供系统状态、颜色、轮廓、动画参数或渲染优先级。
- 普通情绪保持 5–15 秒后回归中性。高优先级覆盖结束时，只有尚未过期的底层情绪可以恢复。
- 头顶触摸触发短时开心或喜爱，接近触发好奇，摇晃触发眩晕；这些反应持续 1.5–3 秒，不能覆盖错误、离线或更新。

### 动画与性能

1. 固件使用乐鑫组件注册表中的官方 `espressif/m5stack_core_s3` BSP 4.0.0、`esp_lvgl_port` 与 LVGL 9.4；从应用依赖和硬件实现中移除 M5Unified/M5GFX。显示、触摸、AW88298 扬声器、ES7210 麦克风和 BMI270 均通过官方 BSP 边界访问。
2. 动画计算目标为 60 Hz。动态球体由 LVGL 对象树表达，使用 24 行双 DMA 缓冲和对象失效区域刷新；页面切换和 320×240 静态 PNG 才允许整屏刷新。占据主要无效区域的四层球体椭圆最多以 30 Hz 更新，眼睛、轨道和前景效果仍可按目标帧率更新。
3. 系统状态使用 120–220 ms 无回弹过渡；普通情绪使用 250–450 ms 轻微弹簧过渡；开心和惊讶最长 600 ms；回归中性使用 600–1000 ms。
4. 粒子只用于喜爱、完成、更新和眩晕等少数强调状态，同时最多八个，使用固定数组，不在逐帧路径申请内存。开心和惊讶主要依靠独立眼型与球体姿态表达，避免所有状态都堆叠装饰。
5. 渲染器根据帧耗时、显示锁等待、丢帧和音频 underrun 在管理员设置的 1–60 FPS 范围内以五帧为步长调节，并保留精确端点。LVGL 与 UI 固定在 Core 1；WakeNet、录音和播放继续优先于动画。自适应模式在音频繁忙时只允许降到管理员设置的最小值，固定模式保持配置目标并明确上报 `AUDIO_BUSY`，结束后按稳定窗口恢复。
6. 固件和管理页暴露目标/实际 FPS、场景更新与 LVGL 刷新耗时、丢帧、降帧原因、活动状态层、可用堆最低水位和音频 underrun 计数；总帧成本按两段耗时之和评估，不记录对话正文、音频或秘密。
7. 管理员可以用步长为 1 的滑块选择固定 `1–60` FPS，或组成自适应最小/最大范围。固定模式锁定正常目标，不因绘制预算自动改写配置；音频并发降载明确上报 `AUDIO_BUSY`。管理页始终同时展示目标和实际帧率，屏保固定 20 FPS。策略保存在服务端并在设备重连后同步。
8. 管理页语义按钮只发送枚举化、1–15 秒的临时预览。预览不能伪造真实连接、错误、更新或会话状态，也不能覆盖正在进行的真实交互；静态 PNG 模式拒绝预览。

### 分阶段交付

1. `MEDIA-002A`：重构现有 v1 管理体验，分离资源包创建与设备启用，支持按中英文标准文件名批量导入、8/8 完成度、逐项预览和状态说明；同时固化调研与本 ADR，不修改固件协议。
2. `MEDIA-002B`：实现独立动画时钟、160×160 局部刷新、60/30/20 自适应、诊断指标，以及中性、开心、生气、惊讶、倾听、思考、说话、错误八种真机原型。
3. `MEDIA-002C`：补齐全部状态、结构化情绪协议、角色主题色和触摸/接近/摇晃触发。首版页面只能选择内置动态主题和角色主色，不开放任意轮廓或动画 JSON。

原计划每阶段使用独立任务分支；用户在 `MEDIA-002A` 审核后明确要求 A/B/C 合并到当前任务分支，因此本次作为一个跨三端任务提交交付。固件仍先完成自动化与制品校验，再经逐次授权提供应用 OTA；保留 NVS，不把设计确认视为刷写或部署授权。

CoreS3 当前没有独立接近传感器，因此固件保留“靠近好奇”的受限语义与优先级，但能力心跳明确上报 `proximity_supported=false`，不会伪造接近事件。IMU 摇晃和触摸反应可直接启用。

## 原因

- 状态分层允许机器人同时表达“正在说话”和“开心”，又不让模型伪造离线、错误或更新。
- 参数化局部动画比增加全屏 PNG 更节省带宽与闪存，并能用同一组基础姿态组合出更丰富的可见行为。
- 60 Hz 动画时钟加自适应呈现保留流畅度上限，同时以音频稳定和可观测降帧约束资源竞争。
- 保留 v1 资源包避免破坏现有数据库、分区、设备和用户素材；动态主题可以逐步取代默认机械眼而不阻塞旧模式。
- 分阶段真机验收可以先证明帧预算与过渡，再扩展状态、传感器和角色协议，降低一次性跨三端修改的风险。

## 影响

- `MEDIA-002A` 只改变管理页面和文档，资源包 API、设备命令、固件分区和运行设备保持不变。
- `MEDIA-002B` 需要重构当前 10 FPS 全屏绘制循环，把状态更新改成提交目标姿态，由统一 UI 时钟插值和局部呈现。
- `MEDIA-002C` 需要增加向后兼容的情绪字段与能力协商；旧 `HAPPY`、`SAD` 值继续兼容映射，不能复用为新字段编号。
- 动态主题编辑器、任意远程动画 JSON、GIF/图片序列和多自定义外观常驻不在首版范围；它们必须在真机性能与格式安全验证后另立任务。
- `MEDIA-002D` 以 LVGL 9.4 对象树替代 160×160 M5GFX 软件画布和逐帧扫描线光栅化。圆角对象、变换、局部失效与 BSP DMA flush 负责球体、胶囊眼、腮红、轨道和粒子；RGB565 色深及 160×160 动态区域保持不变。
- 设备硬件访问统一收敛到官方 CoreS3 BSP：显示/触摸使用 `esp_lcd` + `esp_lvgl_port`，音频使用 `esp_codec_dev`，IMU 使用 `sensor_hub`/BMI270。原有应用 OTA、NVS、协议、语音状态机与 PNG A/B 资源格式不改变。
- 诊断耗时继续使用 32 位微秒值。固定 60 FPS 是调度目标而非硬件承诺；是否达到目标以实机的实际 FPS、传输耗时、音频 underrun、WakeNet 成功率和稳定性共同判断。
- CoreS3 官方 BSP 的音量接口仍使用 `0..100` 用户刻度，不能把接口刻度直接当作 dB。为了保持迁移前 M5Unified 的听感，固件将旧平方 PCM 音量等效为 dB 曲线，并纳入官方 BSP 声明的约 `+11.39 dB` 固定模拟链路增益；`0` 保持静音，`100` 对应旧实现满量程而不是“0% 对应 0 dB”。
- `41b8827-perf9` 真机在固定 60 FPS 待机场景达到约 55 FPS：场景更新约 1.0 ms、LVGL 刷新约 11.1 ms、显示锁等待约 0.46 ms、音频 underrun 为 0。40 MHz SPI 下 160×160 RGB565 单次传输理论下限约 10.24 ms，因此当前结果作为稳定边界接受，不再通过未验证的 SPI 超频或扩大 DMA 缓冲追逐名义 60 FPS。
- 首个固件原型要求待机十分钟大部分时间不低于 55 FPS，或给出明确自动降帧原因；TTS 期间不得新增音频 underrun，连续三十分钟不得重启或持续泄漏堆内存。
- `esp_lv_eaf_player`、`esp_emote_gfx` 和 EAF/Emote 二进制包仍是后继资源格式候选，但 LVGL 显示栈迁移已在本次完成。后续采用 EAF 不再需要更换显示驱动，只需比较资源容量、解码、取消、WakeNet 与 TTS 并发，并复用现有 A/B 安装、摘要校验和内置错误回退。

## 许可边界

Emotion Ball、小智、M5Stack Avatar、LVGL Kawaii Face、RoboEyes 和商业产品只作为可观察的产品或架构参考。仓库不复制第三方实现、轮廓数据、配置或素材；任何后续直接复用都必须先确认与项目分发方式兼容的明确许可证。

## 替代关系

不替代 ADR 0022；它继续定义 v1 静态资源包的安全兼容基线。本记录替代 `MEDIA-002` 早期以“多资源目录常驻”为首要前置的草案，先交付原生动态渲染，再决定是否仍需多自定义外观常驻。
