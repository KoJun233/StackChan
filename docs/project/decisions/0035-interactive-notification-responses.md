# 0035：互动通知采用显式动作白名单、轮询回执和确认式语音执行

- 状态：ACCEPTED
- 日期：2026-08-13
- 工作流：服务端、前端、部署
- 关联：[0032：外部通知平台](0032-external-notification-platform.md)、[0028：确认且幂等的语音动作](0028-confirmed-idempotent-voice-actions.md)

## 背景

外部 Agent 在完成任务或请求人工处理后，不仅需要确认通知已经播放，还需要知道用户是否已知晓、要求稍后再次播报或确认事项完成。现有设备 ACK 只描述音频播放结果，不能代表用户业务回执。

## 决策

1. 外部通知默认仍为单向播报。调用方必须在创建时显式声明 `ACKNOWLEDGE`、`SNOOZE`、`COMPLETE` 中允许的动作；模型、设备和管理员不能扩大该白名单。
2. 回执单独持久化并固定绑定通知及其集成。外部令牌只能通过既有状态查询或 MCP `get_notification_status` 轮询本集成结果，不增加任意回调 URL。
3. “稍后提醒”需要 1–1440 分钟，重新进入同一可靠通知队列，并把过期时间延长到新播报时间后 24 小时；其他终态回执幂等返回首个结果。
4. 语音只匹配同设备、同角色最近 24 小时内已送达且仍可回应的通知。回应仍先创建两分钟有效、同设备/同会话的结构化提案，确认后执行。
5. MCP 仍只暴露 `push_notification` 和 `get_notification_status`。前者增加可选动作参数，后者增加动作白名单和最新回执；旧请求不传新字段时行为与响应兼容。
6. 管理页面可创建互动测试通知、查看最新回执并手动记录回执，用于无实体语音时验收；不展示令牌、认证载荷或回执原句。

## 影响

- Flyway V31 增加回执白名单、回执事件和通知语音动作类型。
- 本任务只替换服务端与控制台，不修改固件或设备命令。
- “已知晓”“已完成”等普通对话只有在可信范围存在匹配的互动通知时才会进入提案，避免误触发。
- 摘要聚合不与回执事务耦合，保留为 `EVT-003` 独立设计；在此之前继续逐条确定性原文播报，避免模糊单条通知的 ACK、重试、过期和回执归属。

## 替代关系

无。本决策扩展 ADR 0032，不改变其独立令牌、确定性正文、免打扰、离线可靠性和 HTTPS 边界。
