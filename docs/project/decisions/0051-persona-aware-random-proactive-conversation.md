# 0051：主动闲聊采用持久随机时刻、当前人设和已确认兴趣

- 状态：ACCEPTED
- 日期：2026-09-10
- 工作流：服务端、前端、部署
- 关联：[0021：提醒与有限主动交互采用确定性规则和设备级控制](0021-limited-proactive-interaction.md)、[0029：长期记忆建议经过敏感过滤、冲突确认与有界检索](0029-reviewed-memory-suggestions-and-bounded-retrieval.md)、[0030：个性化主动关心只在确定性规则通过后生成](0030-rule-gated-personalized-proactive-care.md)

## 背景

既有主动问候已经具备显式开关、允许时段、最小间隔、每日上限、免打扰、忙碌仲裁、确认记忆和主题冷却，但调度器会在规则首次满足时立即触发，实际并非时段内随机。个性化生成只读取一条记忆，没有读取当前活动角色的人设；没有可用记忆时直接播放固定备用文案。用户需要的是有分寸的桌面伙伴：在指定时段内随机出现，每天最多三次、两次至少间隔一小时，并按当前角色和已确认兴趣自然开场。

当前文本模型使用 DeepSeek 官方接口，没有能返回可核验来源的联网搜索能力。模型知识不能作为“最近发布”“今天发生”等实时资讯来源。

## 决策

### 持久随机调度

- 主动闲聊继续默认关闭，只有管理员显式开启后才生成下一次随机候选时刻。
- 候选时刻均匀落在设备时区的剩余允许窗口内，并保存到 PostgreSQL。服务重启、调度器重复扫描或页面刷新不得重新抽取。
- 每次成功占用主动名额后，下一次候选必须晚于最小间隔；当天达到上限后从下一本地日期的允许窗口抽取。配置约束固定为每天一至三次、最小间隔六十至一千四百四十分钟。
- 到达候选时刻后仍执行在线、免打扰、活动语音和待播放提醒仲裁；忙碌或离线只顺延，不抢占当前交互。

### 当前人设与兴趣

- 规则全部通过后，措辞生成读取当前活动角色的名称、语气、回复长度、主动程度、背景、话题边界和禁忌。
- 自动记忆建议只有在用户明确表达兴趣、爱好或内容偏好时，才预置“允许主动提及”；建议仍为待确认且停用。用户确认该兴趣后，同一稳定主题及相邻话题可以直接用于主动开场，无需为每个细分兴趣再次确认。
- 每次最多读取一条当前角色范围内、已确认、启用且允许主动提及的记忆，并继续执行七天主题冷却和用户停用。
- 没有合格兴趣时只按当前人设生成普通问候；模型失败或输出不合规时使用管理员保存的备用问候。

### 事实边界

- 未提供外部来源时，提示词禁止生成实时资讯，应用输出策略同时拒绝“最近发布、最新模型、今天更新”等时效性断言。
- 未来资讯型开场必须接入能返回标题、来源、发布时间和稳定链接的数据源，并保存最小来源证据后才能启用；不得仅凭模型声称已经联网。
- 摄像头、麦克风常开、身体动作和固件均不属于本任务。主动播放继续复用现有可靠提醒、TTS、设备 ACK 和停止路径。

## 发布与兼容

- Flyway V47 为设备交互设置增加可空的下一次主动时刻，并把历史配置收敛到最小一小时间隔、每日最多三次；主动开关和既有计数保持不变。
- 管理页面展示下一次随机候选，并明确备用问候、规则上限和无来源资讯边界。
- 本任务只需发布 server 与内置管理页面，不修改或刷写 CoreS3。
