# ADR 0067：伙伴播报视图与统一近期来源

- 状态：ACCEPTED
- 日期：2026-09-14

## 背景

今日概览此前没有明确设备/角色选择，提醒按管理列表的降序展示，列表长度被当作数量。主动话题静默与追问仍单独寻找最近主动消息，可能跨过后播出的普通提醒。评审 M04/M05/M07 要求清楚知道谁在提醒什么。

## 决策

新增只读管理员接口 `/api/v1/reminders/timeline`，强制提供 deviceId 与 roleId；不建立另一套队列。单次可重复读事务查询待处理和已下发消息，按排期升序取十条及真实总数；最近三十分钟成功播报取十条与截断标志，保留来源、状态和原时区。周期提醒可以同时有上次播放和下次排期。

今日概览首次读取设备当前伙伴，后续选择只改变查看范围，不切换设备角色。待办读取选定伙伴所有设备的真实总数，列表保持五条并明确范围。播报视图分别说明个人提醒（含待办截止）、外部通知、工作简报、工作休息和主动陪伴；不把播放完成解释为业务完成。旧链接/API 保留，正文不写浏览器持久化。

页面切换或刷新时清空旧内容，序号校验阻止迟到响应覆盖新伙伴；读取失败区别于空列表。主动上下文与长期话题静默也先查看最近所有来源的成功播报，遇到更新的其他来源或同时间歧义不回退旧主动话题。

普通提醒语音“推迟”以原排期与当前时间的较晚者为起点，不将未来提醒提前。确认仍固定 ID、内容、排期与归属，保留管理员显式操作原语义。

## 验证

服务端定向 14/14 通过，覆盖权限/缺少范围、超过十条真实总量、顺序/来源/时间/角色隔离、旧主动上下文隔离、确认目标变化及未来提醒推迟。前端 33 文件 106/106 通过，新增 API 范围测试和迟到响应/刷新失败组件测试；类型、改动文件 ESLint/Stylelint 通过。最终构建与全回归结果以工作流状态为准。

仍需真机与页面人工验收，不能由此声称口语统一回应全部完成：普通提醒与工作休息的简短回应路由、外部通知提案的具体对象名称仍按实施清单继续处理。
