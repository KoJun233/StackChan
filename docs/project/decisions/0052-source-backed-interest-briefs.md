# 0052：兴趣资讯使用后台缓存、受限选择和可追溯来源

- 状态：ACCEPTED
- 日期：2026-09-10
- 工作流：服务端、前端、部署
- 关联：[0030：个性化主动关心只在确定性规则通过后生成](0030-rule-gated-personalized-proactive-care.md)、[0051：主动闲聊采用持久随机时刻、当前人设和已确认兴趣](0051-persona-aware-random-proactive-conversation.md)

## 背景

COMPANION-001 能按当前人设和已确认兴趣自然开场，但当前 DeepSeek 文本接口没有可核验的联网搜索能力。让模型凭训练知识声称“最近发布了某项技术”会产生时效错误，也无法让管理员追查来源。主动问候的实时路径还必须保持轻量，不能在机器人准备开口时等待外部资讯站点。

## 决策

### 来源和刷新

- 第一版只读取 Hacker News 官方只读 API 的 `beststories` 与 `item` 数据；不需要账号或密钥，也不向该来源发送设备、角色、记忆或兴趣。
- 服务端启动后异步刷新，之后每三十分钟刷新；候选缓存最多使用两小时。外部请求失败、超时或没有合格候选时保留短时旧缓存，缓存过期后退回普通人设问候。
- 只接受四天内、类型为 `story`、未删除、未标死且使用公开 HTTPS 链接的项目。标题去除控制字符并限制长度，拒绝明显的提示注入文本。

### 选择和措辞

- 只有主动个性化已显式开启，并选出一条已确认、启用且允许主动提及的兴趣记忆后，才把最多六个候选标题交给当前配置的文本模型做相关性选择。
- 候选标题视为不可信数据。模型只能返回候选编号和一小段人设化开场，不能改写标题、补充事实或决定触发时机；编号、长度和输出格式由应用再次校验。
- 最终播报由程序把开场、固定来源名和选中标题确定性拼接；播报最多引用标题前六十个码点，提醒记录保留完整标题。模型没有选择合适标题、返回未知编号或调用失败时，使用普通人设问候或管理员备用文案。
- 同一设备已经使用过的来源链接不再进入候选，既有七天兴趣主题冷却、随机时刻、每日上限、最小间隔、免打扰和忙碌仲裁继续生效。

### 证据和管理页面

- Flyway V48 在主动提醒上保存来源名、原始标题、原始链接、Hacker News 条目收录时间和抓取时间；这些字段只由服务端从已验证候选写入。
- 提醒 API 返回来源证据，管理端在提醒列表展示可点击的 HTTPS 原始链接和来源收录时间。用户把提醒编辑成普通提醒时清除全部主动来源字段。
- 本任务不修改固件、摄像头、麦克风常开、身体动作、TTS 或设备协议。

## 替代关系

本文实现 ADR 0051 预留的“保存最小来源证据后再开放资讯型开场”。ADR 0030 与 0051 的确认记忆、规则先行、默认关闭和可靠投递边界继续有效。
