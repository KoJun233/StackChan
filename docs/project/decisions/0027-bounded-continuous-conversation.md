# 0027：连续对话采用设备本地有界跟进窗口

- 状态：ACCEPTED
- 日期：2026-07-30
- 工作流：服务端、前端、固件、部署

## 背景

当前每次语音回复播放完成后，CoreS3 会恢复 WakeNet；用户要继续说话时必须再次说唤醒词。INT-009 需要在回答后提供短暂的免唤醒跟进窗口，同时继续遵守本地唤醒、只在本地 VAD 检测到有效语音后上传、触摸取消、隐私安全诊断和 `motion_disabled` 边界。

## 决策

### 配置与兼容

- 每台设备保存 `continuous_conversation_enabled` 和 `follow_up_window_seconds`；默认关闭、默认窗口 8 秒，窗口只允许 3 至 8 秒，以继续满足现有 8 秒/512 KiB 语音正文上限。
- `configure_interaction` 在功能启用时增加 `continuous_conversation_enabled=true` 与 `follow_up_window_seconds`。功能关闭时服务端继续发送既有四字段命令，使当前 `b05d60f` 等旧固件仍能应用音量和夜间模式。
- 新固件同时接受严格的四字段和六字段命令；四字段命令明确恢复为“连续对话关闭、窗口 8 秒”。旧固件收到默认关闭配置时行为不变。

### 本地会话状态机

- 首轮仍只由本地 WakeNet 或在线长按说话触发。回复播放完成且功能启用后，设备恢复麦克风并进入 `listening` 表情的跟进窗口，不要求第九种表情资源。
- 跟进窗口继续使用既有能量阈值执行本地 VAD；没有有效语音时不构造 WAV、不调用语音 HTTP 接口，并在窗口结束后恢复 WakeNet。
- 每次有效跟进使用新的 `turn_id` 和原有 SCV1 请求/响应；同一设备的持久会话历史负责连续语境，不新增音频格式或对话正文诊断字段。
- 一次连续会话最多完成 3 个跟进回合，且从首次唤醒或长按开始最多 2 分钟。到达任一上限、触摸取消、明确说“结束聊天”、离线或任一回合失败都会结束本地会话并恢复 WakeNet。
- “结束聊天”只按规范化后的完整识别结果匹配，不对普通句子做模糊关键词触发；命中后设备丢弃尚未播放的回复音频并立即结束跟进。

### 诊断与隐私

- 设备阶段增加 `FOLLOW_UP_LISTENING`、`FOLLOW_UP_TIMEOUT` 和 `CONVERSATION_ENDED`。字段仍只有 `turn_id`、连接内 `sequence`、白名单阶段、0..300000 毫秒相对耗时和失败事件的安全失败码。
- 跟进超时和会话结束是正常完成语义，不使用 `FAILED` 或自由文本；每个跟进窗口使用独立 `turn_id`，保持现有 `(turn_id, source, stage)` 幂等约束。
- 不保存或上报常开麦克风、触摸坐标、音频、转写、回复、结束短语正文、URL、凭据或供应商载荷。诊断仍按七天清理。

## 发布与兼容顺序

1. 先发布 V23、管理 API/页面以及接受新阶段的服务端；默认关闭时继续向旧固件发送四字段配置。
2. 确认旧固件语音、提醒、音量/夜间模式和心跳无回退后，再构建新固件。
3. 只有用户逐次确认 CoreS3、串口、LAN HTTP Quad profile 和精确提交后才允许刷写。
4. 新固件连接旧服务端时只收到四字段配置，因此连续对话保持关闭，原有单回合行为不变。

## 安全边界

- 本功能不改变 SCV1、设备身份、固定同源下载、触摸取消或生产 HTTPS-only 边界。
- 本地 VAD 之前不上传麦克风数据；跟进窗口有时间和回合双重上限，禁止演变为持续云端监听。
- 不初始化或启用舵机、摄像头、LED、NFC 或其他执行器；`motion_disabled` 保持不变。
