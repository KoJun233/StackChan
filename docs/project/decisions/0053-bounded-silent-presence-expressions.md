# 0053：无声陪伴使用独立开关、持久随机计划和既有动态表情

- 状态：ACCEPTED
- 日期：2026-09-11
- 工作流：服务端、前端、部署
- 关联：[0038：动态球形表情分层渲染](0038-layered-expression-rendering-and-resident-appearance-catalog.md)、[0051：主动闲聊采用持久随机时刻](0051-persona-aware-random-proactive-conversation.md)

## 背景

用户大部分时间坐在电脑前游戏或工作，不会持续关注机器人。日常陪伴应以短暂无声表情为主，只有提醒或明确启用的主动问候才开口。现有动态表情已经能由服务端下发，但没有独立的低打扰计划；把表情绑定到语音主动问候会让用户无法分别控制两种打扰强度。

## 决策

- 增加默认关闭的“无声陪伴表情”开关，与语音主动问候开关和每天三次额度完全独立。
- 无声表情复用现有设备时区与主动陪伴允许时段。开启或成功显示后持久化下一候选；候选距离当前或上次成功显示 30–90 分钟，每个本地日期最多八次。
- 到点后仍检查免打扰、设备在线、最近活动语音和正在播放的提醒。条件不满足时不占次数，等条件恢复后再尝试。
- 表情只使用当前活动角色主题和固件已有的 `CONTENT`、`HAPPY`、`FOCUSED`、`TIRED`，强度为弱或中等，持续 6–8 秒。晚间使用困倦表情，其余按当日计数轮换。
- 调度和表情选择都由程序完成，不调用 LLM，不创建提醒，不合成音频，不读取摄像头、麦克风或电脑活动，也不执行身体动作。
- Flyway V49 只保存开关、下一候选、上次成功时间和本地日期计数；管理页展示开关与下一候选时间。

## 兼容和失败处理

- 旧设置请求缺少新字段时按关闭处理；旧设备或不支持动态表情的设备不会成功计数。
- 固件协议不增加新命令，继续使用已经发布并验证的动态表情配置命令；本任务不刷写固件。
- 服务重启从数据库恢复候选，不会因每分钟扫描而重新抽取。关闭功能会清除下一候选，不删除历史计数。
