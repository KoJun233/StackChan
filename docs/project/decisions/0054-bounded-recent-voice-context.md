# 0054：语音话题承接只使用有界的完整近期轮次

- 状态：ACCEPTED
- 日期：2026-09-11
- 工作流：服务端、部署
- 关联：[0027：有界连续对话](0027-bounded-continuous-conversation.md)、[0029：确认式长期记忆](0029-reviewed-memory-suggestions-and-bounded-retrieval.md)、[0050：自然低延迟短语音](0050-low-latency-natural-voice-conversation.md)

## 背景

设备与当前角色已经复用一个持久语音会话，低延迟回复也会收到历史消息，因此短句承接并不缺少存储或传递链路。但既有实现把永久会话中最近二十条完成消息视为同等上下文，几小时前或更早的话题也可能被模型理解成“刚才”；失败回复遗留的孤立用户消息也可能进入历史。用户希望机器人能接住吐槽、分享输赢和延续刚才的话题，同时不能补造本次游戏结果或人物事件。

## 决策

- 语音模型只接收最近三十分钟内完成的至多四个完整用户/助手轮次；网页聊天的历史策略不变。
- 只有配对完成的用户和助手消息可以进入语音近期上下文。陈旧轮次、失败或中断回复、孤立助手消息和没有完成回答的用户消息全部排除。
- 低延迟直接模型与受控 Agent 共用同一筛选结果，不增加额外模型调用、摘要调用或数据库迁移。
- 语音提示明确把“刚才”“还是”“又”“然后”“那个”等省略表达关联到最近一轮。上下文足够时直接自然承接，不复述历史；无法确定对象时只问一句简短澄清。
- 已确认长期记忆继续用于稳定人设和兴趣，但不得据此补造本次游戏、输赢、人物或事件。

## 原因

三十分钟足以覆盖一次游戏、工作插曲或刚结束的简短交流，同时避免持久会话把过时内容伪装成当前话题。保留四个完整轮次可以覆盖短交流中的必要指代，又能减少低延迟路径的输入量。确定性筛选比再次调用模型生成摘要更快，也不会引入新的事实来源。

## 影响

- 语音跨唤醒承接仍然可用，但超过三十分钟后需要用户重新点明对象。
- 长期兴趣和人设不会因近期窗口清空而丢失；它们继续受确认、角色隔离和有界检索约束。
- 本任务不修改数据库、API、控制台、语音供应商、固件、摄像头、麦克风常开或身体动作。

## 替代关系

本记录细化 ADR 0027 与 ADR 0050 的语音上下文边界，不替代既有记录。

## 后续优化：数据库有界读取

回复前的历史读取改由数据库过滤当前会话、完成状态和用户/助手角色，再按 created_at、id 倒序最多返回二十条，服务层反转为原来的时间顺序。沿用已有 conversation_messages_order_idx 索引，不增加迁移；管理页面查看、导出和删除仍使用既有完整记录接口。

该优化限制传入 Java 的历史正文数量；不承诺数据库只扫描二十行，也不把查询改进等同于已经实测的端到端语音提速。真实 PostgreSQL 用例覆盖同时间戳排序、过滤后限量、会话隔离、回复关联、空会话和不存在会话。
