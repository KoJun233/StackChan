## 浏览器证据和当前连接状态

专用 Browser 插件一直缺少 26.915.31945/scripts/browser-service.mjs。Computer Use 曾成功查看、导航和点击 Chrome，获得以下真实画面证据；之后窗口会话重置，重新打开 Chrome 时工具因不能可靠确认新标签页 URL 停止操作。没有绕过该校验。

1. 独立合成预览的首页最初显示在线机器人但伙伴“未获取”。原因是 FaSelect 的 change 同样由程序赋值触发；改用 update:model-value 响应用户选择后，刷新显示正确默认伙伴、设备实际伙伴及可用聊天按钮。
2. 桌面点击首页聊天入口，伙伴 ID 保留在 URL，聊天选择器和标题一致，输入框及发送按钮可见。
3. Chrome 响应式 400×435 初验发送按钮被裁切。取消页头固定 70% 基准宽度、压缩窄屏卡片留白并允许必要滚动后，重新构建刷新，完整显示输入和发送；历史抽屉开关可用。该视口不能代替实体软键盘验证。
4. 两位演示伙伴、两台演示机器人：书桌机器人预选“小芽”时当前仍为“小暖”；确认弹窗显示具体机器人及前后伙伴；确认后仅书桌机器人变为“小芽”，客厅仍为“小暖”。成功提示与结果一致。

临时预览脚本在被忽略的 .tools/ux-preview.mjs，运行 `node .tools/ux-preview.mjs`，仅绑定 127.0.0.1:19090，无上游代理。GET 返回合成数据；伙伴设置和陪伴设置 PUT 只修改进程内演示状态；其他写操作拒绝。它不读取真实凭据、不调用模型或机器人，不代表服务端端到端验收。

用户已手动打开具体预览页面，Computer Use 仍拒绝读取窗口，原因是无法可靠确认浏览器 URL。此条件跨多轮重试持续存在；专用 Browser 插件所需 26.915.31945/scripts/browser-service.mjs 经文件检查仍不存在。当前阻塞是浏览器工具环境，不是缺少用户授权；不再请求重复打开相同页面。 预览进程会话丢失时先检查原句柄，再启动新的本地服务。
