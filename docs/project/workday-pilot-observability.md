# WORK-002 私用观察与门槛可观测性

- 文档状态：COMPLETED
- 日期：2026-08-30
- 实现基准：`c62ccd0`
- 工作流：服务端、前端、部署

## 目标

`WORK-001` 已形成工作日陪伴闭环，但原有九十天聚合不能直接回答十四天私用门槛是否通过。`WORK-002` 在不修改固件协议、不保存正文和原始传感器数据的前提下，把误播报、外部服务降级、动作安全结果和设备重启纳入本地聚合，并提供一份固定十四天报告。

十四天观察仍是合入后的真实使用过程，不拆成 A/B/C 子任务。`WORK-002` 只交付支撑该过程的可观测性和管理入口。

## 固定门槛

- 从管理员显式开始或重新开始当天起，固定观察十四个自然日。
- 冻结开始时的设备时区和工作日掩码；中途修改设置不改变当前观察窗口。
- 十四天内至少八个计划工作日发生过显式工作会话。
- 每天最多形成一次确定性首次简报。
- 每个七天分段内人工标记的误播报不超过两次。
- 日历和天气降级必须有受控来源失败码；不保存响应或正文。
- 固件动作安全拒绝可见但不算实体动作失败；反馈、超时或硬件失败必须为零。
- 设备序号回退代表设备重启；观察窗口内必须为零。
- 只有窗口完整结束后才给出 `PASS` 或 `FAIL`，此前为 `COLLECTING`。

## 数据模型

Flyway V43 扩展每日聚合：

- `false_trigger_count`
- `motion_rejected_count` / `motion_failed_count`
- `device_restart_count`
- 日历、天气失败计数和最后受控失败码

设备只额外保存最后一次已接收的固件 `sequence`。`workday_pilot_observations` 每台设备只保存一份当前观察窗口、时区和工作日掩码快照。重新开始不会删除九十天聚合，只重置当前窗口。

不新增日程正文、天气原始响应、播报正文、触摸通道、距离、照度、舵机位置或自由文本原因。

## 采集边界

- 心跳首次序号小于数据库最后序号时记录一次设备重启；正常 WebSocket 重连但序号继续增长不计重启。
- 固件累计动作失败数只记录相邻心跳的正差值；设备重启时不把计数器归零误判为新动作失败。
- `CAPABILITY_MISSING`、`NOT_CALIBRATED`、`ADMIN_DISABLED`、音频忙、离线、升级、设备错误、并发忙和软限位归为安全拒绝。
- `TIMEOUT`、`FEEDBACK_FAULT`、`HARDWARE_FAILURE` 归为动作失败；`TOUCH_STOP`、`VOICE_STOP` 是预期停止，不进入两类计数。
- 首次简报读取到过期或不可用日历/天气时，记录受控失败码；同一工作日重复调度不重复增加该来源计数。
- 可观测性写入使用隔离事务并由核心链路容错，指标异常不能拒绝合法心跳或抑制简报。

## 管理接口与页面

设备绑定接口：

- `GET /api/v1/workday/{deviceId}/pilot`
- `POST /api/v1/workday/{deviceId}/pilot:start`
- `POST /api/v1/workday/{deviceId}/pilot:restart`
- `POST /api/v1/workday/{deviceId}/pilot/false-trigger`
- `DELETE /api/v1/workday/{deviceId}/pilot/false-trigger`

交互设置页显示观察日期、进度、两个七天分段的误播报数、外部服务归因、动作拒绝/失败和设备重启。误播报只能由管理员显式标记并可撤销今天最近一次计数。

开始操作按设备当前日期计算；同一天开始前已经存在的匿名每日聚合仍会计入，因此应在当天首次实际使用前开始。观察开始不会启用工作模式或身体动作。
