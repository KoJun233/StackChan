设备端现在使用可中断的 `1200 ms` VM 上电等待，并将其计入动作看门狗。动作请求携带停止代数，入队后到执行前的停止不会被清掉。命令 ACK 只表示入队；设备再以命令 ID、模板、固定结果和固定失败码发送 `body_motion_result`。服务端保存设备与命令绑定的结果，页面在收到实际设备结果前不标“完成”；手动命令查询到 15 秒仍无结果时标 `UNCONFIRMED`。新服务端候选每五秒巡检缺失的自动结果，标成 `UNCONFIRMED` 并关闭自动开关，不等待下一个业务事件，也不重发动作。结果事件不含角度、原始位置或音频。结果暂存在固件内存中跨 WebSocket 重连发送，掉电/重启后不保留；服务端无法凭空确认遗失的结果。

自动动作另有持久开关，默认关闭，不与显式舵机启用共用。服务端只处理立即发生的确定性事件；持久事件键去重，已完成的自动动作间隔至少 10 分钟、每设备本地日最多 8 次；在线、已 armed、反馈/校准/能力有效且非 DND 才发。没有离线补发或自动重新 armed。自动动作结果超过 15 秒仍缺失时，新候选的定时巡检关闭自动开关，需人工查看后重新启用。“今天安静点”按设备及本地日生效，暂停后续主动语音、随机无声表情和自动动作；明确设置的普通提醒继续，管理员手动动作仍受固件安全门控。

## 目标与完成定义

用户希望完善已有的 `WAKE`（唤醒）、`LOOK_USER`（看向主人）、`NOD_SMALL`（轻点头）、`THINK`（思考）、`DROWSY`（困倦）五个动作，而非只交付 `WAKE`。这里的“完成”同时要求：五个固定模板都能在 K151 上安全执行、停止和恢复；管理端明确显示命令受理与实际执行结果；有语义合适且低频的自动触发；动作不会损害语音、显示、网络和设备安全。

完成分为三个互不冒充的层级：

1. **代码完成**：协议、固件模板、安全门控、事件编排、页面和自动化验证通过。
2. **实体动作完成**：按[逐步实机验收](../runbooks/k151-body-motion-smoke-test.md)实际执行五种模板，逐项确认方向、幅度、回中、停动和故障降级。
3. **陪伴体验完成**：自动触发在真实使用中自然、低打扰，用户明确认为动作有价值。尚无日常使用基线，此层不能由前两层自动推定。

本任务不引入模型选择角度/动作、自由旋转、舞蹈、循环动作、常开摄像头或未经确认的传感器推断。动作的最终拒绝权始终在设备固件。

## 已确认的产品选择

- 五个模板都纳入开发与实体验收，不能只验收点头后把其余四个记为完成。
- 自动动作从低频、明确事件开始；连续追问不反复动作，不用增加随机动作次数制造存在感。
- “今天安静点”按用户本轮选择覆盖当前设备上的全部伙伴、主动语音和随机无声表情；用户明确设置的普通提醒继续。自动身体动作也遵守这一设备级安静状态，管理员手动验收入口仍可用。该策略与 V51 的角色级主动语音暂停不同；2026-10-01 语音旧角色级别名已修复并以 `device-quiet-voice-20261001` 部署，完整回归 611/611、双伙伴真实数据库范围及隔离 V53 恢复通过。“恢复设备陪伴”只解除设备安静，不清除角色暂停或启用舵机，见[今日安静修复](../runbooks/device-quiet-voice-20261001.md)。
- 用户选择先推进动作，再开展自然使用观察；最初交接阶段只写文档，随后已授权软件开发，本文件上方的实施记录为当前进度。

用户此前也选了“长时间空闲后的首次唤醒”作为理想 `WAKE` 时机。顶部触摸或管理页显式开始工作可以在空闲期请求动作；WakeNet 命中的语音唤醒会立刻进入受保护语音回合。自 `1b46c28` 起，空闲语音仅暂时阻止动作，保留先前许可；实际中断已入队/运行的动作仍永久禁用。语音唤醒同时转动的时序尚未设计及验证，当前只交付安全的显式工作开始场景；若接手 Agent 要实现它，须先提出新的声音/机械时序、验证不漏录，并更新 ADR 0042。

| `WAKE` | `(0,35,450) → (0,48,450) → (0,45,350)` | 轻微醒来；显式开始工作时使用，不抢本地语音唤醒/录音窗口 |
| `LOOK_USER` | `(0,52,650) → (0,45,450)` | 固定抬头姿态，不具备识别人脸或持续追踪能力；在确认返场且传感器有效时使用 |
| `NOD_SMALL` | 原版 `(0,51,350) → (0,39,400) → (0,48,350) → (0,45,400)` 在反向第二帧未到目标；当前 `24c62a7` 改为 `(0,55,650) → (0,35,1000) → (0,45,700)`，俯仰仍在软限位内，并延长固定看门狗 | 放大轨迹第一帧实际位置仍未到 55° 目标，用户仍见约 5°；先确认自由机械行程，再检查运动完成时序，不能把失电回落视为主动回中 |
| `THINK` | `(16,50,800) → (10,48,450) → (0,45,550)` | 思考姿态；当前“活动语音回合禁动作”使语音处理中的自动触发不合法，见下文决策门 |
| `DROWSY` | `(-8,28,900) → (5,38,650) → (0,45,600)` | 温和收尾；适合显式结束工作或安静前的空闲窗口，避免临睡随机动作 |

### 必须先处理的具体风险

1. **冷启动时序不一致（软件已修）**：初版 `execute_motion_locked()` 打开 VM 后只等待 **100 ms**；现在使用与探测一致的可中断 **1200 ms** 等待并扩大看门狗预算。历史故障已证明 250 ms 不足以覆盖升压轨和两路舵机冷启动；实机仍须核验。
2. **受理与完成混淆（软件已修）**：服务端 `sendBodyMotion()` 只表示 WebSocket 发送；固件收到命令后将模板排入深度 1 的队列即可 ACK。新增最终结果事件、服务端持久状态与页面展示；未收到结果仍标 `UNCONFIRMED`，不能用心跳 `RUNNING` 推定完成。实机仍须核验结果是否准确反映回中和断电。
3. **待机动作的语音冲突**：`current_motion_guard()` 把采音、播放及活跃语音回合计为忙碌；语音开始会停动并禁用。不能直接在 WakeNet 命中后、ASR/TTS 期间发 `WAKE` 或 `THINK`，否则被拒绝、延迟听音或违反 [ADR 0042](decisions/0042-local-first-k151-body-safety.md)。
4. **历史文档口径冲突已修正**：[设备协议](../protocol/device-v1.md)原称只有管理员身体接口会创建动作命令；现在管理员显式校准和启用后，确定性工作事件也可请求固定模板，设备仍最终裁决。已有编排服务定向测试；四个业务触发源的端到端回归和实机观察仍待补充，不能把文档修订视为自动动作已实机通过。
5. **语音后的 armed 状态**：`voice_control.c` 的 `begin_turn()` 不论动作是否正在运行，都会调用 `safety_state_stop_motion_with_reason(VOICE_STOP)`，把设备退回 `motion_disabled`。因此“等语音播完再点头”在现有策略下仍不能执行；不得为了自动点头静默重发启用命令。若要改变“开始语音即禁用”的策略，先单独提出安全设计、修订 ADR 0042、覆盖抢占/重启/反馈故障实测，再由用户决定；本计划首版只使用不经过语音回合的触发源。

## 实施方案与依赖顺序

### 阶段 A：五模板的安全执行链

1. 从实施时最新 `master` 建独立 `codex/` 任务分支，重新核对运行固件、硬件能力、校准状态、服务端和页面版本。已有无动作校准历史只作排障线索。
2. 固件修复并验证动作路径的 VM 冷启动、两路扭矩读回、逐帧反馈、软限位、回中与断电。所有等待和 I/O 都必须有界并可由触摸/音频/离线/错误停止。成功后确认失去保持力；失败保持 `motion_disabled`，不能自动再启用或重放。
3. 五模板逐一做参数边界和执行状态测试。模板可在实机观察后调整固定帧，但仍须固件编译时固定，保持协议枚举不变；任何新角度都重新验证双轴软限位和原始位置边界。
4. 增加最小执行结果或等价可核验证据，覆盖“入队后失败”“被触摸停止”“播放开始时停动”“正常完成”四类。页面只把可靠完成状态标成完成，失败展示固定错误码，不上传原始反馈、位置或电流。
5. 五模板的管理端按钮继续作为逐个验收入口；默认保持禁用。任何页面预览/测试不得绕过设备校准和 armed 门控。

**阶段 A 退出条件**：固件与协议测试、服务端结果处理和页面状态测试通过；两种固件 profile 可构建；尚未实体执行时明确标记为“待实机”，不得进入“已完成”。当前构建与服务端/前端定向验证已通过，但设备端 Unity 用例未运行、完整服务端回归未通过，阶段 A 尚不能整体标为已验收。

### 阶段 B：逐项实体动作验收

严格沿用[既有实机流程](../runbooks/k151-body-motion-smoke-test.md)，不要用自动触发代替手动逐项检查：无动作启动 → 无扭矩校准 → 显式启用 → `NOD_SMALL` → `LOOK_USER` → `THINK` → `DROWSY` → `WAKE` → 触摸/语音/断线/重启等停动测试。每项需记录候选提交、制品摘要、设备/profile/NVS 策略、时间、模板、预期/实际和固定失败码；不记录原始舵机位置、私人音频或凭据。任一项不通过即停止并回到禁用，不能把其余项预填通过。

用户后续已明确授权持续访问、部署和测试直至目标完成，`32d4553` OTA 已安装并保留 NVS。真实运动需要用户在旁观察并先清出机械空间；在其就位前保持动作禁用。

### 阶段 C：五种动作进入有意义的陪伴场景

自动触发应由确定性事件编排，不读取模型输出中的动作名，不让 Tool、Skill、MCP 或通知正文拥有运动权限。推荐按下表逐一接入，每项单独回归和实机观察：

| 动作 | 首选触发 | 必须满足的附加条件 | 不触发时 |
| --- | --- | --- | --- |
| `WAKE` | 管理页或顶部触摸显式开始工作，且距离上次动作有冷却 | 工作窗口有效、设备 armed、音频空闲；现有服务调用需验证实际受理/完成；语音启动工作因本地禁用动作而不在首版范围 | 仅保留原生屏幕苏醒；普通 WakeNet 语音唤醒窗口不做身体动作 |
| `LOOK_USER` | 工作模式下，经有效接近能力确认的返场 | `proximity_supported=true`、真实状态变化、冷却到期；不能把缺失能力当作在场 | 仅显示返场表情；没有传感器证据时不假装“看见主人” |
| `NOD_SMALL` | 管理页明确完成一项待办或选择休息，且业务结果成功 | 操作未开启语音回合、设备仍 armed 且音频空闲；每个操作只一次 | 表情/文字确认即可，不因普通闲聊猜测“同意”而点头；语音确认后的点头受上文安全决策门约束 |
| `THINK` | 已绑定设备的网页文字对话进入较长处理阶段 | 设备未处于任何语音回合、处理仍在继续、动作不会与回答播放重叠 | 只显示 `FOCUSED` 等屏幕表情；**语音处理中身体思考**需另行更新 ADR 0042 和安全验证，不属于本阶段默认行为 |
| `DROWSY` | 管理页或顶部触摸显式结束工作时的空闲收尾 | 用户在场或明确触发、没有待播语音、设备 armed、当天/事件冷却未超额 | 只显示睡意表情；不按时钟或模型情绪突然动作 |

若某触发源在当前产品路径中不存在、只通过语音发起、传感器未验证或无法证明安全窗口，就把该映射标为“未交付/条件未满足”，继续保留五模板的手动安全功能；不要为凑齐五个自动触发而放宽固件门控。尤其不要将 `LOOK_USER` 宣称为人脸跟踪，或把 `THINK` 偷放入录音/活动语音窗口。

编排规则：同设备同一时刻最多一个动作；短时重复、跨来源并发和重试必须去重并有冷却；只在在线且 armed 的当前会话发送，过期事件直接丢弃，不建离线动作队列；音频、升级、DND、设备级“今天安静点”和安全错误优先；重启/断线后不补动作、不恢复 armed。建议把自动动作开关与管理员手动安全启用区分，默认关闭自动触发，避免“允许测试模板”被误解为“允许机器人自主转动”。

供首版评审的保守额度：每台设备的自动动作之间至少间隔 10 分钟、每个设备本地日最多 8 次；`WAKE`/`DROWSY` 每次显式工作会话各最多一次，`LOOK_USER` 每次有效返场最多一次，`NOD_SMALL` 每个明确业务确认最多一次，`THINK` 每个符合条件的文字对话最多一次。次数仅在确知动作完成时占用；若执行结果暂不可核实，先不要开启自动动作。额度和冷却应由同一确定性编排处统一裁决，进程重启后不得重新播放已处理事件；下一 Agent 可依据实体时长与初期观察调整常量，但不能让提醒或语音因额度而被延迟。

### 阶段 D：真实使用价值

用户此前主要进行开发测试，尚无自然使用基线。阶段 B/C 通过后，先低频试用并记录每天动作实际完成数、被拒/停止数、用户是否觉得自然或打扰，以及误触发的具体场景；不保存原始传感器流或对话正文。根据观察调触发时机/冷却，不以动作次数、五模板按钮可点或自动测试数量作为陪伴价值结论。

## 交接与停止条件

- 下一条精确操作：完成本任务单个中文提交并仅推送任务分支，由用户创建 PR、审核和合并；按现场新确认恢复的低频自动动作自然使用，工作 `OFF`。断线、重启、安全停止后不自动重新启用。用户记录打扰与陪伴价值，不再重复已通过的受控动作测试；真正本地语音回合停动未验，按用户要求暂不继续音频测试。
- 任一候选若动作方向错误、卡滞、持续扭矩、异响、发热、越界、触摸未停、语音冲突或重启，立即停止该轮，保持 `motion_disabled`，记录非敏感失败现象，修复后重新走阶段 B；不得继续测试余下模板。
- 若以后增加语音中的身体动作场景，须先修订安全设计与 ADR 0042 并单独验证；当前 `THINK` 只在网页文字对话满足条件时自动触发，不放宽录音/语音禁动作限制。
- 任务完成、暂停或阻塞时更新[固件状态](status/firmware.md)和[全局总览](status/overview.md)，写明五项分别达到的层级、未完成项、下一条精确操作、验证命令和实体授权范围。外部推送及设备操作仍遵守 `AGENTS.md` 与用户后续授权；运动验收需用户就位观察。
