# 工作日桌面陪伴 V1 开发设计

- 文档状态：ACTIVE
- 决策日期：2026-08-24
- 当前任务：`WORK-001`
- 实现基准：`fa093dc`
- 目标硬件：M5Stack StackChan K151/K151-R
- 产品阶段：单用户私用验证，暂不承诺开源安装支持

## 目标

在现有语音、提醒、角色、记忆、设备连接和动态表情能力上，交付一个可以连续私用的工作日桌面陪伴闭环。机器人由用户显式进入工作模式，再根据在场状态维持或暂停；每个工作日最多进行一次确定性天气/日程简报，在用户实际在场的专注时间达到阈值后提供可回应的休息提醒，并用有限、可取消的身体动作表达存在感。

首轮成功不以新增模块数量衡量，而以十四天内是否稳定进入日常使用衡量。通过十四天门槛后继续运行六至八周，再决定是否恢复开源支持、日历写入、随机主动关心、摄像头或智能家居。

## 当前实现进度

- `BASE-010` 已完成文档事实恢复：MEDIA-004 软件和 LAN 发布已收口，V2 EAF 实体激活因暂无素材继续延期；K151 的接近/环境光硬件事实已修正。
- `WORK-001A` 第一切片已完成并发布到 LAN server/V37：V37 只保存设备级工作日设置；管理 API 和既有“交互与主动陪伴”页面可以管理默认关闭的工作日、时间、50/10 节奏、10/45 离开阈值、时区和固定地点。
- 设置在数据库、服务端和页面三层保持同一边界；经纬度必须成对、返场阈值不得小于离开阈值、开始与结束时间不得相同，工作窗口支持跨午夜。
- `WORK-001A` 第二切片已完成并发布：V38 持久保存七态工作模式、在场专注、离开暂停、休息选择和首次简报原子占位；九十天日聚合不含正文，页面只读展示当前状态和汇总。
- `CONN-001` 已完成 LAN/V39 发布和用户语音复测：只读接入 iCloud Calendar，支持加密 App 专用密码、已验证 Apple Account 邮箱、日历发现与允许列表、未来七天手动及每小时同步、二十四小时缓存和设备绑定的近期日历 Agent Tool。
- `WEATHER-001` 已完成、发布并通过用户验收：V40 按设备固定位置保存 Open-Meteo 当前及今明两天的最小必要字段，缓存一小时；管理页提供无保存测试和手动同步，每小时调度自动刷新，设备绑定天气 Agent Tool 强制读取新鲜缓存。
- 当前尚未接入工作模式启动入口和工作模式周期调度；日历与天气同步不会自行生成首次简报、休息播报、传感器自动化或舵机动作。本切片无固件变更，不需要刷写或实机测试。

## 固定产品边界

- 当前活动角色负责语气、音色、表情和动作风格；工作时间、地点、日历和专注设置属于设备，不按角色重复保存。
- 工作模式由语音“开始工作”或顶部区域长按显式启动。传感器可以维持、暂停和恢复模式，不能在用户从未启动时自行进入。
- 每个工作日首次到达最多播报一次简报；当天后续返回只允许无声表情和动作。
- 主动语音只用于首次简报、临近日程和用户启用的休息提醒。随机闲聊和由模型判断的打断不在 V1。
- 日历首版只读。模型、Agent Tool 和设备不能创建、修改或删除日历事件。
- 日程、天气、在场和计时判断均为确定性逻辑。LLM 不改写事实、不选择舵机角度，也不补全失败的外部数据。
- 摄像头、NFC、红外、Home Assistant、iOS App、多硬件兼容、舞蹈、连续旋转和公开开源安装支持保持冻结。
- LAN HTTP 仍只用于受信任开发环境；生产入口继续保持 HTTPS-only。

## 用户闭环

### 启动与首次简报

1. 用户说“开始工作”或长按顶部区域。
2. 服务端确认设备在线、处于配置的工作窗口且不在免打扰状态。
3. 设备以原生表情进入苏醒状态；只有音频空闲时才执行有限“苏醒/看向用户”动作。
4. 服务端读取缓存天气和未来日历事件，生成不超过约二十秒的确定性简报：一句角色化问候、当天显著天气或降雨、最近两项允许播报的日程。
5. 私密事件只显示和播报“私人日程”；不可用的数据段被明确跳过，不阻塞其余简报。
6. 当天简报成功、部分成功或取消均记录不含正文的结果，避免反复播报。

### 在场、离开与返回

- 接近传感器只产生当前在场状态，不保存原始时间序列。
- 连续离开十分钟后暂停专注计时并进入低打扰表现；离开四十五分钟后再次出现才算重新到达。
- 当天重新到达只执行无声苏醒、看向用户或轻微点头，不再次播报简报。
- 环境光只调节亮度；变暗不能结束工作模式。
- 用户可随时语音结束工作或再次长按顶部区域。免打扰、离线、固件更新和错误状态始终优先。

### 专注与休息

- 默认专注五十分钟、休息十分钟；只在用户在场时累计专注时间。
- 临近日程、活动语音回合、通知播报、免打扰或设备离线时不发起休息提醒。
- 提醒提供“开始休息”“稍后十分钟”“今天跳过”三个确定性动作；语音确认链和屏幕按钮复用现有互动通知语义。
- “稍后”重新进入可靠队列；“今天跳过”只影响当前设备的本地工作日，不修改全局提醒。

## Apple 日历接入

### 认证与授权

- 仅支持 iCloud 中的日历，不支持“在我的 iPhone/Mac 上”的纯本地日历。
- 管理员输入 Apple Account“登录与安全性”中已登记并验证的邮箱，以及单独生成、可撤销的 App 专用密码。真实 Shell 对照证明手机号会在密码校验前被 Apple CalDAV 固定拒绝，因此不接受手机号；禁止提交或记录 Apple 主密码。
- Apple 当前优先为支持的第三方应用提供“账户数据共享”授权；本项目尚未接入该授权流程，因此按 Apple 对不支持应用的后备方案使用开启双重认证后的 App 专用密码。
- Apple 官方确认中国大陆 iCloud 由云上贵州运营，并把 `*.icloud.com.cn` 列为中国大陆 iCloud 服务域；CalDAV 发现先访问 `caldav.icloud.com`，仅在认证失败时尝试 `caldav.icloud.com.cn`。后续目标只允许 HTTPS/443 下的两个根入口和 `p数字-caldav.icloud.com[.cn]` 编号分片，不接受任意区域、自定义 URL、用户信息或片段。参考 [Apple 第三方 App 接入说明](https://support.apple.com/zh-cn/121539)与[企业网络所需主机](https://support.apple.com/zh-cn/101555)。
- App 专用密码复用项目现有秘密加密边界，API 只返回连接状态、账户掩码、最近同步时间和安全失败码。
- 管理员显式选择允许读取的日历。没有进入允许列表的日历不参与同步、简报或诊断。
- 首版 CalDAV 客户端只执行发现、日历列表和只读事件查询，不实现写方法。

### 数据最小化

- 事件缓存仅保存生成简报和近期提醒所需的事件 ID 摘要、日历 ID、开始/结束时间、忙闲、私密标记、标题和可选地点。
- 不缓存备注、参与人、附件、会议正文或认证响应。
- 私密事件标题在进入语音/页面 DTO 前替换为“私人日程”。
- 日历详情缓存最长二十四小时；连接删除或撤销时立即物理删除凭据和缓存。

## 天气接入

- 管理页保存设备位置名称、IANA 时区、纬度和经度；不建设手机定位或位置轨迹。
- V1 使用 Open-Meteo，只请求当前状况、当天高低温、体感温度、降水概率/降水量和必要的天气代码。
- 天气缓存按设备位置保存，最长一小时；简报读取缓存时必须携带观测/预测时间。
- 只有降雨、明显温差或其他规则命中的信息进入语音；普通天气使用一句简短事实。
- 请求失败时返回安全失败码并跳过天气段，不能让 LLM推测。

## 确定性工作模式状态机

```text
OFF
  -> STARTING           用户显式启动
  -> ACTIVE_PRESENT     启动成功且用户在场
  -> ACTIVE_ABSENT      连续离开达到 10 分钟
  -> ACTIVE_PRESENT     返回；离开 >= 45 分钟时产生一次无声返回行为
  -> REST_PROMPTED      在场专注累计达到 50 分钟且规则允许
  -> RESTING            用户选择开始休息，10 分钟后恢复 ACTIVE_PRESENT
  -> ACTIVE_PRESENT     用户稍后或休息结束
  -> SKIPPED_FOR_DAY    用户选择今天跳过，不再发起休息提醒
  -> OFF                用户结束、跨工作日恢复、管理员关闭或安全状态要求
```

状态迁移必须使用设备时区和服务端时钟。进程重启后可从持久状态恢复，但不会重放已经记录过的首次简报或休息语音。Redis 只用于锁和短期协调，PostgreSQL 保持持久事实来源。

## 身体动作与传感器安全

### 硬件能力

K151/K151-R 具备两个反馈舵机、十二颗 RGB、三段顶部触摸、接近/环境光传感器、IMU、NFC、红外和电池监测。V1 只启用接近/环境光、现有 IMU/触摸、反馈舵机和已有显示/声音；其余能力继续关闭。

设备心跳新增显式能力位，字段缺失永远解释为不支持：

- `body_motion_supported`
- `body_touch_supported`
- `proximity_supported`
- `ambient_light_supported`
- `servo_feedback_supported`

运行诊断只允许当前在场布尔值、环境光分档、动作状态、最后安全失败码和累计失败计数，不保存原始传感器流。

### 运动边界

- `motion_disabled` 仍是默认和失败回退。只有完成本机校准且管理员显式启用安全动作后才进入 `motion_armed`。
- 首次校准确认水平中心和垂直中心；垂直软限位固定在 10°..80°，比官方 5°..85° 建议范围更保守。
- V1 只允许 `WAKE`、`LOOK_USER`、`NOD_SMALL`、`THINK`、`DROWSY` 五个固件内置模板。协议不接受任意角度、速度、循环次数或远程 URL。
- 模板具有固定最大幅度、速度、总时长和回中动作；同一时间最多一个动作。
- 录音、WakeNet 关键窗口、TTS 播放、固件更新、离线或错误状态禁止动作。触摸停止、语音停止和本地看门狗必须立即断开动作并回到 `motion_disabled` 或安全中心。
- 服务端只发送枚举动作和幂等命令 ID；固件始终拥有最终拒绝权。

## 数据模型与迁移计划

从当前 V36 开始按实际交付拆分迁移，禁止用一个迁移同时引入未实现的后续阶段：

1. V37：设备工作日设置，包括固定地点坐标；不提前创建未使用的运行表。
2. V38：工作模式运行状态、首次简报去重和九十天聚合使用统计。
3. V39：加密 iCloud Calendar 连接、允许日历和短期事件缓存。
4. V40：天气短期缓存；如届时不需要持久表，则明确记录为无迁移实现。
5. 固件协议版本保持向后兼容；能力位缺失时页面禁用动作和在场自动化。

建议服务端包边界：

- `workday/`：设置、状态机、调度、简报编排和聚合指标。
- `calendar/`：CalDAV 认证、发现、只读同步、缓存和安全错误映射。
- `weather/`：Open-Meteo 客户端、缓存和确定性天气摘要。
- 复用 `interaction/` 的免打扰和设备时区、`reminder/` 的可靠投递、`notification/` 的互动回执、`role/` 的活动角色与音色、`device/` 的连接和能力门控。

## API 与页面

管理端在现有“交互设置”页面增加“工作陪伴”区域，不新增重复一级导航：

- 工作模式启停、工作日/时间、50/10 时长、10/45 离开阈值。
- 地点名称、时区、经纬度和天气连接测试。
- iCloud Calendar 连接、撤销、日历发现和允许列表。
- 动作校准状态、安全启用开关和能力禁用原因。
- 当前工作模式、今日简报状态、专注/休息状态以及近九十天聚合指标。

管理员写接口继续要求会话和 CSRF。凭据连接测试必须使用提交值或已加密值，但响应、日志和错误不得回显凭据、CalDAV 认证载荷或事件正文。

## 失败与恢复

- 日历失败：跳过日历段，天气和问候继续；显示安全失败码，保持下次计划同步。
- 天气失败：跳过天气段；不复用超过缓存上限的陈旧预报。
- 设备离线：不生成音频，不记为已播报；上线后仅在仍处于当天首次到达窗口时补发一次。
- 传感器缺失：允许用户显式使用工作模式和墙钟计时，但页面清楚标记不能自动暂停。
- 舵机未校准或失败：表情、语音、日历和天气继续工作，动作永久回退关闭，直到管理员重新校准。
- 服务重启：依赖 PostgreSQL 恢复工作模式和去重状态，不重放已确认动作。

## 本地指标与保留

仅保存以下聚合结果九十天：活跃工作日、工作模式启动/结束、简报成功/部分成功/失败/取消、休息/稍后/跳过、误触发标记、动作拒绝/失败、设备重启和外部服务安全失败码。不得保存对话正文、日程标题、天气完整响应、精确位置历史或原始传感器样本。

## 实体与产品验收

实体动作必须逐次获得设备、profile、提交和 NVS 策略授权；未授权时只产生自动化和构建证据。

十四天门槛：十个工作日中至少使用八天；每天最多一次主动简报；每周误播报不超过两次；日历和天气无错误归属；没有舵机越界、卡死或持续运动；没有设备自动重启。通过后继续运行六至八周，再根据聚合行为决定下一迭代。

## 后继迭代入口

只有私用稳定数据支持时才重新评估以下分支：确认后写入日历、规则化普通关心、TTS 期间轻微动作、Home Assistant、摄像头理解、NFC/红外、开源安装向导和多硬件兼容。每个分支必须单独写 ADR，不能通过扩大本文件范围直接进入实现。
