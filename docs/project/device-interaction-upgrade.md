## 已确认的产品行为

| 项目 | 选择 |
| --- | --- |
| 顺序 | 先舵机、表情、触摸；再屏幕确认和日常菜单；本地视觉作为独立阶段 |
| 外观 | 在现有 LVGL/BSP 中实现 RoboEyes 风格的简洁双眼，独立眼睑、眨眼、视线和自然过渡；不复制第三方实现 |
| 模式 | 空闲左右滑切 WAKE/PTT，上滑开控制中心；按住说话保留；忙碌触摸优先停止 |
| 模式提示 | 移除右下空闲切换按钮；切换有短眼睛动作、短文字；常驻不可点击的小采音状态符号 |
| 摸头 | 空闲、已明确启用且通过本地门禁时，一次轻点头和喜爱眼神；运动中触摸继续急停 |
| 确认 | 统一覆盖现有需要确认的操作；短语音提示替代完整复述，屏幕提供确认/取消，错误时取消后重说 |
| 卡片输入 | 卡片显示期间暂停唤醒和采音；停止提示音只停止声音，取消按钮才撤销操作；旧固件保留语音确认 |
| 菜单 | 输入模式、音量、亮度/夜间显示、今天安静/恢复、工作/休息、伙伴、连接/电量状态及停止操作；首版不开放校准/凭据/OTA |
| 视觉范围 | 本地人脸位置检测，不识别身份、不保存/上传图像；默认关闭，由菜单开启 |
| 视觉调度 | 只在脸部待机时采集；录音/播放、菜单、卡片、升级暂停；保留 LTR553 共享电源所有权 |
| 多人/丢失 | 首次选最大脸，随后优先目标位置连续性；短丢失等待，持续丢失缓慢回正并停止跟随动作 |
| 身体跟随 | 眼神持续跟随；已启用舵机时采用死区、限速、间隔的有限头部跟随，优先保留唤醒空档；不反复发送 LOOK_USER 冒充追踪 |

## 已确认的代码问题

1. 舵机软件每 50 ms 发目标，内部目标时间 60 ms；每步 UART、I²C、相对等待累积时长，段末反馈/恢复还可停顿。软件因素有代码证据，机械/供电根因未做现场测量。
2. 情绪在 TTS 合成前下发并开始 5–15 秒倒计时，PROCESSING/SPEAKING 却完全遮蔽；长回答可能在首次可见前就耗尽情绪。
3. 工作开始和返场发送 JOY，而固件只接受 HAPPY 等十二枚举；返场 4 秒也违反 5–15 秒协议。
4. 完成待办提案仅保存对象 ID/旧标题，执行不核对固定内容；后台编辑后旧确认可作用于新内容。
5. 现触摸直接分发语音任务、只有按下/释放；新菜单和卡片必须拥有独立事件归属，避免点确认触发取消、长按菜单触发采音或释放穿透。
6. 当前构建未启用中文字库；屏幕任意待办标题需要字库/换行/滚动与内存、制品预算，不能只增加中文 label。

## 协议和安全边界

- 卡片展示固定动作内容、时间/时区及伙伴；设备只回传卡片 ID 和 CONFIRM/CANCEL，不把点击转换为最新提案的“确认”文本。
- 从已认证连接确定设备，所有卡片执行核对当前伙伴和会话；对象编辑、过期、删除或替换使原卡片失效；并发点击只执行一次。
- 菜单持久设置通过服务端窄字段更新和回执；输入模式独立保存在 NVS；亮度为本次启动的本地覆盖，相机重启关闭；旧设置不能重连后悄悄覆盖本轮操作。
- 录音/播放、断线、更新、错误、摸头停动和校准/反馈仍为最终本地门禁；默认禁用、重启不恢复许可，跟随不能自动 armed。
- 新本地跟随限定固件计算的安全范围，不向模型或远程协议开放任意角度、速度或轨迹；保留当前校准导致的下行限制。
- 图像只驻留工作缓冲；当前仅协商设备 UI 能力；视觉状态/失败码/聚合性能保留本地，不上报图像、框坐标或原始传感器流。
- 生产 HTTPS-only；不改凭据、模型计费、现行部署模式。不安装固件、不驱动硬件、不打开相机、不外推，直到有本任务的明确许可。
