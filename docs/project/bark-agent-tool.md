## 用户目标

用户已确认通用持续任务可用，要求把现有 Bark 推送封装成 Agent Tool，供伙伴按目标调用。复用原设置，无需在对话中提供 Key。先前的原型部署授权继续适用；保持 LAN、身份、卷、凭据、DoH 和原固件。

## 接口与授权

`send_phone_notification(title, body)` 只接受标题和正文，标题 1–80 Unicode 字符，正文 1–2800 UTF-8 字节；超长内容由 Agent 摘短后再调用，服务端不静默截断。接收人和服务器地址来自已有加密 Bark 设置，模型不能指定 Key、地址、设备、伙伴、回合或运行 ID。

内置工具目录、管理开关及审计复用现有 Agent 管理入口。聊天和语音只有当前用户明确要求手机推送才开放写工具，否定、示例、设置咨询不开放。涉及已有事实查询的请求，先成功读取对应工具才允许推送。语音普通续讲不继承上一轮推送动作。每次外发前重新检查设备、伙伴、Agent 总开关、工具开关和 Bark 渠道。

后台执行还要满足当前任务、尝试、工具快照和 BARK 交付范围。CONSOLE 规划不保存通知写权限；旧空快照只继承内置读取。旧快照不增加新工具，新任务仍由 AI 选择已有授权工具。

## 真实结果与幂等

返回 `receiptId/status/errorCode/deduplicated`。SENT 只证明 Bark 接受，不证明手机送达或阅读；FAILED、UNKNOWN 不构成成功步骤，不允许模型回退冒充发送。UNKNOWN 先检查手机历史，不自动重发。明确的新用户回合可发新通知。

V60 新建投递标记表，仅存服务端回合或运行生成的不可逆指纹、内容指纹、回执 ID、状态和时间；不存消息正文、Key 或原归属 ID。同一回合或运行最多一个工具投递，模型重复调用、不同内容、并发调用、重启及不确定结果均不触发第二次外发。外发前独立提交 SENDING；该表不使用外键，避免与持续任务持有的归属锁形成独立事务等待。

普通定时成果仍自动按 BARK 渠道投递。若执行 Agent 已实际调用通知工具，真实回执替代自动通知，防止双发；失败或不确定回执阻止自动补发。已发出的通知无法撤回。现有明确失败后的人工重新投递复用成果，并同步回执。

## 验证与安装

2026-10-11 用户现场发现「嗯，给我的手机发一条消息」漏判，语音低延迟路径无工具；具体工具的「有没有功能」追问也漏判。修复任务 `codex/bark-voice-routing` 从最新 master 创建并包含未合入依赖。通知支持目标与动词的两种顺序；能力咨询只读取配置授权目录，并以实际目录覆盖旧否认回答。角色和工具边界通过模型 system prompt 传入。缺正文且无工具操作时返回明确内容追问，相邻用户回答补全本次授权；取消、咨询、换话题、续讲及已发送历史不能继续写权限。通知正文内的否定和能力词不作为指令；补充的字面正文不触发无关天气查询。没有回执不能声称成功，已尝试失败仍按原失败处理。修复已从保留 V57–V60 的冻结 a37d220 安装，最终相关 103/103。用户现场复测确认基本正常，并授权推送当前任务分支。
