## 固定产品与安全边界

- 机器人服务于一位长期用户，数据模型仍保留设备范围；近期不引入多用户权限体系。
- 保持设备本地 WakeNet；跟进窗口也必须先由本地 VAD 判定有效语音，禁止常开云端录音。
- 记忆采用“明确指令 + 建议箱”；只有用户确认且启用的记忆可以进入模型上下文。
- 主动关心由确定性规则决定时机；模型只能使用允许主动提及的已确认记忆生成一句简短措辞。
- Agent 只能看到当前请求被授权的 Skill 和 Tool；所有 Tool 都由应用执行，模型不能获得底层 API、数据库、文件系统或凭据的直接访问权。
- `INT-008` 只开放只读 Tool；后续涉及提醒、设置或记忆副作用时，模型只能提交结构化提案，由服务端复核并在需要时等待用户确认。
- 不开放语音删除、部署、凭据、固件、摄像头或舵机操作；`motion_disabled` 保持不变。
- 生产保持 HTTPS-only，绝不组合 LAN 与 production Compose；固件继续遵循服务端先兼容、旧固件验证、再构建新固件的发布顺序。

## `INT-008`：受控 Agent、Skill、Tool 与 MCP 基础

基线服务端直接使用 Spring AI `ChatClient`，没有 Tool、Skill、MCP 或 Agent 循环。本任务改用 Spring AI Alibaba 1.1.2.2 `ReactAgent`，同时继续复用现有 OpenAI-compatible `ChatModel` 和供应商配置；不在第一版开放副作用。

### Agent 执行内核

- 新增共享 `AgentOrchestrator`，供网页文字聊天和设备语音回合调用；它使用 `ReactAgent` 执行 ReAct 循环，不复制两套工具执行逻辑。
- 使用 Spring AI `ToolCallback` 作为统一执行接口，并用 Agent hook/interceptor 在应用侧逐次检查权限、超时、结果大小和剩余预算。
- 每回合最多 4 次 Tool 调用、Agent 总预算最多 20 秒；单次结果最多 8 KiB、全部 Tool 结果最多 24 KiB。触及任一上限即停止调用并生成不含伪造结果的安全回答。
- 当前模型不支持 tool calling、返回未知工具、参数不符合 JSON Schema 或供应商失败时，回退现有普通聊天；不得猜测工具结果。
- Agent 由部署总开关和 PostgreSQL 管理员紧急开关共同控制；关闭时请求路径回退原有 `ChatClient` 行为。第一版只读能力随 V19 默认启用，管理员可立即总停或逐项停用。

### 内置 Tool 与 Skill

- 当前保留两个已经实机验证的只读 Tool：当前日期/用户时区和列出本回合实际能力；提醒、记忆和设备状态查询延后到对应业务任务，避免页面展示不可用能力。
- 管理员上传完整 ZIP Skill 包；包内必须且只能有一个规范 `SKILL.md`，并完整保留 `references/`、`examples/` 等附属文件。
- 服务端安全解压到独立持久目录，拒绝路径穿越、绝对路径、重复路径、链接、加密或特殊条目、超深目录和压缩炸弹；重名默认拒绝。
- 导入后默认停用，管理员查看元数据和文件清单后手动启用。`SkillsAgentHook` 仅向下一回合注册已启用 Skill 的 `read_skill`。
- Skill 包不会自动获得 Shell、Python、文件系统、新 Tool、MCP 或业务写入权限；当前版本保存附属文件但不执行或自动读取。

### MCP Client

- 接入 Spring AI MCP Client，并把发现的 MCP Tool 适配成同一 `ToolCallback` 策略链；第一版只支持 Streamable HTTP，不启用会在 server 主机启动进程的 STDIO transport。
- MCP server 连接由管理页面或兼容启动配置提供；页面连接、加密 Bearer Token、发现、健康与逐 Tool 授权由管理 API 提供，所有新连接和 MCP Tool 默认禁用。生产只允许 HTTPS，LAN development 可显式使用私有地址 HTTP，但不得降低生产边界。
- 工具发现不等于授权：管理员必须从发现结果中逐个加入允许列表，并确认第一版仅用于只读调用；未列入允许列表、名称冲突、schema 变化或连接身份变化时立即停用。
- 页面只接收 `NONE/BEARER` 认证；Bearer Token 使用现有 AES-GCM 密钥加密，任何 API、页面、审计和日志都不得返回 secret，模型上下文也不接收 endpoint、header 或 secret。其他认证方式仍由部署边界管理。
- 第一版不开放 MCP resources、prompts、sampling、roots 或 elicitation，只交付受控 Tool 调用。

### 管理与审计

- 新增 Agent 能力页面，展示启用状态、内置 Skill/Tool、MCP server 健康、发现工具和允许列表；管理员可以停用单个 Skill、Tool 或整个 MCP server。
- 每次调用只记录回合 ID、Skill ID、Tool 名、来源类型、MCP server ID、成功/安全失败码、耗时和截断标记；不记录参数、结果正文、对话正文或认证信息。
- 提供紧急总开关；关闭后新请求不再获得任何 Tool，正在等待的远程调用按超时取消，普通聊天继续可用。

### 验收

- 网页与语音各完成一次内置只读 Tool 回合；模型没有调用 Tool 时仍保持当前回答行为。
- Skill 搜索/加载、Skill 不存在、越权 Tool、未知 Tool、畸形参数、四次上限、20 秒超时和结果截断均有确定性测试。
- MCP 覆盖连接成功、未授权工具、schema 变更、重名、断线、超时、撤销和秘密脱敏；任何失败都不执行其他工具或产生副作用。
- Agent 关闭、模型不支持 tools、MCP 全部离线时，文字和语音聊天都回退现有闭环。

### 第一条精确操作

当前分支为 `codex/int-008-agent-tools-mcp`，基于 `8122959`。ReactAgent 主链和 DeepSeek V4 Tool 修复已在 LAN 验证；本任务新增 ADR 0024/V20 自定义 Skill ZIP 生命周期，以及 ADR 0025/V21 页面管理的可移植 MCP 连接和加密 Bearer 认证。V21 已发布，真实 HTTPS MCP 已发现 8 个 Tool，授权状态由管理员页面控制；用户已完成验收并授权推送单一中文任务提交，下一步由用户创建 PR 并人工合并。

## `INT-009`：短暂连续对话

当前分支为 `codex/int-009-continuous-conversation`，基于已合入 DATA-001 的 `a51ac83`。ADR 0027、V23、服务端四/六字段兼容、管理端、固件状态机和全量验证均已完成；LAN server 已发布并迁移到 V23，旧固件兼容和用户单轮语音 smoke test 通过。经用户明确授权，LAN HTTP Quad 完整镜像已刷入 CoreS3 `COM3`，五区回读、启动和跨心跳周期验证通过且 NVS 未擦除；后续播放加固 `dd81a7e` 同样完成五区验证并保留 NVS。

### 协议与状态机

- `configure_interaction` 在功能关闭时保持四字段旧协议，启用时发送六字段命令；新固件严格接受四或六字段，四字段会关闭功能并恢复默认 8 秒窗口。
- 机器人完成回复并恢复麦克风后进入默认 8 秒的跟进聆听窗口；屏幕继续复用八状态中的 `listening`，不要求第九张图片。

- 触摸、明确说“结束聊天”、静音超时、离线或错误立即结束会话并恢复 WakeNet。
- 每个连续会话最多 3 个跟进回合、从首次唤醒起最多 2 分钟；任一上限到达即结束。
- 新增跟进聆听、跟进超时和会话结束阶段事件，事件只携带白名单阶段、相对耗时和安全失败码。

### 验收

- 覆盖有效跟进、无有效语音不上传、静音超时、触摸退出、结束短语、三回合上限、两分钟上限、离线与错误退出。

## `INT-010`：安全语音操作

### 首批动作

- 创建单次/周期提醒；稍后提醒；跳过下一次。
- 设置临时免打扰和音量。
- “记住……”创建 `PENDING` 记忆建议。
- 查询下一条提醒和待确认记忆数量。

### 执行边界

- 仅当用户说出“提醒我、记住、音量调到、安静到”等明确动作表达时才解析动作；普通聊天直接走现有回答。
- 复用 `INT-008` Agent 内核，但副作用 Tool 只能接收结构化动作提案，不能直接调用业务服务。
- 对模型输出执行字段、权限、时间、范围和枚举二次校验；解析失败退回普通对话，不产生副作用。
- 提醒、免打扰和音量先复述具体结果，用户在跟进窗口确认后执行；模糊时间只追问。
- `actionProposalId` 绑定管理员、设备和会话，2 分钟过期；确认接口幂等，重放不得重复创建提醒。
- “记住……”可在单回合创建 `PENDING` 建议，但在确认前不得进入上下文。
- 删除记忆/对话、部署、凭据、固件和设备控制不加入语音动作白名单。

### 验收

- 覆盖取消、过期、重复确认、跨设备/会话确认、畸形 JSON、越权枚举和供应商失败，全部无意外副作用。
- 动作审计只记录提案类型、状态和安全标识，不记录完整用户语句或模型响应。

## `INT-011`：长期记忆 2.0

当前分支为 `codex/int-011-memory-2`，基于已合入 INT-010 的 `fbe5bde`。ADR 0029、V25、完成回合异步单条建议、敏感过滤、同主题确认替代、`pg_trgm` 有界检索、使用 ID 记录和管理端来源解释均已实现；服务端 299/299、前端 66/66、真实 PostgreSQL V1..V25、类型/构建、Compose、文档与差异检查通过。本地候选已只发布 server/V25，旧 `dd81a7e` 自动重连，用户确认人工测试无问题并授权推送；下一条精确操作是由用户创建 PR、人工审核并合并。

### 建议、冲突与检索

- 正常对话结束后最多生成 1 条高价值建议；自动拒绝凭据、精确地址、身份号码、财务或医疗推断。
- 建议箱显示类型、设备/全局范围、来源回合、建议原因和可能重复项；用户可确认、修改或拒绝。
- 记忆增加 `topicKey`、重要度、最后使用时间、来源回合、替代关系和“允许主动提及”开关。
- 同主题冲突创建待确认替代项；确认后旧项保留审计记录但不再进入上下文，禁止静默覆盖。
- 第一版启用 PostgreSQL `pg_trgm` 与普通索引，按设备范围、关键词/相似度、重要度和时效性组合排序；每轮最多 8 条且总计不超过约 4,000 个中文字符。
- 每个完成回合只记录使用过的记忆 ID；诊断页面可解释引用来源，但不复制记忆正文到日志。

### 验收

- 未确认建议永不进入上下文；冲突项不自动覆盖；禁用或删除后下一轮立即失效。
- 敏感推断被拒绝；无 `pg_trgm`、空结果和重复候选都有确定性回退。

## `INT-012`：有边界的个性化主动关心
