## 1. 结论与优先级

当前控制台的主要问题不止是配色和间距。部分聊天操作存在已复现的状态错误；设备、伙伴、会话三种操作范围不够清楚；常用任务与工程配置混排；说明文字承担了本应由页面结构解决的导航责任。

建议顺序为：**先修交互正确性，再明确操作对象，随后重组日常页面，最后统一视觉和精简文案。** 单独换主题无法修复错会话、错伙伴和保存状态不透明的问题。

本报告列出 **8 项交互问题与 10 项信息架构、布局及表达问题**。其中 B01–B04 已在 Mock API 的隔离环境复现；其他问题有源码证据，尚未完成真实浏览器复现或视觉验收。P1 表示应先处理的核心路径或操作归属问题；P2 表示随后处理的恢复、效率和体验问题。没有证据表明服务端隔离机制被绕过，不能把前端把请求发往错误目标等同于服务端越权。

### 已确认的产品取舍

| 维度 | 用户确认 | 对改造的约束 |
| --- | --- | --- |
| 使用对象 | 个人日常使用优先，技术配置退居次级 | 首屏服务聊天、伙伴和机器人状态，诊断按需进入 |
| 设备 | 电脑为主，手机也需顺畅操作 | 先优化桌面效率，同时验收窄屏与触屏 |
| 调整幅度 | 可以重组菜单与页面，保留现有能力 | 收敛入口不等于删除功能、数据或兼容链接 |
| 首页 | 伙伴与机器人状态优先，近期事项辅助 | 工作模式和风险统计不再与伙伴争夺首屏 |
| 视觉 | 温和陪伴感，柔和颜色，伙伴形象突出 | 用伙伴形象承载特色；表单、状态和操作保持清晰 |

以上五项已通过两轮询问确认。具体色值、导航名称和线框仍是本报告的设计提案，DRAFT 不代表已经授权实施或发布。

## 3. 交互问题清单

### B01 · P1 · “新对话”把点击事件传成伙伴 ID

- **证据：**[聊天页](../../apps/stackchan-console/src/views/companion/chat/index.vue)第 103 行将 `conversationStore.startNewConversation` 直接作为 click 处理器；[conversation store](../../apps/stackchan-console/src/store/modules/conversation.ts)第 115–116 行将首参数解释为 `roleId`。[API](../../apps/stackchan-console/src/api/modules/companion.ts)第 64–65 行序列化 `{ roleId }`，而服务端要求 UUID。FaButton 透传原生点击事件。
- **复现：**挂载 Vue 按钮并点击，Mock `createConversation` 收到 `MouseEvent`，并非所选伙伴 ID。已确认前端参数错误；真实服务端 400 未现场触发。
- **影响：**核心新建入口可能失败；按钮本身缺少创建失败反馈与创建中防重复操作。
- **建议：**显式无参调用或明确传当前伙伴 ID；创建期间锁定按钮和目标，错误在当前任务内可恢复。
- **验收：**选伙伴 A→点新对话→请求 body 的 `roleId` 是 A 的 UUID；连点只创建一次；失败显示原因并可再试。

### B02 · P1 · 跨伙伴重试可能把 A 的输入发给 B

- **证据：**[conversation store](../../apps/stackchan-console/src/store/modules/conversation.ts)第 125–130 行切伙伴未清 `failedRequest/errorMessage`；第 87–100 行遇到空历史不进入会话切换清理；第 218–226 行重试忽略保存的 `request.conversationId`，使用当前会话或新建会话。
- **复现：**A 发送失败→切到没有历史的 B→重试。隔离测试确认新建 B 的会话并向它发送 A 的原输入。
- **影响：**违背用户对独立伙伴的预期，可能在错误的伙伴历史留下内容。这是前端请求目标错误，不是已证实的服务端隔离漏洞。
- **建议：**切伙伴立即清旧重试状态；重试数据绑定原伙伴、会话与消息 ID，并验证当前归属。不能悄悄创建当前伙伴的会话承接旧请求。
- **验收：**切到 B 后没有 A 的错误条和重试入口；任何旧回调或重试均不得向 B 提交 A 的文本；同会话幂等重试继续有效。

### B03 · P1 · 快速切换后选择器、历史内容和发送对象错配

- **证据：**[conversation store](../../apps/stackchan-console/src/store/modules/conversation.ts)第 103–112 行先更新当前会话 ID，再无条件提交异步消息；第 87–95 行伙伴会话列表也无请求代次。聊天页只在生成时禁用切换，历史加载时仍可操作。
- **复现：**先请求 A，再请求 B，让 B 先返回、A 后返回。隔离测试分别复现“当前 ID 为 B，内容是 A”以及“当前伙伴为 B，活动会话来自 A”。
- **影响：**用户可能在错误上下文继续聊天。新会话消息加载失败时，也可能继续展示旧会话内容。
- **建议：**请求捕获伙伴/会话快照与代次，只允许仍匹配当前选择的结果提交；切换时立即清除或遮罩旧内容，加载失败显示所属对象及重试入口。
- **验收：**用可控 Promise 验证两种乱序及加载失败；选择器、标题、内容、发送目标始终一致。不要只测试正常顺序。

### B04 · P2 · 首次创建会话失败时草稿丢失

- **证据：**[聊天页](../../apps/stackchan-console/src/views/companion/chat/index.vue)第 49–59 行在请求成功前清空 `draft`；[conversation store](../../apps/stackchan-console/src/store/modules/conversation.ts)第 150–151 行创建会话在发送 `try` 外，失败不会形成 `failedRequest`。
- **复现：**输入文字→发送→Mock 创建会话失败。挂载测试确认编辑器清空，消息列表、失败原文和 store 错误状态都为空；页面仅能弹一次发送失败提示。
- **影响：**用户需要重打输入，且看不到可重试的失败消息。
- **建议：**失败恢复原草稿或保留失败气泡；首次创建与后续流式发送共享恢复流程。清空前捕获原文，避免错误恢复覆盖用户新输入。
- **验收：**创建请求断网/500 后原文可编辑重发；发送成功不重复显示草稿；取消生成和输入法组合键行为保持正确。

### B05 · P2 · 记忆筛选乱序覆盖当前列表

- **证据：**[记忆列表](../../apps/stackchan-console/src/views/companion/memories/list.vue)第 112–132 行无条件覆盖列表、总数和 loading；第 251–260 行筛选变化直接发请求；第 359–379 行操作仍作用于渲染出的行。
- **触发：**按伙伴或确认状态从 A 切 B，A 的响应晚到；当前筛选为 B，列表却恢复为 A。
- **证据级别：**静态确认缺少乱序保护，未运行该页面复现。
- **建议与验收：**每次查询绑定完整筛选快照，只有最新查询可更新；切范围时旧列表不可误操作。乱序返回后，条目、总数、确认/删除目标均匹配当前筛选。

### B06 · P2 · 设备诊断标题与回合记录可能属于不同设备

- **证据：**[设备总览](../../apps/stackchan-console/src/views/devices/overview/index.vue)第 95–109 行先改 `selectedDevice`，未清旧记录就异步加载；第 173 行标题使用新设备，第 185–188 行仍渲染旧回合；其他设备诊断入口可继续点击。
- **触发：**打开 A 诊断再打开 B。B 加载时可能短暂显示 A 记录；乱序返回后可能持续错配。
- **证据级别：**静态确认，未实际点击。
- **建议与验收：**记录、记忆使用信息和标题按同一设备快照提交；切换清旧数据。A 晚到或失败不能覆盖 B 的成功结果，也不能在 B 标题下显示 A 的记录。

### B07 · P2 · 加载失败被画成空待办或“零风险”

- **证据：**[今日概览](../../apps/stackchan-console/src/views/dashboard/index.vue)第 94–109 行先清任务数组，并将任务与可选工作状态绑定为 `Promise.all`；第 233 行仅按空数组显示“没有开放待办”；第 31–35、195 行在健康数据未取得时显示绿色风险 0。
- **影响：**页面虽有顶部错误条，局部卡片仍传达“没有任务/没有风险”的确定性结论；工作模块失败会丢掉已经成功的任务结果。
- **证据级别：**静态确认条件分支；该页面已有请求代次，不能误写成没有竞态保护。
- **建议与验收：**分别处理未加载、加载中、成功为空、失败和旧数据；分区加载。健康失败显示“未获取”；只有任务请求成功且为空才显示无待办；工作状态失败不妨碍任务展示。

### B08 · P1 · 日常设置被七个接口牵连，保存结果不透明

- **证据：**[交互设置](../../apps/stackchan-console/src/views/settings/interaction/index.vue)第 331–339 行一次 `Promise.all` 加载交互、工作配置、运行、指标、观察、日历、天气；第 540–543 行无条件并发保存交互与工作配置。保存后还等待天气读取，任一后续异常都进入“保存失败”。
- **触发：**工程观察或日历接口失败，日常打扰设置也无法正常加载；两项保存一成功一失败，或两项成功但天气读取失败，页面无法准确说明已生效内容。
- **影响：**用户可能反复保存、误判状态，两个页面看似独立却相互牵连。
- **证据级别：**源码直接确认请求与错误边界；未对真实服务做失败注入。
- **建议：**按任务独立加载、验证和保存；非必要诊断失败局部展示。暂时无法拆分时，至少区分各写入结果与保存后的刷新失败，不用笼统失败掩盖已落库内容。
- **验收：**修改主动设置不写工作配置；工程观察/天气失败仍可读取和保存主动规则；部分成功明确列出结果，不假定两端点具备事务原子性。

### 6.2 聊天

```text

                                          对话消息
                                          就近的失败与重试
                                          输入框 / 发送或停止

```

移除“支持 Markdown、复制回复、自动滚动……”等能力目录式描述；复制、停止和重试由实际控件表达。首次空态可提供一句自然邀请，正常会话不占用额外说明空间。保留 TDesign Chat 展示层和现有 Pinia/SSE 状态边界，先修 B01–B04 再改布局。

### 6.3 陪伴方式与工作陪伴

陪伴方式顶部固定目标机器人与伙伴、当前暂停状态和恢复时间，随后依次组织“语音开场”“无声陪伴”“免打扰”。保留它们独立的开关和原有频率约束，不能合成一个含义不清的总开关。次数、间隔、备用文本、话题记录放相应高级区。

“今天暂停主动聊天”是即时动作；规则表单用“保存陪伴设置”。若动作不影响无声陪伴或普通提醒，按钮附近给出这项直接后果。不得把临时暂停写成所有功能静音。

工作陪伴拆为独立视图：当前状态与启停、专注/休息规则、日历与天气、工程观察。诊断失败不阻断日常设置；观察页面保留“工程结果不等于陪伴价值”的准确提示。底层请求可共享封装，页面加载和保存边界必须分开。

### 6.4 伙伴、记忆和形象

伙伴管理按“当前可用 / 已归档”分区；用名称、现有形象、个性摘要和音色继承状态帮助识别，避免把容器术语当主要标题。归档和永久删除放次级操作，原七天规则、默认伙伴保护及二次确认不变。

记忆优先显示伙伴与确认状态，正文便于阅读；新增、确认替代、停用和删除的作用对象清楚可见。遗忘范围说明只在相关操作和帮助中完整呈现，不能被彻底删除。

形象页默认展示目标设备当前形象及生效状态；素材制作、PNG 导入、EAF 生命周期动画放次级页签；真机预览先选目标再发命令。设备未报告当前形象时显示“未获取”，静态示意须标为预览，不能冒充实时设备屏幕。

### 6.5 设置、诊断与扩展

AI 与语音使用统一表单宽度、持久字段标签、就近校验和保存反馈。密钥字段继续掩码，保留“留空不修改”等真实语义；音色无法列举时提供清楚的标识输入说明。

运行健康将连接、语音回合、表情性能和资源状态组织为诊断内容，固件升级独立分区。Agent 日常能力默认全宽；Skill、MCP、策略和审计按任务进入，MCP 连接编辑使用明确表单。低频不等于删除，原安全门控与确认保留。

## 7. 视觉与文案规范草案

### 7.1 视觉方向：温和的伙伴工作台

以机器人的眼睛、表情和伙伴名称作为识别中心；普通页面使用安静的背景和清楚的表单。避免每张卡都带插画、渐变、阴影与常驻说明，伙伴形象只在首页、伙伴管理和聊天身份区重点出现。

以下是设计色板，不是已生成或已验收的主题代码：

| 角色 | 浅色建议 | 深色建议 | 用途 |
| --- | --- | --- | --- |
| 雾白 / 夜蓝灰 | `#F5F7FA` | `#1B2531` | 页面背景 |
| 白 / 深蓝灰 | `#FFFFFF` | `#253344` | 内容表面 |
| 墨蓝 / 雾白 | `#263449` | `#EEF2F7` | 正文与标题 |
| 安静紫 / 浅紫 | `#7065A8` | `#B8A9E4` | 主操作、当前伙伴点缀 |
| 薄荷 / 深薄荷灰 | `#DEEEE8` | `#304940` | 柔和的辅助区域，不单独代表在线 |
| 桃粉 / 深桃灰 | `#F3E2DF` | `#513B40` | 伙伴形象小面积点缀 |

错误、警告、成功继续使用独立语义色和图标/文字，不拿柔和点缀色替代错误提示。实施时将提案转换为框架 OKLCH token，浅深两套一起完成，复查文本、禁用态、焦点、菜单和聊天局部变量；不能只改 `primary` 或把原十六进制直接填进 OKLCH 字段。主题作用于共享包，需先确认所有应用影响范围。

中文优先使用系统中文无衬线字体：`"PingFang SC", "Microsoft YaHei", "Noto Sans CJK SC", sans-serif`；不引入外部字体网络依赖。正文建议 14–16px，辅助 12–13px，区块标题 16–18px，页面标题 24–28px；关键状态不得只有很小的浅灰字。

布局建议：正文/短表单 720–800px、常规业务内容 1120–1200px、宽表格按需扩展，但共享左右基线。采用 4/8/12/16/24/32px 间距档位，页面与卡片不层层重复 padding。按钮高度桌面约 36–40px，触屏常用操作以 44px 为设计目标。圆角分别承担控件与内容区层级，不是所有东西都用同一个大圆角。

动画只服务反馈和伙伴形象；不让整页卡片持续浮动。提供减少动态效果的表现，离线状态也能明确辨识。以上是提案与验收目标，当前未做浏览器对比度或软键盘测量。

### 7.2 文案分层

1. 页面名称回答“这里做什么”。页头描述可选，不强制每页一段。
2. 字段提示回答“不同选择有什么后果”，避免复述标签。
3. 状态信息回答“发生了什么、对谁、何时生效”。
4. 详细机制进入帮助、诊断或相关的高级区。
5. 删除范围、归档、确认替代、密钥一次展示、设备升级等重要后果留在操作附近。

| 当前文案 | 建议写法/位置 | 理由 |
| --- | --- | --- |
| 首页“按日常任务组织，而不是按技术模块堆叠。” | 删除，保留具体入口 | 用户无需阅读页面的设计说明 |
| 聊天“消息由现有服务端会话与流式生成能力管理。” | 删除；标题显示当前伙伴 | 技术实现不帮助发送消息 |
| “支持 Markdown、复制回复、自动滚动、停止生成与失败重试。” | 删除常驻描述；相应控件提供名称或提示 | 让功能通过交互表达 |
| “角色容器” | “我的伙伴”或“伙伴列表” | 与个人使用语境一致 |
| 全局“角色设定” | “通用对话规则（高级）”；说明“适用于所有伙伴” | 避免与单伙伴个性混淆 |
| “服务重启后从 PostgreSQL 恢复。” | 日常页删除；帮助中可写“重启后保留进度” | 保留用户相关结果，移除存储实现 |
| “使用确认记忆生成一句个性化措辞” | “个性化开场”；“结合已确认的兴趣选择话题” | 缩短并明确依据 |
| “解除冷却” | “恢复主动聊这个话题” | 保留伙伴范围与原有频率限制，不承诺立即开聊 |
| “保存交互与工作日设置” | 拆分后分别用“保存陪伴设置”“保存工作规则” | 按钮准确对应请求范围 |
| 长段 PNG/EAF、A/B 槽说明 | 主页面：“查看当前形象，选择或导入素材”；格式机制放制作帮助，替换后果留在启用确认 | 日常任务与制作细节分层 |

不可删除的说明包括：记忆停用/删除不会自动抹除原聊天或已有备份；清空全部影响所有伙伴；角色归档及永久删除条件；配置作用于全局还是单伙伴；危险操作目标与后果。精简的对象是重复说明和实现解释，而不是必要的决策信息。
