## C02. 身份、隔离与时间

每个业务资源必须绑定认证管理员与服务器可验证的 `deviceId`、`roleId`。前端/模型传来的 ID 仅作请求选择，服务端检查其可访问绑定。跨角色或跨设备资源按现有 API 约定返回 404 或 403，不向未经授权主体泄露标题、来源或正文；集合查询在 SQL/服务层按绑定过滤。

数据库时刻用带时区 UTC instant；用户展示和每天的预算分桶使用设备设置的有效 IANA 时区，默认 Asia/Shanghai；不得用浏览器时区改变服务器额度。修改时区不清空当日已消费额度，保守继承当前有效窗口计数，次日再按新设置开始。测试使用注入时钟与固定日期，覆盖午夜、时区修改和夏令时；定时规则遵循现有调度语义。

角色切换立即使新goal-owned未开始的旧角色动作、当次交互批准、手机接续和普通主动候选失效；已存在的历史仍保留其原角色。legacy已经授权的角色绑定周期业务继续原规则，不因切换聊天伙伴一律停用，也绝不转到新角色执行或显示私人内容；角色归档仍沿原取消规则。已生效外发不能以切换/删除/暂停宣称撤回。

## C03. 资源标识与修订

`goalId`、`stageId`、`taskId`、`runId`、`artifactId`、`approvalId` 均是不含隐私的稳定标识。R02 先沿用现有 task/run，R03 映射后保留所有旧标识与历史；不把相同时间标题作为资源主键。

`revision` 表示目标/任务当前业务计划版本，正整数，从 1 起。改变目标、标准、来源、阶段、行动范围/交付方式时事务内加一并使旧执行计划/批准失效。执行与批准快照字段叫 `goalRevision`。普通已读或一个无关 UI 显示操作不会任意改变目标 revision。

写请求 `expectedRevision` 必须和资源当前 revision 相同；任务资源未暴露该值时先增加只读字段，不能让前端猜 attempt。反馈独立资源如有并发更新使用 `resourceVersion`，只控制该反馈/已读资源；不得替代目标修订检查。R02 反馈在同一事务验证任务 revision 和反馈 resourceVersion；R03 的目标修改统一验证 expectedRevision。

所有可造成新资源、运行、反馈、批准或外部动作的新增写入口接受 HTTP `Idempotency-Key`。键为 16–128 字符 ASCII `[A-Za-z0-9._:-]`，由客户端随机生成，不能包含正文、Token 或个人身份。绑定认证主体、资源范围、操作和正文摘要；同键同请求返回第一次的结果和标识，不重复执行；同键不同请求返回 409 `IDEMPOTENCY_CONFLICT`。保存期至少 24 小时，具有外部动作的永久运行槽/动作幂等记录不因通用键清理而失效。执行副作用前仍做 C06 守卫。

拟新增统一回查 `GET /api/v1/companion/operations/{key}?action=受控操作&resourceId=UUID`，由R02首次落地，后续写操作复用同一收据服务。新建资源时resourceId可省，服务端按已认证范围和action查找；不能通过猜键获得其他设备/角色的数据。回查只返回状态、resourceIds、revision和固定错误码，不返回正文或认证信息。

收据状态限定 PENDING（已持久化意图尚未提交业务结果）、COMMITTED（业务变更与收据同事务成功）、FAILED（固定失败已保存）、NOT_FOUND（本认证范围无收据）。PENDING不表示已经创建目标或执行成功；网络未知时先查或用原键安全重投，不能换键盲发。FAILED同键返回原失败，新的明确意图才可新键重试且仍检查revision/永久动作槽。清理收据不能改变真实外部动作和目标历史。

正文摘要采用服务端校验后的规范JSON：稳定字段顺序、明确默认值、完整相关scope/资源/expectedRevision；同语义的空白或字段顺序变化不会变成不同意图。`action`是服务端各写入口注册的固定操作码，不接受模型/客户端自定义动作；增加入口时同时注册回查映射并测试授权。异步运行命令的COMMITTED仅表示运行意图已保存并返回原runId，不表示工具/阶段/外发已完成，实际结果仍查询run/delivery。

## C04. 目标、阶段与现有运行状态

拟新增目标状态只有以下八项：

| 状态 | 含义 | 用户可见表达 |
| --- | --- | --- |
| DRAFT | 目标草案，尚缺接受/关键条件；不启动工作 | 需要确认目标或补充条件 |
| ACTIVE | 已接受、有可执行下一步；并不等于正在发声 | 已接下，按允许范围推进 |
| WAITING_USER | 等待用户给信息、审阅或具体批准 | 等你补充/确认这一项 |
| BLOCKED | 缺能力、预算、不可确定副作用或运行错误导致无法继续 | 受阻，说明原因与选择 |
| REVIEW_READY | 最终成果待采用；目标尚未确认完成 | 有成果可以查看 |
| PAUSED | 用户暂停；不再启动阶段/工具/普通目标提示 | 已暂停，成果仍保留 |
| COMPLETED | 用户明确采用/认可且完成标准满足 | 按约定完成 |
| CANCELLED | 用户终止，终态；不再继续旧目标 | 已取消 |

目标仅由真实事件转移；最后阶段成功最多令目标 REVIEW_READY。用户“看过”、Bark SENT、工具 SUCCEEDED 都不能令目标 COMPLETED。用户明确有效指令可作为接受只读/纯文本目标的依据，无需机械重复点击；缺信息、可能外写或目标歧义时按归属需求追问。

纯暂停/恢复为使旧执行失效可递增revision，但不能令已经待阅的有效成果永久不可采用：只有目标/标准/资料/行动范围内容未变时，按R03在当前修订建立同一artifact的有效关联，记录inheritedFromRevision与definitionDigest，重新检查标准、归属和R10新鲜度；不重写原artifact，不计新交付。改变预算/偏好/来源等不得沿此路径直接认可旧成果。resume是否返回REVIEW_READY以该有效关联和当前检查为准。

拟新增阶段状态：`PENDING / RUNNING / SUCCEEDED / FAILED / BLOCKED / CANCELLED`。SUCCEEDED 指本阶段规定成果与证据已验证，不等于最终目标完成。PAUSED 只属于目标，阶段运行被失效/取消后留下原历史；不能偷偷给阶段增加与当前计划不一致的枚举。完整转移与终态重开见 R03。

现有 Delegation run 枚举必须保持：`RUNNING / SUCCEEDED / NO_UPDATES / FAILED / CANCELLED / BLOCKED`。新阶段与旧 run 通过绑定记录映射；NO_UPDATES 不是生成新成果、不可计为实际交付，也不是目标失败。不得改变旧前端与 API 对这些值的处理。

新goal-owned run结束为NO_UPDATES时stage回PENDING、goal转WAITING_USER(reason=NO_NEW_DATA)，持久化“补资料/稍后再查”选择；不遗留RUNNING或ACTIVE立即重跑。用户明确继续后才重新守卫和领取；legacy周期委托继续原规则。

现有 Delivery 枚举必须保持：`NONE / PENDING / SENDING / SENT / FAILED / UNKNOWN / SKIPPED`。SENT 只表示供应商/渠道已接受；UNKNOWN 表示无法确定是否接受，不能重发来试探。SKIPPED/NONE 不能说已发送。新增已读、采用、外部业务结果要用独立字段和用户事件，不往旧投递枚举塞 READ/ADOPTED。

## C05. 成果、来源、反馈和已读

成果至少关联 goal（若已有）、task/run、stage（若已有）、revision、创建时间、正文、事实/推断区分、来源证据、缺失条件和建议下一行动。事实来自真实工具或用户明确提供；不得把模型补出的 URL、价格、工具名当证据。引用应能回溯实际读取步骤与规范 URL，失败读源须单列。

artifactId的唯一产生与关联规则由R10固定；所有视图使用同一成果标识。R02先保存原run/attempt/output版本，后续增加稳定artifact引用或单一关联记录，不复制正文建第二库、不把历史映射/暂停恢复继承计为新产出。

反馈至少区分：接受本阶段成果、需要改进、修改偏好/标准、暂停、取消；最终明确采用且标准满足才完成。先看结果不等于允许下一阶段外发，也不等于允许将事实写成长时记忆。多轮指代只在已认证且相关目标明确时绑定；两个可选目标时问一次，不静默选择。

已读为服务器保存的资源事件/字段，来自用户打开指定结果并完成显式标记或满足 R09 规定的可见确认；Bark 推送、通知点击重定向未认证、后台预取不得标已读。用户采用由独立反馈记录；完成标准由 R03 验证。

## C06. 行动权限与失效守卫

行动类别至少分开：本地文本生成、已获准公开资料读取、个人本地数据变更、Bark 外发、其他外部写。MVP 不开放支付、购买、日历/邮件等通用写操作。凭据存现有服务端加密设置，模型与网页结果仅见能力状态，绝不见完整认证载荷。

实际允许工具 = 当前可信目录 ∩ 当前角色授权 ∩ 目标保存范围 ∩ 当次具体动作批准（如需要）∩ 未过期预算；任一交集为空，受阻或等待用户。模型提议不是授权。来源网页中的指令不能增加这个交集。

新增批准 TTL 120 秒，服务器计算 expiresAt，绑定 goalId、goalRevision、device/role、actionDigest、contentDigest 和单次用途。读取范围可持续授权，具体外发每次验证实际内容；旧明确 Bark 请求保持已有语义，不被新批准层强迫重复确认。修改正文/收件范围/目标 revision、取消/暂停、角色改变、撤销和到期都使旧批准失效。

阶段领取、每个工具开始、结果写入/交付前均重查当前 revision、状态、角色、预算与批准。暂停/取消先事务保存失效，再尽力终止在途工作；禁止启动后续动作。已经发出的请求无法保证物理撤销，保留真实/未知状态；晚到结果只能保留为失效历史，不能修改新目标、自动播报或外发。

## C07. 有限执行预算

拟新增外层默认上限：每目标最多 5 阶段，每阶段最多 5 个预先描述行动；每阶段最多 8 次工具调用，每 run 最多 120 秒，每目标每天最多 3 次 run，每设备每天最多 10 次 run。多目标共用设备额度；失败和重试计入额度，纯查询历史/反馈不计为执行 run；并发通过数据库原子扣减，不能超发。

现有 Agent 默认 4 次工具、20 秒超时，配置最大 8 次、超时校验 1–60 秒；工具结果现有大小限制继续生效。新外层 8/120 不扩大内部4/20，实际取更严约束。调度已有 2 worker/no queue 和 10 分钟 RUNNING 租约保留；120 秒是新逻辑 run 预算，不等于可以占用租约重复执行。

只读失败最多 2 次额外重试（总计 3 次），每次重新守卫并计预算。新 goal-owned 副作用 FAILED/UNKNOWN 不自动重发，UNKNOWN 受阻并给可核查选择；现有 legacy 非目标任务的旧投递失败重试保持原兼容，R04 需明确隔离标记，不能声称旧代码原本已做到。

额度耗尽目标进入 BLOCKED，reason=BUDGET_EXHAUSTED，保存成果和下一行动；设备或目标额度回补不偷偷重新启动被阻塞目标，用户恢复时按新窗口重新检查。没有确认供应商费用只能写金额未知；不换更贵模型、购买额度或延长死循环。具体金额上限为可选用户配置，未设置金额不会绕过调用和时长硬限额。

## C08. 记忆与注意力

确认记忆、目标状态与短期对话上下文分开。当前明确指令优先于旧事实；修订/替代/deleted 来源退出召回且清除相关主动候选；未确认建议、模型总结、外部网页和旧任务结果不能自动成为已确认个人事实。用户允许存储不等于允许主动提起；R06 保留 allowProactiveMention 等已有字段。

新的统一普通主动开关默认 false；不开启时不发普通语音/无声主动候选，成果保留待阅，用户查询仍可答。旧设置值可保留供 UI 展示，不得默默启用新机制或绕过新预算；用户主动选择启用后普通来源统一仲裁。已有明确授权到期提醒与业务渠道通知遵循原独立规则，不混入普通主动额度。

启用后默认普通主动窗口为设备本地 10:00–18:00，每设备日最多 1 次语音、3 次无声提示；候选获准前不消耗展示数，实际呈现后消费；同一成果不因来源重复展示。专注、免打扰、录音/播放、错误角色、暂停、TTL 过期时不抢占；过期不补播、不积压。提醒也须遵守其既有免打扰安全边界。TTL、拒绝与公平细节见 R07。

成果普通提示以稳定artifactId和实际内容版本去重，不能只用当前goalRevision生成presentationKey。纯暂停/恢复的成果继承不建新提示、不重置已呈现/拒绝记录；只有实际产生的新成果才可按R07重新申请候选和设备额度。

## C09. 语音与固件

当前8秒 capture、约800ms VAD尾静音、4轮/30分钟上下文、首轮后3次 FOLLOWUP/2分钟启动约束、单WAV等必须先测再改，不能直接靠增大参数验收。连续模式默认关闭保留。短答不得跳过实际工具取证。

拟工程门槛：端点判定→本地反馈每次≤200ms；普通聊天端点判定→设备首声 p50≤2.5s、p95≤5s；触摸→扬声器停止至少10次每次≤250ms，并验证无晚到复活。端点判定不含用户停顿/VAD尾静音，另行记录“停止说话→端点”。复杂工具耗时独立计数，接下提示不算成果/有效首声。

百分位需至少30个适用实测样本并保留样本/版本/网络条件，仍只称本样本分位数；10个取消样本只报告逐次和最大值。缺录音、时间源或设备首声证据就显示 UNKNOWN，不用服务端 TTS完成代替设备首声。R01 规定分阶段计时。

协议真实声频交互状态名为 PROCESSING，不能凭需求增加名为 THINKING 的必填枚举。后台 goal ACTIVE/RUNNING 不占据前台 PROCESSING；取消事件携带实际 turn关联，旧回合不能复活。新增设备字段可选、有界、旧固件忽略并保持原显示；不为待阅增加强制摄像头/新动作或分区变更。

## C10. API、数据迁移和错误

现有 REST 路径保持 `/api/v1/...`，原 DTO 只做兼容可选扩展。新目标功能统一 `/api/v1/companion/...`。旧委托成果/反馈扩展可以使用现有 `/api/v1/delegations/...` 与 `/api/v1/delegation-runs/...` 资源范围；不得混成 `/api/companion` 或另造无 v1 通道。

响应错误沿用仓库统一包装，以下为新增 machine-readable code，HTTP 语义需一致；实现前检查现有 handler，不另建 incompatible 错误包：

| HTTP | 错误码 | 客户端行为 |
| --- | --- | --- |
| 400 | INVALID_REQUEST / MISSING_REQUIRED_INFORMATION | 指出字段，不自动补猜 |
| 401 | AUTHENTICATION_REQUIRED | 登录后重新读取资源，不自动重播写请求 |
| 403 | ACTION_NOT_ALLOWED | 说明当前缺少授权，可返回允许的只读替代 |
| 404 | RESOURCE_NOT_FOUND | 不泄露其他角色/设备正文 |
| 409 | REVISION_CONFLICT / IDEMPOTENCY_CONFLICT / INVALID_STATE | 保留输入，刷新后由用户重选，不静默覆盖 |
| 410 | APPROVAL_EXPIRED | 读取最新动作，必要时重新请求批准 |
| 422 | CAPABILITY_UNAVAILABLE / EVIDENCE_REQUIRED | 显示缺能力或缺证据，不伪造结果 |
| 429 | BUDGET_EXHAUSTED / EXECUTION_CAPACITY_BUSY | 保留状态和 next action；不循环快速重试 |
| 503 | DEPENDENCY_UNAVAILABLE | 说明暂不可用；只读可按 R04 有限重试 |

真正的数据损坏/未知副作用不能仅返回友好文字后把运行标成功。业务 BLOCKED 是已保存业务状态，是否用200查询响应或对应命令错误以各接口定义为准；状态查询必须可读出 reason。

数据库迁移编号在实施时从届时最新 Flyway 最大版本递增；R01 已占 V61，R02 仅新增 V62，不把缺 V57 的分支改名再冒充迁移一致。增量表/字段允许旧记录无 goal，旧 delegations/runs/通知/记忆/个人任务数量与关键指纹保持。不执行危险自动降级 DROP；恢复方案使用隔离验证过的一致备份和匹配旧产物，避免新旧 schema混用。

## C11. UI、日志与证据

页面复用 Fantastic-admin 组件与权限/路由约定，正文优先：成果、证据、缺条件、下一行动和可操作反馈。用户流程不暴露 lease、attempt、内部模型名等实现术语，诊断区才可查看有界技术状态。

必须有 loading、empty、error、stale、busy、paused、permission缺失状态；单次操作处理中禁重复点击但保留键盘操作。手机360px、桌面1280px无横向业务滚动；来源长链接可折行，不能挤掉主操作。危险状态以文字和图形一起说明，不只靠颜色。焦点、键盘、对比度和明确标签要求见 R09。

工程日志记录匿名资源 ID、revision、阶段时间/耗时、工具名、状态、错误码、大小和配置摘要。正文、语音、密钥、完整请求/认证载荷、私人来源不得默认写入日志/仓库；手动导出的私人样例保留本地匿名路径与指纹，需求验收只引用不含秘密的摘要。

测试禁止真实 Bark/模型、刷写和生产库副作用，使用 mock transport/provider、时钟、并发屏障和隔离 PostgreSQL。实体测量和真实成果采用另行记录，不能用合成数据充真实观察。

## C12. 完成与实施交接

每份需求 FR/AC 编号不可无记录重排，改动需求需版本说明和受影响验收。开发不能只完成 happy path 或只给界面没有状态持久化。独立需求自动验收通过、兼容证据完整才进入 READY_FOR_REVIEW；外部授权或真实观察待办明确写出，软件与体验完成分别标记。

开始和完成都运行 `git diff --check`、`pnpm docs:check`；按所属状态执行最小验证，按代码涉及面运行相应服务端、前端和宿主/双 profile检查。文档任务用 `pnpm docs:check:test` 作为产品文档最小验证，不借旧软件测试成绩声称新需求已经通过。

每项从最新 master 独立 codex/分支；不改原用户文件。实现、状态和交接在外推之前压成同一个中文任务提交；仅在用户明确允许后推当前分支，不创建 PR、不合入、不推 master。完整交接格式见[入口第七节](README.md#7-每项开发交付格式)。
