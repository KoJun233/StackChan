## 1. 完成后的用户体验

用户在安静环境唤醒设备，或在电视、会议背景音环境切换到按住说话。
机器人及时显示正在听、正在处理、正在说；短闲聊简短自然，查询依据真实工具结果。
用户说“继续讲”时补充下一点，说“换个话题”时切断旧话题，说“不是……而是……”时优先采用纠正。
用户触摸停止后本地声音立即停止，晚到音频不会继续播放，下一轮可以正常开始。
跨天背景通过已确认记忆与目标状态提供，不通过无限扩大语音历史解决。
完成度必须包含可复现软件回归和真实设备测量，两种成绩分别记录。

## 3. 范围与排除

纳入：输入反馈、端点体验、短答与续讲、事实路由、失败恢复、触摸取消、诊断和实机测量。
纳入：R00 选择的一个真实目标入口；只负责正确交接目标，不在语音回合同步跑完长任务。
排除：全双工、语音插话、AEC、声纹登记、常开云录音、摄像头判定谁说话。
排除：更换 ASR/LLM/TTS 供应商、新音色采购、扩大 8 秒输入或连续回合限额。
排除：通用后台执行器、自动外发测试通知；这些分别属于其他需求与授权边界。
若短答与现有协议优化仍不足，交付瓶颈证据；提出独立方案，不能直接变更本范围。

## 4. 功能规则

### 输入、端点与本地状态

- FR01-01：WAKE 与 PTT 继续是两个显式模式；新配置使用现有默认，已有输入模式与灵敏度不暗中改写。
- FR01-02：正式讲话上限保持 8 秒；等待用户开口另计；不能把等待窗与实际讲话窗合并后剪掉短回答。
- FR01-03：WAKE 继续本地 VAD 确认命中后才上传；空采音不上传，不能为统计补造 ASR 请求。
- FR01-04：静音端点默认保持约 800ms；测试包括词中停顿、句间停顿、低音量和连续背景音。
- FR01-05：端点确认后本地进入 PROCESSING，不等待服务器第一字节；每次适用样本的设备状态变化暂定不超过 200ms。
- FR01-06：达到采音上限必须可辨识地记录原因；不把已截断输入当完整需求执行。涉及工具参数缺失时先澄清。
- FR01-07：PTT 松手提交，整次交互不自动续听；WAKE 录音中的独立提交按钮与其他触摸取消继续兼容。
- FR01-08：连续对话默认关闭；开启后追加开口窗默认 8 秒、允许 3–8 秒，首轮后至多 3 次追加回合、120 秒内允许启动。
- FR01-09：达到连续限制后安静收尾，不截断已提交的合法回答；不得自动重开会话规避两分钟上限。
- FR01-10：监听恢复只有重新开始本地采样后才能报告 LISTENING_RESUMED；PTT 准备完成报告 MANUAL_INPUT_READY。

### 回答、上下文与交接

- FR01-11：随口闲聊默认 1–2 句，尽量不超过 40 个汉字；不每轮反问，不主动说教，不用长问候填补等待。
- FR01-12：语音正文硬上限保持 160 Unicode 码点；需要长成果时读出摘要，完整成果由 R02 保存并可查看。
- FR01-13：同一回合继续完整正文一次 TTS、单 WAV；隐藏表情标记不合成、不展示为回答正文。
- FR01-14：普通短聊天快路径只服务无必需工具的聊天；时间、天气、能力、日历、待办、记忆审核、成果查询仍读取真实业务源。
- FR01-15：“给我的手机发一条消息”保留当前正确工具路由；无正文先问内容。续讲、否定、能力咨询不得继承写权限。
- FR01-16：有效近期历史只保留最近 30 分钟、最多 4 轮完整配对；失败、中断、孤立 assistant 消息不得冒充已聊事实。
- FR01-17：明确当前表达优先于旧历史、旧记忆、旧计划；“我问的是天气”不沿上轮继续讨论另一个对象。
- FR01-18：“换个话题”关闭旧话题引用；“继续讲”只补下一点；没有唯一近期对象时问一句澄清。
- FR01-19：确定性的“结束聊天”“先不聊”“现在忙”简短收尾，不调用模型提取新的长期记忆；引用或否定这些字词不执行控制。
- FR01-20：目标长任务通过 R02 建立真实持久状态后才说“已接下”；排队、待确认、缺能力、失败均不能说“已做好”。
- FR01-21：语音回合停止仅取消当前采音/生成/播放；不默认取消已创建目标或撤销长期授权。目标暂停必须有明确对象。

### 停止、异常、并发与兼容

- FR01-22：触摸取消先执行本地扬声器停止，网络取消不得阻塞本地停止；实机至少 10 次，每次不超过 250ms。
- FR01-23：取消绑定 turnId 和设备；旧回合音频、情绪、确认回执晚到均不得重新激活该回合。
- FR01-24：每台设备同时仅一条前台语音回合；新回合不得覆盖未退出的音频锁，拒绝或排队语义沿现有实现明确返回。
- FR01-25：ASR 无有效语音映射 NO_SPEECH 并安静收尾；供应商配置错误、网络错误、TTS 错误不能被吞成无语音。
- FR01-26：断网、麦克风恢复失败、内存不足、响应非法分别保留固定错误码；恢复入口可见，下一次合法请求能继续。
- FR01-27：新 goal-owned 或本轮语音明确写动作不得自动重试 Bark 等外部写操作；legacy 非目标委托原有 FAILED 投递有限重试保持原兼容，不能擅自删除。UNKNOWN 在任何路径均不自动重发。重新录音不重复提交已创建的目标/提案。
- FR01-28：设备、伙伴、会话从已认证服务端绑定取得；网页传入 deviceId 不自动获得设备命令或设备语音授权。
- FR01-29：SCV1/SCV2、旧取消 API 与既有单段播放继续工作；所有新增遥测字段可选，旧固件缺字段显示未知。
- FR01-30：固件改动须先过 R08 容量与栈门槛；禁止为优化语音擅自改分区、刷写、启运动或相机。

## 5. 数据与接口契约

本节标注“拟新增”的项目仅是实施合同；实现者先复用现有字段，不能做平行诊断库。
已有管理员读取接口：GET /api/v1/devices/{deviceId}/voice-turns，保留原 limit 和鉴权语义。
已有阶段包括 SPEECH_CAPTURED、ASR_COMPLETED、LLM_COMPLETED、TTS_COMPLETED、PLAYBACK_STARTED、CANCELLED、FAILED。

| 拟新增/细化字段 | 含义与规则 |
| --- | --- |
| measurementSource | DEVICE_MONOTONIC、SERVER_DURATION、PHYSICAL_OBSERVATION 三者之一，不混合计算 |
| endpointToLocalFeedbackMs | 同设备单调时间差；缺任一事件为 null，不用服务器接收时间替代 |
| endpointToFirstSoundMs | 采音端点确定至实际设备首声；性能门槛使用此值，不包含 VAD 尾静音 |
| endOfSpeechToFirstSoundMs | 实际用户停说至设备首声；由实体观察记录，不能从 LLM 完成近似 |
| captureLimitReached | 8 秒达上限布尔值；旧设备缺失为 unknown，不从转写文本猜测 |
| cancellationToSilenceMs | 实际触摸至扬声器静音；实体样本带采集方法，不填模型返回值 |
| diagnosticCompleteness | COMPLETE、PARTIAL、UNKNOWN；重复事件不提高完整度 |

拟新增管理员汇总读取：GET /api/v1/companion/voice-quality?deviceId=...&from=...&to=...。
该接口只返回计数、阶段耗时、来源和固定失败码；默认近 24 小时，最多 7 天，拒绝超范围。
from/to为ISO8601时刻，from<to；非法范围返回400。管理员必须能访问该deviceId，不能用任意ID读别台设备诊断。
新接口不返回录音、转写、正文、密钥、认证载荷或供应商自由错误串。
设备事件仍复用现有认证上传链路；不得新增未经认证的浏览器上报入口来制造设备成绩。
回合删除沿现有隐私删除边界清理关联诊断；匿名文件不得反向关联用户真实谈话正文。
诊断持久期限沿现有策略；若改变期限必须在 ADR 与隐私删除回归中显式说明。

## 6. 精确状态与文案

| 位置/条件 | 文案或状态 | 行为 |
| --- | --- | --- |
| 设备正在采音 | LISTENING；说明“正在听” | 无未授权录音上传 |
| 端点已确定、等待处理 | PROCESSING；说明“正在处理” | 不能表示后台目标已经执行成功 |
| 实际音频已开始 | SPEAKING；说明“正在说” | 只有真实播放开始才出现 |
| 没有清晰语音 | NO_SPEECH | 连续窗无声收尾，避免报错语音反复打扰 |
| 触摸停止完成 | 回到当前真实安静/空闲状态 | 不补播“好的我停了” |
| 输入疑似达上限且参数不足 | “这一段可能没说完，请再说一小段。” | 不擅自补齐或执行缺失参数 |
| 找不到续讲对象 | “你想继续哪件事？” | 只问一次 |
| 确定性轻量拒绝 | “好的，先不聊。” | 退出当前话题，不说受伤或催促 |
| 长目标接下 | “已接下，进展会保存在项目里。” | 必须已经持久化创建成功 |
| 缺能力 | “这一步目前缺少可用能力，项目里有具体原因。” | 保留真实阻塞，详见 R10 |
| 控制台缺阶段 | “未知：缺少设备播放开始记录” | 不显示 0ms、达标或失败百分位 |
| 样本少于门槛 | “样本不足，暂不能判断” | 显示实际样本数和失败数 |

设备可见中文若需要新增字形必须满足 R08 资源门槛；优先复用已有双眼状态和控制台说明。

每项采用 Given-When-Then，固定录音/模拟不能替代实体时延验收。

| ID | Given | When | Then |
| --- | --- | --- | --- |
| AC01-01 | 连续对话未开启 | 完成一轮普通聊天 | 不自动续听，原开关仍关闭 |
| AC01-02 | PTT 模式 | 用户松手且回答完成 | 提交一次，不开启追加监听 |
| AC01-03 | WAKE 有短轻语音与 600ms 句内停顿 | 用户继续说完 | 不因为调小静音窗剪断正常表达 |
| AC01-04 | 达 8 秒上限、关键参数未说完 | 请求创建目标 | 澄清剩余内容，不能猜参数执行 |
| AC01-05 | 开启连续对话 | 首轮后完成 3 次追加 | 不启动第 4 次追加；两分钟不重开绕限 |
| AC01-06 | 历史存在 5 轮且有一轮失败 | 读取语音上下文 | 最多 4 轮完整成功配对，不包含失败内容 |

| AC01-08 | 正在聊 A | 用户说“换个话题，聊 B” | 回答 B；不继续旧主动消息或 A |
| AC01-09 | 旧偏好为 A | 用户说“不是 A，而是 B” | 当前按 B 回答，长期替代另走 R06 确认 |
| AC01-10 | 无工具普通短聊 | 用户分享输赢 | 1–2 句短答，不每次给建议或追问 |
| AC01-11 | 天气工具未授权或失败 | 用户问现在天气 | 不快路径猜测；返回真实限制 |
| AC01-12 | Bark 上轮已发送 | 用户说“继续讲”或讨论通知能力 | 不再次发送；能力说明读取目录 |
| AC01-13 | 正在播音且网络阻塞 | 用户触摸停止 | 本地先静音；晚到音频不播放 |
| AC01-14 | 旧 turnId 的表情与音频晚到 | 新一轮已经开始 | 旧事件不能影响新轮表情、声音或确认 |
| AC01-15 | ASR 返回官方无词结果 | 追加窗结束 | NO_SPEECH 安静收尾，不记供应商故障 |
| AC01-16 | ASR 配置错误或 TTS 服务错误 | 发起回合 | 固定错误码与可恢复提示，不假装无声成功 |
| AC01-17 | 设备缺 PLAYBACK_STARTED 记录 | 查看诊断 | 首声标未知，不用服务端 TTS 完成补算 |
| AC01-18 | 目标已创建，当前播报未完 | 触摸停止声音 | 停当前回合，目标不被隐式取消 |
| AC01-19 | 用户引用“现在忙”讨论语义 | 完成识别 | 不执行拒绝控制，不撤销无关许可 |
| AC01-20 | 至少 30 个实体短句、10 次触摸停止 | 按约定测量并汇总 | 分别给成功样本、失败、首声百分位与每次停止值，不混入复杂工具任务 |

分位数统一使用有效适用成功样本升序后的nearest-rank法：位置ceil(p×N)，同时报告总尝试/成功/失败/缺失，不能删掉慢样本。
本地端点确认至状态反馈每次暂定 ≤200ms；真实停说至端点及停说至首声延迟均单列，不隐藏 VAD 等待。
触摸停音至少 10 次，每次 ≤250ms，列明每次值与最大值；10 次不能声称稳定 p95。
性能暂定门槛由 R00 基线冻结；变更门槛须给测量原因与用户确认，禁止事后调低以凑通过。
自动测试通过只授予软件完成，真实测量通过才授予实体交流门槛；缺设备授权时交付可验包并标现场待验。
