## 实现与取舍

保留既有语音、角色、记忆、五模板、表情、提醒及安全/备份基础设施；冻结扩展、资讯源、复杂待办和角色数量。没有删除用户数据。当前缺口首先是可控采音与正确收尾，其次是本地短触回应、动作/交互优先级，以及有明确许可的记忆和跨日关心。实现不引入声纹识别、任意运动参数、后台推断私人计划或持续上传背景音。

- 空闲右下角模式区域短触切换 `WAKE` / `PTT`，在独立 NVS 中保存；PTT 空闲不采麦克风、不做 WakeNet 检测。
- 按住说话仅在持有期间采音，松手提交；本次回复后不自动续听。普通监听时右下角为提交，其他触摸取消，拖出取消。
- 稳健唤醒为新默认，不覆盖已经保存的灵敏设置。开始等待与讲话预算独立；三回合、两分钟新采音和八秒讲话边界保留。
- 唤醒模型在正常监听期间复用；现场证明 ESP-SR 2.4.6 的 `clean` 在本设备模型发生空地址访问，已移除该调用，改为进入手动模式或语音回合结束时销毁、下次 WAKE 按需创建。初始化/录音失败保持可见并有界重试，不静默退出语音任务。`LISTENING_RESUMED` 只在实际读取后上报，手动模式用 `MANUAL_INPUT_READY`。
- 已录完 PCM 不再人为每块等待 100ms；HTTP 与无词解析按官方格式，额度限制用固定安全码。模型/TTS 连贯单 WAV 保留，不修改计费设置。
- 新诊断只记录有界阶段时间和固定码；设备采音结束到首声使用同一设备时钟。它尚不等于从用户最后音节开始计时，录音尾部仍须现场测量。
- 头顶空闲短触只显示五秒低优先级喜爱情绪；长按工作控制和运行中急停优先。五模板情绪与语音/生命周期表现分层，运动停止后不恢复许可。
- `记住…` 创建未生效候选，复述后 `确认记住` 绑定候选 ID、内容/更新时间、来源回合、伙伴和设备。后台修改/确认/删除/拒绝使旧语音确认失效，重复确认不重复执行。
- `明天下午三点问问我面试结果` 等明确请求生成一次提案，`确认安排` 后才创建 `FOLLOW_UP`。不清楚时间/主题先澄清；仅 30 天内、只问一次、到期后四小时有效。
- 关心服从当前伙伴、设备安静、伙伴暂停、DND、主题静默与在线状态。超期不补播，派发后无法确认播放不自动重播；只有实际投递的同伙伴/设备关心可进入近期上下文。

完整 AFE 未接入：同类视频人声仍是人声，先实现用户已接受的显式 PTT 隔离。不能据此宣称安静唤醒准确率或响应时间已经达标。

2. `./scripts/build-companion-candidate.ps1` 从 `git archive HEAD` 构建，无缓存、日志、私人 `.env` 或其他工作树。输出忽略的 `.tools/companion007-*/manifest.json`，含提交、归档/JAR/首页 SHA-256、镜像 ID 和 schema 55。

4. 原容器和卷保持，只启动已授权的必要服务；立即停止自动动作并检查设备 DISABLED，不发送转动模板。
5. 用候选执行 `verify-companion-full-restore.ps1 -CandidateImage <image> -ExpectedSchema 55`；生产快照只恢复到内部网络的临时卷，验证原数据计数、管理员和加密配置，保留 DPAPI 备份。

7. 核对镜像/JAR/控制台静态资源与清单、schema 55、健康和设备状态；临时管理员清理到零。

## 现场失败与修复

用户初测按住说话、松手后回复与继续视频“正常”，不是 20 次准确率或 30 分钟误唤醒验收。安装后仅两次结构化 PTT 样本：第一回合 COMPLETED / MANUAL_INPUT_READY，采音结束到 PLAYBACK_STARTED 为 4482 ms，ASR/模型/TTS 为 277/670/837 ms；第二回合 9649 ms，状态 RESPONSE_READY，没有完成/恢复事件。它不能计入成功延迟统计，也不能仅据此判定崩溃原因。目标中位数 3 秒/P95 5 秒尚未通过。

用户报告频繁点击后开机画面重现，并明确允许只读串口、不主动复位。2026-10-01 13:53:38、13:53:47、13:54:10 UTC 捕获三次相同 LoadProhibited / EXCVADDR 0x10。安装应用 SHA-256 与上述制品相同；使用该 ELF 解码为 `dl_convq_queue_bzero` → `model_clean` → `voice_task` 的手动空闲分支（voice_control.c 原 1545 行）。用户确认触发三次。不是凭感觉归因于栈、供电或 HTTP 取消。

修复仅移除 WakeNet clean，在手动空闲和两类语音回合结束后调用已有幂等 destroy；手动空闲无模型时不重复销毁，下次 WAKE 按需初始化。不修改 ESP-SR、凭据或唤醒模型分区。重建频率取舍以稳定性优先，冷初始化的现场耗时仍需复核。宿主新增源路径守卫并通过原五组；守卫不是实际库执行测试，必须继续实机快速切换/录音/取消验收。HTTP 取消重新连接的代码风险另有发现，但三次堆栈不在该路径，本次不凭推测同时改动。
