# MEDIA-003 EAF 生命周期片段实机验收

## 目的

验证官方 `esp_lv_eaf_player` 是否适合承担有限时长的生命周期动画。此 runbook 不授权部署、
刷写、清除 NVS、回退演练或启用 `esp_emote_gfx` 显示接管。

## 前置条件

- 用户逐次确认设备为 CoreS3、应用 OTA、LAN HTTP profile、候选提交/版本和保留 NVS。
- 当前稳定镜像、候选固件路径、字节数与 SHA-256 已记录。
- 候选从 `STACKCHAN_MEDIA003_BACKEND=eaf` 和独立 EAF 依赖锁构建；不得把 Emote lifecycle
  profile 当作可视候选刷入。
- 服务端和设备均在线，`motion_disabled=true`，现有 OTA 成功路径可用。

## 成功路径

1. 发起应用 OTA，等待任务进入 `INSTALLED`，并观察至少三个心跳；若设备自行回退，立即停止。
2. 冷启动一次，确认开机阶段显示自有 EAF 球体片段，约 1.8 秒后自动回到原生动态球体。
3. 连续完成三次普通唤醒对话，记录唤醒命中、回答音量、音频 underrun、实际/目标 FPS、最低堆。
4. 在 TTS 播放中触摸，确认立即停止，晚到分片不播放，下一次唤醒仍正常。
5. 断开并恢复网络，确认离线/重连状态始终由固件原生渲染器表达，不被 EAF 覆盖。
6. 连续重启三次，确认没有黑屏、卡在开机动画、看门狗重启或堆水位持续下降。

## 通过标准

- EAF 只在限定的开机窗口可见，结束、失败和取消后均恢复原生球体。
- WakeNet、VAD、TTS、触摸取消、设备重连和应用 OTA 健康确认均与稳定镜像一致。
- 音频 underrun 保持 0；最低空闲堆不低于 7 MiB；无看门狗、崩溃、自动回退或持续泄漏。
- 视觉收益足以覆盖每段约 54 KiB 的当前素材成本；若只是重复原生眨眼/呼吸，则不采用 EAF。

## 失败处理

- 保留设备和 OTA 任务上报的安全失败码，不保存音频、转写、令牌或完整认证载荷。
- 若自动回退，记录候选版本和失败阶段，不立即重复 OTA；先检查启动确认、重启原因和设备日志。
- 若语音、触摸或连接退化，结论为 EAF 候选未通过。回到稳定镜像，默认 native 路径无需修改。
- 本轮不主动演练失败回退；仅处理真实发生的自动回退。
