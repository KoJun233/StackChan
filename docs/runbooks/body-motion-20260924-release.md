用户授权继续操作后，在 COM3 只读、限时且过滤敏感字段的串口监听下，以相同镜像重试。任务 `f53145e2-97bb-4e6b-8905-dc200abc7fc1` 再次以 `ROLLED_BACK / device_rollback` 结束；旧版 `4444860` 恢复在线且动作禁用。新镜像启动后在 `device_provisioning_start()` 返回 `ESP_ERR_NO_MEM`，30 秒后 OTA 健康确认超时而自动回退。启动日志显示硬件和语音阶段已完成，故障发生在传输初始化后的 USB 配网任务创建；这次没有执行实体动作。

修复把传输任务的 32 KiB 连续栈和 USB 配网任务的 16 KiB 连续栈都预留在 Wi-Fi 初始化之前。配网任务在 Wi-Fi 就绪前等待任务通知，避免提前处理 USB 请求。预留和失败处只记录内部堆总量及最大连续块，不记录凭据。修复后的 LAN HTTP Quad 构建已通过；仍需用新镜像验证启动、OTA 健康确认、联网及五种实体动作。后续以新候选镜像的实际提交、大小和摘要为准，不再安装失败的 `233ee31` 镜像。

第三次 OTA 使用干净提交 `e14fb36`、大小 1,652,144 字节、SHA-256 `6D983E11329A736A49E917A0C2FA9A53077E8DDB08201E07B7AC96652B94C530`，任务 `9826a8d3-22e6-4851-a5ff-a4073306ea53`。新镜像日志证明传输栈预留时内部最大连续块 53,248 字节，配网栈预留前为 31,744 字节，随后 Wi-Fi 初始化返回 `ESP_ERR_NO_MEM`；30 秒健康确认超时后再次安全回退。旧版 `4444860` 在线、动作禁用。旧版启动日志同口径显示 Wi-Fi 初始化后内部空闲仅约 26 KiB，这解释了提前预留 16 KiB 配网栈后 Wi-Fi 空间不足。

后续候选把常驻 Wi-Fi 接收缓冲从 16 减至 12、发送缓冲从 16 减至 8，并把 RX BA 窗口与接收缓冲同设 12。根据 ESP-IDF Kconfig 每缓冲约 1.6 KiB，预计可在 Wi-Fi 初始化时减少约 19 KiB 常驻需求；失败日志增加 Wi-Fi 初始化阶段的错误码及内部堆指标。以下记录该候选的实际部署结果。

第四次 OTA 首次投递 `b22cf94` 时，旧固件在下载阶段的 Wi-Fi PHY 内存错误后重启，服务端未收到受理 ACK；旧版 `4444860` 重新在线且动作禁用。任务 `6c84551f-7e29-4940-9508-f1a6fed3a9ec` 因没有受理 ACK、设备已恢复旧版且心跳新鲜，由带这些前置条件的单条数据库更新记为 `FAILED / device_restarted_before_ack`，防止 15 分钟后自动重派。它不代表新镜像启动失败。

同一候选第二次投递任务 `604ef042-381e-4c84-b597-017f53eb8a7e` 成功进入新 OTA 分区，终态 `INSTALLED` 且设备上报版本 `b22cf94 / motion_disabled / DISABLED`。镜像大小 1,652,304 字节，SHA-256 `C27D742449BFCB945C8E06CBEA9465D247C26CF230D5DBBDF33D22E816F9433B`，NVS 保留。串口显示传输和配网栈预留成功、Wi-Fi 初始化完成、USB 配网就绪；新固件 Wi-Fi 初始化后内部空闲 25,115 字节，最大连续块 16,384 字节。设备心跳确认 K151 动作与触摸能力、已保存校准、反馈待显式启用探测，且没有启动动作。真实语音、模板转动和停止尚待逐项验收。

`scripts/verify-body-motion-device.ps1` 默认只读上报版本、安全状态、反馈、校准和固定失败码；`-Step ApiStatus` 另用临时管理员只读核对页面所用设备接口与自动动作开关。该接口已返回 `b22cf94`、在线、命令通道可用、动作禁用及自动动作关闭，临时管理员清理后数量为零。`-Step Calibrate`、`Enable`、五模板名、`Stop`、`Disable` 才会向设备发命令。脚本每次使用随机一次性管理员，结束即登出、删除账号；动作前强制检查新版心跳、已 armed、校准和反馈能力。实体动作只在用户就位并可观察时逐项运行。

## 固件及实机下一步

当前设备已安装 `24c62a7`，NVS 保留；新鲜心跳与受保护 API 确认在线、`motion_disabled / DISABLED`，自动动作关闭。用户已授权持续部署与测试。先在用户重新确认旁观后同步采集放大轨迹的实体表现及串口反馈。真实运动前需用户确认头部周围空间、底座稳定且线缆不受拉扯。首个 `NOD_SMALL` 成功、用户确认方向/幅度/回中和无异常后，才按[五动作实机流程](k151-body-motion-smoke-test.md)逐项测试 `LOOK_USER`、`THINK`、`DROWSY`、`WAKE` 及触摸、语音、断线、重启停止。任一异常立即停止并保持禁用，不把余项预填为通过。真实陪伴价值还需自然使用反馈。

## 回退边界

V52/V53 新增数据表，旧 V51 服务端对 V53 运行库未作兼容验证。故障时保留当前现场与停写快照，先在隔离库核验恢复，再决定恢复窗口；脚本不会把旧镜像直接启动在 V53 库上，也不会自动覆盖正式数据。快照包含 DPAPI 加密配置，依赖原 Windows 用户和机器；本地卷不是异机灾备。生产部署继续遵守 HTTPS-only 边界。
